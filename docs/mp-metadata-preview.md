# 旧公众号文章的列表预读保护

文件列表按进度排序、阅读历史及历史状态统计会通过原生 `BookList.getBookInfo` 提前打开阅读记录。
官方 KOReader v2026.07.1 的 `DocSettings.open` 会读取候选，删除损坏或空的候选，再尝试备份。
有效记录的读取本身不会立即迁移；迁移和其他候选的清理发生在之后的保存阶段。
因此只在“打开文章”时保存原始记录，不能覆盖此前浏览列表时已经删除的损坏文件。

现在插件在上述预读真正调用 `DocSettings.open` 之前，按现有索引核对旧文章的准确路径，
先保存各位置的原始候选到按账号隔离的记录数据库，再允许原生读取。
文件管理器创建首屏、尚未设置其 `instance` 时也覆盖在内；阅读器中的历史列表使用同一保护。
已经有原生信息缓存时不会额外读取文件或保存快照。带独立版本标记的文件、普通书籍及无关元数据沿用原流程。

保护范围只限于活动插件下 `BookList.getBookInfo` 内对同一路径的实际读取。
其他调用直接使用 `DocSettings.open` 时保持原行为；全新启动时、插件加载之前的直开也尚未覆盖。
识别沿用准确的公众号容器／文章索引，不按文件名猜测归属。保存前后核对文件身份和账号；
账号变化、来源变化或保存失败不会继续该次原生读取。插件关闭或界面销毁后不保留拦截权限。

保存失败时返回原生无信息占位，百分比显示“–”，不伪造 0% 或笔记数量，也不把失败结果缓存。
原生状态筛选会把这个占位归为“新书”，这不证明文章确实从未读过；存储恢复后刷新即可重试。
不能增加原生未定义的状态，因为历史统计直接累加固定的状态键。
成功预览仍沿用原生元数据展示，不因此确认共享记录属于当前文章版本。

记录恢复继续要求明确选择：候选可能属于另一个版本，损坏候选保存原始字节并显示不可读，
有效备份可以恢复到独立副本。保护不会修复已经丢失的字节，也不会自动选择候选或改写原正文。

## 验证

33 项组件检查覆盖首屏初始化、活动阅读器、缓存命中、普通／独立版本、记录和来源错误、
保存失败／抛错及重试、账号变化、递归调用、界面销毁／替换／禁用、第三方包装、参数空位和原生异常。

实际运行使用官方 KOReader v2026.07.1 Linux ARM64／Xvfb、合成账号及正文：

- 先在没有活动文件管理器时复现原生预读删除损坏共享候选、保留有效备份。
- 创建实际文件管理器首屏，逐次核对候选原文已提交到文件 SQLite，才允许原生记录读取。
- 旧受管 HTML、旧标题 HTML／EPUB 的读取和原生缓存命中通过；实际历史列表及状态统计可打开。
- 注入保存失败后，实际文件列表显示“–”，原始候选未变，原生读取没有执行；历史状态统计仍可用。
  恢复存储后，同一入口可重试，不受失败缓存阻止。
- 预读之后从实际文件管理器打开，仍可明确选择有效旧备份；恢复副本的原生位置及批注一致，
  再由全新进程重开确认数据库原始快照和阅读记录仍在。

```sh
luajit spec/mp_metadata_preview_spec.lua
xvfb-run -a python3 scripts/test_mp_metadata_runtime.py \
  --koreader /path/to/runtime --run-dir /path/to/new-profile --metadata-preview
```
