# 新建私密想法的限定三步验证

独立 Python 实验已在本人授权后完成：只新建一条私密测试想法、编辑该新记录、删除该新记录，总计三次数据 POST，没有重发。
每步均独立回读，最终额外回读确认原有想法、划线、书架成员／标记及精确位置恢复一致；临时执行记录已清除，登录凭据继续保留。
尚未接入插件的想法写入入口，当前「我的云端想法」仍为[只读浏览](my-cloud-thoughts.md)。

## 三次修改的固定范围

工具选择书架中已有划线、完整本人想法不超过 18 条的普通数字书号，复用一条服务端划线的章节、range 和引用原文。
新建文本仅包含固定验证说明和随机标记，显式 `isPrivate=1`；不将原想法作为修改对象。
每次另行取得限定许可后，最多执行以下三次数据 POST，每一步都独立读取完整想法、划线、书架状态及阅读位置：

1. 新建一条私密测试想法，完整回读确认同书、本人、引用、范围、文本与私密字段，才能认定新记录编号。
2. 只修改这个新编号的测试文字，重新读取并确认仍然私密。
3. 只删除这个新编号，重新读取两次，核对原有想法、划线、书架成员／置顶／私密／读完标记及章 UID／序号／偏移／百分比恢复。

不根据创建回执中的编号直接操作；回执缺失或无法识别时，只通过独立完整读取确认结果，绝不重发 POST。
原有记录变化、私密状态或目标不符、读取不完整、位置改变时停止后续修改。
每次修改前另读一次当前状态，编辑和删除必须针对已独立确认的新记录。
最多三轮只读回查，GET 总量上限 80，应用层请求间隔至少 350 毫秒；执行中不自动续期授权。
这只是已有远端划线的范围复用，尚未验证原生选中文字到上传坐标的转换。

服务端可能改变笔记排序、最近操作时间等历史信息，删除测试记录也不能保证恢复这些信息。
中断、读回不一致或私密状态异常时可能留下测试想法。工具停下并保留执行记录，不擅自追加清理请求。
服务端权限规则仍需真实新建后核对，不能以请求中的私密字段代替结果。

## 本机执行记录与命令

独立钥匙串条目只保存限定计划、各原始状态摘要、新记录编号和执行阶段，不保存引用正文、原想法内容或登录凭据。
每次可能发送前先持久记录对应阶段并读回，原子比较旧记录；不自动恢复发送，不重复领取阶段。
只有完整最终回读通过才清除记录。原有登录凭据按用户要求继续保留。

```sh
# 默认离线；以下三种操作均不修改云端数据。
python3 scripts/verify_annotation_experiment.py
python3 scripts/verify_annotation_experiment.py --saved-session --prepare
python3 scripts/verify_annotation_experiment.py --saved-session --check-pending
```

`--prepare` 完成两次完整预检后只保存本机意图，打印去敏指纹。
`--check-pending` 只读当前状态，不消费或清理意图。
尚未发送的 prepared 意图可以用 `--discard-prepared --expected-intent <指纹>` 本机清理；已进入发送阶段的记录不能这样清除。
需要另行获得上述三次云端修改的许可后，才运行 `--saved-session --apply --expected-intent <指纹>`。本次许可已经使用，不能复用。
执行前重新绑定同账号、同书、同划线、同内容范围和所有原状态摘要，任意变化都在零次修改时拒绝。
其他进度／书架／读完实验有未处理记录时，也不能开始本实验。

## 授权后的实际结果与格式修正

新建返回 HTTP 200 和 reviewId，首次回读因章节编号类型未通过校验而停止，实际只发送一次新建，没有编辑、删除或重发。
两轮只读诊断确认仅新增的一条测试记录：本人、同书、私密 `isPrivate=1`、初始文字、引用及范围均一致，所有原状态未变。
服务端把新建载荷中的章节编号以十进制字符串返回；旧三条记录是数字，旧模型因此报 `my_thoughts_number`。
Python 现仅对 chapterUid 接受规范十进制字符串并转为有界整数，拒绝前导零、指数、空白、越界和布尔值，其他数值字段不放宽。
真实四条列表的完整投影通过后，Lua 接入相同规范化；缓存仍保持原有整数形状。

在原三次许可尚剩两次、且独立回读已经确认新建实际成功的条件下，新增显式 `--continue-after-create --expected-intent <原指纹>`。
它只接受 create_pending／已消费一次的原计划，重新核对同账号、原书／划线、原范围上下文、唯一私密初始测试记录及全部原状态摘要，两次完整读取必须一致。
满足这些条件后只领取编辑和删除阶段；不能再新建，不能接续 edit_pending／delete_pending 或其他未确认修改，也不允许改变目标、原始状态或提高总上限。
CLI 参数本身不是额外授权。公有、重复、缺失、已被编辑或原数据变化的记录均在零次新增写入时拒绝。

按本人原授权完成剩余两次后：编辑后的同一记录保持私密，内容独立核对；删除后和最终额外回读均确认原三条想法、52 条划线、140 本书架成员／标记和精确阅读位置恢复。
三个 POST 分别只有一次，执行过程中授权 POST 为零；检查通过后独立确认钥匙串执行意图不存在。
首轮停止、只读诊断和限定接续均保留为独立记录，没有把它们描述为一次无中断运行。
该真实往返验证的是 Python 协议，不代表 Lua 的云端写入或原生写后回读已完成；后续操作需要新的授权范围。
