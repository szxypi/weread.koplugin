# 单章跨文件链接准备

单章导航的后台准备已实现并通过原生运行时验证：从实际源 EPUB 恢复原链接，
按目录识别同一本书中的目标章节，再独立核对目标缓存和锚点。
自动打开、按需下载和跨文件返回仍待接入；当前阅读器还没有调用这套准备结果。

## 准备结果

| 结果 | 已核对的内容 | 后续含义 |
| --- | --- | --- |
| `ready` | 源文件身份、源链接确实存在、目标包的书籍／章节标识，以及唯一目标锚点；已知版本不能冲突 | 可供后续打开流程使用，仍须新阅读器实例核对实际文档和 DOM |
| `needs_download` | 原链接对应同书目录中的候选章节，缓存缺失或不可用 | 尚未证明目标锚点存在，不会启动网络请求 |
| `unavailable` | 来源变化、未知链接、歧义目录／目标、已知版本冲突或缺失锚点等 | 保留当前阅读位置，不能任意选择其他章节 |

目录计划与现存包内链接解析是两个接口。未知目标只能产生计划，不能通过现存链接的校验。
旧缓存的未知版本仅用于本机核对，不增加任何云端进度或时长上报权限。

## 来源与原生链接

原生单章 URI 已相对生成包内的 `OEBPS/text/chapter.xhtml` 重定位，
与原目录中的源文件路径不同。准备任务从原生实际选中的 URI 出发，
读取源包真实 XHTML 中的链接，恢复原相对路径后核对目录归属。
如果同一个原生投影对应不同的原始目标，会返回歧义，不能只凭文件名猜测。

实际发现原生“外部／缺失文件”链接已经做过 URI 解码；例如源链接中的 `%252A`
会在原生对象里成为字面 `%2A`。后台按该投影匹配，不再解码一次。
这与整书内部 `#_doc_fragment_…` 编码锚点的情况不同，两个分支分别处理。
中文、百分号文件名和 XML 数字实体锚点均经实际原生链接对象验证。

任务只读取独立 libarchive 描述符，不使用继承的阅读器／ZIP 句柄，不写缓存，
不接收 Cookie 或授权对象，不访问网络，不返回正文。链接专用扫描也不清理脚注正文或
输出其诊断内容。返回中只包含来源／目标身份、成员摘要和目标锚点等交接所需信息。

## 验证

- 独立 Lua 检查覆盖缓存命中、未缓存计划、同书／章节标识、观察到的版本冲突、
  目标缺失／重复、源文件替换、目录稀疏项／重复 UID、注释伪链接、源 URI 歧义、
  中文实体、字面百分号，以及计划不等于锚点证明。
- 官方 KOReader v2026.07.1 Linux ARM64／Xvfb 的 600×800 与 1264×1680／300 DPI：
  实际读取三个独立 EPUB，获取原生手势命中的链接，在真实后台子进程中完成核对。
  子进程若误用继承的原生文档读取接口会失败；正常任务通过独立归档读取完成。
- 预演覆盖中文与相对 URI、字面百分号、中文百分号文件名、未缓存计划、版本冲突、
  重复锚点和源包替换。当前阅读位置不动，旧阅读器身份不重新绑定，测试归档恢复原字节。
- 当前证据均为合成资料；没有真实账号数据修改，也没有导航或下载动作。

复验时使用全新目录：

```sh
luajit spec/chapter_link_worker_spec.lua
xvfb-run -a python3 scripts/test_discovery_runtime.py --chapter-link-preflight \
  --koreader /path/to/runtime --run-dir /path/to/new-directory
```

KO2 尺寸追加 `--width 1264 --height 1680 --dpi 300`。
结果见[去敏报告](validation-assets/2026-11-12/chapter-link-preflight.json)。

## 后续接入门槛

- 准备结果须绑定当前账号、授权代次、书籍、源文档实例、视口和目录快照；翻页、切书、
  休眠或取消后不打开旧结果。
- 缺失章节沿用现有单章下载流程，完成后重新核对实际包；切换到新 ReaderUI 后再次核对
  书籍／章节、文件身份和真实 DOM，再使用目标锚点。
- 切书前保留本机检查点与精确返回位置，保持正常的同步权限门槛；原生本文件历史和跨文件
  Back／Forward 必须一起验证，文件变化时不能把旧 XPath 套到新正文。

这些门槛通过前，本项仍属于导航开发中的后台准备，不能计作完整单章跨文件功能。
