# 查看想法引用原文

「我的云端想法」中的文字引用可打开「查看想法引用原文」，定位到 KOReader 原生阅读器中的对应文字。
仅在本人快照中存在明确 reviewId、正数章节 UID、文字型引用及合法范围时显示入口；无引用、未知类型或缺少范围的想法仍可浏览文字。
定位使用想法的 `abstract`，不借用想法正文、附近划线或单纯的同文搜索替代来源证明。

## 原文与本机坐标

独立 Python 先对实际 3 条想法核对：原始 Unicode 范围提取的可见文字与引用相同，来自同一章节，两次读取的原文字节一致。
Lua 随后使用同一真实数据独立投影，全部目标与 Python 相同。
服务端范围的单位与阅读进度不同，仍先严格核对引用，再复用已有来源坐标转换、归档核验和原生 DOM 定位。
只裁除引用两侧空白，中间文字不放宽；不明确或有歧义的来源不能生成目标。

复用划线的后台流程：优先检查当前文件、单章及整书缓存，核对书籍／章节／原文和渲染成员，再由原生导航器确认目标在当前视口。
对应章节缺失时另行确认下载，下载完再次核对，不能直接使用服务端范围跳页。
成功跳转保存本机位置，不授予云端上传权限。引用内容、范围、记录编号、账号、文档、原快照、阅读位置变化或关闭／取消使旧任务失效。
本次也补齐了所选行被原地修改时取消旧查找的保护。

## 验证范围

- 10 项独立 Python 测试，覆盖类型与身份、引用／范围、标识与文本边界、只读工具默认关闭、固定查询和请求上限、稳定前缀以及失败信息过滤。
  Lua 引用／归档适配 26 项，共用原生查找／交接／下载 74 项，个人标记界面归属与入口 38 项。
- 真实 3 条／1 章在 600×800 和 KO2 尺寸 1264×1680、300 DPI 下，经实际 PluginLoader／FileManager 详情入口、原生按钮、ReaderUI 与目标可见核对。
  同次读取的私人正文由生产打包器建立一个单章和一个合并测试缓存；每尺寸首进程逐条定位后，全新离线进程从合并缓存逆序重做，合计 12 次。
  所有原生进程的插件 HTTP 均被拒绝，计数为零；云端想法及精确位置独立确认未变。配置仅存 tmpfs，安装文件核对后删除，无真实截图或人工目视验收。
- 两尺寸合成各含 6 条引用／2 章，以及无引用和缺范围记录，覆盖公开／私密标示、长章、短引用、实体编码、中文和表情、工作进程取消、旧取消回调、跨文件及全新离线进程。
  原划线、本人想法列表、想法编辑／草稿、首页／书架／书城／统计／授权与正常阅读／同步／恢复组合同步回归。
  合成原文弹窗及定位截图可目视检查，模拟字体的表情缺字不代表实际文字被删改。

真实数据限定为一本书的一章，不代表所有书籍或范围类型；实际账号的缺章联网下载、TXT／CB_ 范围、实体 KO2 按键／联网／休眠仍待验证。
本批账号数据和授权 POST 都为零，目录／正文的只读 POST 单独计数；既有登录继续保留。
