## 文件管理器在测试中的作用

本工具加载 KOReader 原有文件管理器，让它创建正常的插件实例，然后进入插件首页和书架。
选书、详情「阅读」、目录准备、下载和原生阅读均由插件内的入口完成。
测试没有在文件管理器中选择预制 EPUB，也没有直接调用 ReaderUI 打开测试文件。

另一些底层排版／来源位置测试会直接打开合成文件，用于隔离格式、字体或位置转换问题；
这些结果只说明相应底层能力，不能替代首页／书架／书城到阅读和同步的功能验收。

## 可复现入口

`scripts/verify_owner_reading.py` 默认离线，不读取钥匙串、不联网、不启动阅读器。
`scripts/test_owner_reading.py` 在 CI 检查默认行为、固定报告格式、凭据隔离、超时、
云端位置未变、离线零请求、清理和前后进程一致性。

在已有本人授权的 macOS 开发环境生成候选包，然后运行（`--lua-command` 必须放最后）：

```sh
bash scripts/package_release.sh ../.validation/owner-reading-candidate.zip
python3 scripts/verify_owner_reading.py --saved-session --lua-command \
  docker exec -i -w /source weread-validation xvfb-run -a \
  python3 scripts/run_owner_reading_probe.py \
  --koreader /validation/runtime/lib/koreader \
  --candidate /validation/owner-reading-candidate.zip
```

KO2 尺寸在末尾追加 `--width 1264 --height 1680 --dpi 300`。每次运行只使用一个原生进程，
在线进程退出后才启动离线进程，两者共用同一临时配置；不同运行之间重新创建配置。

验证 TXT 时，在 `--lua-command` 前增加 `--book-format txt`。
该模式优先检查书架中的 TXT 元数据，最多读取八本书的目录；确认同书 `e_0` 回退标记后，
才允许读取同章 `t_0`／`t_1`。原文按纯文本处理，保留字面标签、实体、BOM 与换行供内存核对，
不把它作为 HTML 解析。已有进度使用原章节；明确的全零未读状态选择插件默认的首个可读章节，
不为方便测试跳到较长章节。原进度及目录在前后均需一致，才启动原生验收。
独立的 `scripts/verify_txt_reading.py` 可只读核对格式与正文，默认离线；
17 项新增离线测试检查请求范围、回退身份、目录／位置稳定与纯文本处理。

## 真实整书模式

在 `--lua-command` 前增加 `--full-book`，可选择书架中一本含 2–32 个可读章节的 EPUB。
选择范围最多十二份目录，封面及零字数章节按插件原有规则排除；每个正文章节均需通过
同书／同章 Reader 身份、原始分片解码、来源哈希和目录版本核对，任何一章失败即停止。
只读准备阶段每次成功请求后间隔一秒，不重试业务错误，也不自动执行登录续期。

在线验收从插件首页进入书架可见页，打开详情「下载全书」，确认下载并点击「立即阅读」。
正文、资源打包、原生阅读、翻页及本机原文位置保存均使用生产流程。
独立 Python 检查逐章原文字节、来源密封值、渲染哈希、目录顺序、ZIP 完整性、
长文本片段保留和所有剩余图片引用。图片标记转成脚注时，必须核对原注释文本、
唯一的原生脚注目标、引用和回链，才计入已解释的图片差额；普通图片缺失仍判失败。
包内图片另由 KOReader 实际解码，不能只凭文件头认定可显示。

在线进程正常关闭后，全新离线进程仍从插件书架及详情「阅读」进入同一整书，
核对页码、可见位置、全部来源和图片，并确认 EPUB 文件逐字节未变、HTTP 为零。
固定报告保留未解释的图片和文本数量；存在差异时不会跳过检查或报告通过。
整书模式只接受 EPUB，不改变原有单章／TXT 的默认范围或请求上限。

## 核对内容和边界

Python 先核对本人账号，在有限书架样本中选一本已有阅读位置的普通书籍，
读取前后云端位置、同书 Reader 上下文、目录和原始正文分片，并核对目录稳定。
这些均复用已有只读协议，不新增服务端接口。

Lua 探针加载打包插件和 stock FileManager，刷新真实 Web 书架并定位包含目标书籍的可见页，
调用实际选书及详情「阅读」按钮回调。目录准备、下载、生成 EPUB、SQLite、BookStore 和
阅读器交接均走生产代码；没有预制 EPUB、替换下载正文或内存书架后端。
它将 Python 原文样本与 CRE 文本匹配，跳转到样本并确认其在当前页和屏幕范围内，
执行真实重绘和翻页，再通过原生文档关闭保存位置。离线新进程再次点击「阅读」，
核对同一路径、章 UID、页码和可见 XPointer；任何 HTTP 请求都会失败。

测试期间自动同步和阅读时长上报关闭，云端进度、书架、笔记等写入和登录续期一律被拦截。
允许的 POST 只有同一本书的目录和目标章节内容读取。图片和资源走实际下载路径，
初始来源限制为既有公共资源域；整书还可读取同书 Reader 给出的、已核对的
`https://res.weread.qq.com` 章节资源归档，认证仅传给该精确主机的 HTTPS 地址。
其他重定向仅允许匿名 HTTP(S) 公网地址，拒绝私网、
用户信息、片段和控制字符，并保留流式下载的文件重置与体积限制。
探针结束后再次验证本人账号及云端位置未变，合法轮换的 Cookie 核对后保存回原钥匙串条目。

授权通过捕获的内存管道传入，并由匿名文件描述符提供账号作用域。
测试钩子从普通设置的写盘过程中暂时剔除认证字段，保留正常偏好和书籍存储；
章节会话字段、正文、侧车记录及缓存只存在 Linux `/dev/shm` 临时内存文件系统。
脚本检查该挂载类型，审计生成文件中的认证秘密，关闭截图，并在成功或失败后清理配置。
原生输出和轮换凭据只经私有管道处理，公开报告仅有固定状态、布尔值和计数。

单章与整书模式分别记录所选书籍、章节范围和显示尺寸，不证明全部书籍类型、
真实云端同步写后回读、多设备协调、笔记写入或 KO2 实体按键／休眠／网络恢复。
真实界面通过结构、文本位置和重绘核对，没有保存私人页面截图，也没有人工目视验收。
完整授权保存功能仍由已有授权测试覆盖；本项的设置过滤仅用于隔离开发凭据。

后续 TXT 本地原文定位已接通，使用独立的纯文本 UTF-16 坐标；真实验收也增加了 Python 原文哈希／
唯一样本偏移与实际 CRE 字符位置的一致性、后台采集、位置提示、原生往返跳转及既有同步单位保护。
TXT 的云端坐标语义与精确上传仍未核对，见[TXT 原文位置说明](txt-source-position.md)。
