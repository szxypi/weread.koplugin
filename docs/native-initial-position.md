# 首次云端位置：独立协议验证

真实账号的一本无云端章节位置的 TXT 已经建立首次位置：恰好一个原生零时长请求、明确成功回执、原生／Web 精确目标回读，以及最后独立核对通过。新的进度保留，未尝试恢复成零章号。

这是 Python 发送器的协议证明；阅读器提供目标位置和只读来源核对。生产插件的首次同步入口仍未接通，不因这次试验开放自动初始化。

## 区分原始状态和目标位置

`native_initial_position.py` 的 `no_chapter` 是带类型的观察，不是一个正常位置：保留明确的零章号／零偏移／零百分比，分别记录章节索引和摘要是否存在。缺失字段不会填成实际章节索引或空摘要。目标继续使用既有严格正章号位置模型，包含目录明确索引、原文 UTF-16 偏移、30 个字面原文标量和实际界面整数百分比。

本次范围仅选用三项原生计数均为零的样本。它不证明有历史时长但缺位置的情况，也不证明服务端能够恢复“尚无章节”的状态。

## 候选、发送与回读

1. 已有书架的正常“阅读”流程进入实际 ReaderUI。真实后台工作进程重新核对账号、原文和目录，父进程验证锚点可见、原文坐标反向匹配和当前页面百分比；候选仅经私有管道返回。阅读器不持有原生写入授权，所有原生网络路由均禁止。
2. 宿主 Python 独立按原始 TXT 切片核对 30 字摘要和目录索引，并读取两种云端原始状态、原生版本、三项计数、两端书架成员／标记和来源指纹。
3. 先禁止发送预演，再以新进程重做候选和只读核对。正式发送前再次读取原始状态，声明新独立钥匙串槽位后才允许唯一请求。
4. `readingTime=0`、`hours=[]`，不附带历史时长。成功回执先持久保存，再进行最多四轮只读等待；首次即时观察未齐备，第二轮两端目标完整一致。再独立读取来源、版本、计数、书架和目标，才封存槽位。
5. 最后以不启动阅读器、无写入能力的 `--inspect` 在新进程连续核对两份完整状态；当前目标仍一致，原有槽位和回执结论保持。

`secure_native_initial_position.py` 使用独立服务和协议，单次领取、保存／回读及旧修订保护。已领取或已封存范围不能再次发送；没有成功回执时，即使当前位置匹配目标，也保留未知结果。

## 结果与边界

[固定字段记录](validation-assets/2026-11-12/native-initial-position.json)包含：

- 两尺寸真实 KOReader 合成账号候选／首次写入流程。独立模拟服务核对完整请求与签名；正常和延迟回读封存一次，缺回执／拒绝回执保留未知，计数变化保留已有成功回执并停止。
- 真实账号先准备、两次禁止发送预演，正式一个数据请求、零授权请求、一个明确回执、第二轮目标读回及最终独立复核。原文／目录、版本、三项原生计数、书架成员和标记保持；最近阅读时间和排序可能已更新，不能宣称所有服务端历史恢复。
- 原始无章节观察、目标和摘要仅保存在钥匙串；正文和实际标识只在内存管道／临时内存文件系统使用。普通报告只保留固定字段，临时配置删除、工作进程回收，无正文截图。
- 旧手动、关书、定时、原文摘要及所有旧授权试验的消费记录保持。新增范围已封存为 `retired/posts=1`，启动标记已消费，不能重跑。后续核对仅使用 `--inspect`，不会改变回执或创建恢复请求。

现有字段和签名参考已保留归属的 [Moon 固定版本实现](https://github.com/AnkioTomas/moon/blob/43b2181da6eb5285b62114da85e1413d2f8464e4/book.koplugin/source/wechat/app.lua)与[墨水屏端点目录](https://github.com/teng-lin/weread-omni/blob/88bd2e095d7d7ee423eaadf8f40653e72c5be6d4/docs/endpoints.md)。这些资料列出请求构造，不作为首次初始化或恢复语义的证明；语义结论来自本次限定实际请求与独立回读。
