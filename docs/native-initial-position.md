# 首次云端位置与原生入口

真实账号的一本无云端章节位置的 TXT 已经建立首次位置：恰好一个原生零时长请求、明确成功回执、原生／Web 精确目标回读，以及最后独立核对通过。新的进度保留，未尝试恢复成零章号。

这项真实写入来自 Python 发送器，阅读器提供目标位置和只读来源核对。随后已把该协议接入生产原生插件：正常同步时可显式选择“同步当前阅读位置”，成功回执、精确回读和本机保存完成后才授予后续自动同步资格。原生入口已通过两尺寸完整合成验收，尚未新增真实账号的原生首次写入。

## 区分原始状态和目标位置

`native_initial_position.py` 的 `no_chapter` 是带类型的观察，不是一个正常位置：保留明确的零章号／零偏移／零百分比，分别记录章节索引和摘要是否存在。缺失字段不会填成实际章节索引或空摘要。目标继续使用既有严格正章号位置模型，包含目录明确索引、原文 UTF-16 偏移、30 个字面原文标量和实际界面整数百分比。

本次范围仅选用三项原生计数均为零的样本。它不证明有历史时长但缺位置的情况，也不证明服务端能够恢复“尚无章节”的状态。

## 候选、发送与回读

1. 已有书架的正常“阅读”流程进入实际 ReaderUI。真实后台工作进程重新核对账号、原文和目录，父进程验证锚点可见、原文坐标反向匹配和当前页面百分比；候选仅经私有管道返回。阅读器不持有原生写入授权，所有原生网络路由均禁止。
2. 宿主 Python 独立按原始 TXT 切片核对 30 字摘要和目录索引，并读取两种云端原始状态、原生版本、三项计数、两端书架成员／标记和来源指纹。
3. 先禁止发送预演，再以新进程重做候选和只读核对。正式发送前再次读取原始状态，声明新独立钥匙串槽位后才允许唯一请求。
4. `readingTime=0`、`hours=[]`，不附带历史时长。成功回执先持久保存，再进行最多四轮只读等待；首次即时观察未齐备，第二轮两端目标完整一致。再独立读取来源、版本、计数、书架和目标，才封存槽位。
5. 最后以不启动阅读器、无写入能力的 `--inspect` 在新进程连续核对两份完整状态；当前目标仍一致，原有槽位和回执结论保持。

`secure_native_initial_position.py` 使用独立服务和协议，单次领取、保存／回读及旧修订保护。已领取或已封存范围不能再次发送；没有成功回执时，即使当前位置匹配目标，也保留未知结果。

## 结果与边界

[固定字段记录](validation-assets/2026-11-12/native-initial-position.json)包含：

- 两尺寸真实 KOReader 合成账号候选／首次写入流程。独立模拟服务核对完整请求与签名；正常和延迟回读封存一次，缺回执／拒绝回执保留未知，计数变化保留已有成功回执并停止。
- 真实账号先准备、两次禁止发送预演，正式一个数据请求、零授权请求、一个明确回执、第二轮目标读回及最终独立复核。原文／目录、版本、三项原生计数、书架成员和标记保持；最近阅读时间和排序可能已更新，不能宣称所有服务端历史恢复。
- 原始无章节观察、目标和摘要仅保存在钥匙串；正文和实际标识只在内存管道／临时内存文件系统使用。普通报告只保留固定字段，临时配置删除、工作进程回收，无正文截图。
- 旧手动、关书、定时、原文摘要及所有旧授权试验的消费记录保持。新增范围已封存为 `retired/posts=1`，启动标记已消费，不能重跑。后续核对仅使用 `--inspect`，不会改变回执或创建恢复请求。

独立 Python 协议阶段的 22 项新增测试、126 个测试模块共 1626 项测试（零跳过）、256 组 Lua 通过；730 份 Lua 语法与 728 份静态检查无警告。1865 份文件凭据／私密摘要扫描和 302 条文档链接检查通过。

## 原生入口与回执恢复

`native_cloud_state.lua` 将无章节观察与正章号位置分开，保留索引／摘要存在性。普通 `point/snapshot` 继续严格校验正位置；旧位置绑定和观察哈希不变，首次同步绑定使用独立哈希域。只有三项原生计数均为零才允许建立位置；只读核对可观察有计数但仍无章节的当前状态。

正常同步读取到明确 Web 无章节状态后，不采用较旧网关位置。手动同步提供“同步当前阅读位置／保留 KOReader 进度”；取消、打开书籍、定时或关书均不建立位置。选择绑定当前账号、文档和页面，准备时重新核对原文及目录、原生版本、完整原生基线、计数和书架；Web 与原生的可选字段存在性可不同，实际原生基线仍原样绑定。

发送器先保存 SQLite 领取，再发送唯一零时长原生请求。初始目标只能是正章号完整原文点，不能以 Web 发送器或只读匹配替代首次成功。明确回执先保存，最多四轮回读允许暂时仍为原始无章节状态；目标及计数完全匹配、本机结果保存后才开启后续同步。后来的本机移动继续保留为待同步点。

缺回执、拒绝回执保留 `pending`，计数变化保留 `acknowledged`，本机保存失败保留 `verified` 并关闭自动资格。正常同步进入既有只读核对流程；当前仍无章节时直接说明该状态，不显示成 0% 坐标。取消核对保留旧阶段，显式归档也不会把未知结果改写成成功。

[原生入口固定字段记录](validation-assets/2026-11-12/native-reader-initial.json)记录实际 KOReader／后台进程／SQLite 和离线新进程的两尺寸合成验收。六类场景覆盖成功、延迟、缺回执、拒绝、计数变化及本机保存失败；每类恰好一个模拟数据请求，零真实数据或授权修改。另保留无原生授权输入的取消／离线续读与原有手动、定时、未知回执回归。

本轮 127 个 Python 模块／1630 项测试（零跳过）、257 组 Lua、733 份 Lua 语法和 731 份静态检查通过，无静态警告。两尺寸原有手动／定时／未知回执回归和无原生授权输入的取消／离线重开均通过。1871 份文件与候选包的凭据／私密摘要扫描、305 条文档链接通过，旧消费记录和钥匙串授权保留。

下一步需以另一合格样本和新独立范围验证原生入口的真实首次写入；已封存的 Python 范围不可重用，也不恢复成零章号。实体 KO2、实际写满／断电、多设备并发、更多格式、有历史时长但无章节的初始化和整体性能仍待验收。
