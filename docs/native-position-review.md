# 核对待确认的进度同步

开发分支已在阅读器的“同步进度”入口接入恢复流程，尚未发布。存在上次未完成的原生位置记录时，
先显示书名并询问是否核对当前云端；读取不会重发或撤销旧请求，也不会直接移动本机位置。

## 核对和重新比较

后台连续两次独立读取原生版本、完整位置／摘要、三项时长计数和书架；两份当前状态必须完全一致。
核对可以接受其他设备已产生的新状态，不要求云端还停在旧请求的起点或终点。核对期间发生变化便停止，记录和本机位置保留。
只读恢复不会续期；授权失效时提示检查墨水屏登录，不重发数据修改。

核对完成后，用户可保留待确认记录，或封存旧记录并重新比较当前打开的书。
没有明确回执的旧请求始终保留“结果未知”；当前位置即使恰好等于旧目标，也不据此判定旧请求成功。
已有回执的记录保留原阶段，核对不会把旧位置覆盖到阅读器。

封存使用账号、请求编号、阶段和修订的原子比较；摘要记录与解除阻塞在同一 SQLite 完整提交中完成。
保存失败全部回滚，旧记录继续阻止发送。历史最多保留 32 条，保存原阶段及原请求／当前状态的哈希，不保存正文摘要。
旧回调、已封存选择及其他账号不能修改新记录。

封存本身保留最新本机意图，并撤销旧的自动发送资格。随后重新读取位置；存在差异时，即使关闭了平时的冲突提示，
也要求再次选择本机或云端。保留本机产生新的来源检查和请求编号；使用云端只定位和保存所选位置。
翻页、切书、关书、换账号、断网、休眠或 40 秒有效期结束，会取消尚未完成的核对和选择。

## TXT 的云端选择

验收发现云端定位仍只支持 XHTML，现已接通独立 TXT 分支：核对 `e_0` 的同书／章标记后，读取 `t_0`、`t_1` 原文，
前后位置与 Reader 内嵌位置必须一致，按字面 TXT UTF-16 模型反向核对目标。
独立归档还须匹配原文哈希、字节数、格式、文件身份和渲染章；不能把 TXT 当 XHTML 过滤，也不能从本机跳转推导云端资格。
保存云端选择需要已核对的云端来源包、实际应用的位置和当前目录索引一致。

## 验收与限制

[固定字段记录](validation-assets/2026-11-12/native-position-review.json)区分模拟 UI 和真实只读数据：

- 600×800 和 KO2 尺寸各七种实际 ReaderUI 场景：保留本机、使用云端、取消、翻页、断网、换账号、封存提交失败。
  模拟未知请求已在本机服务生效但不返回成功回执；核对不重发，旧结果不改写，新移动保留到用户再次选择。
- 每个场景全新进程离线重开，HTTP 为零；已封存记录仍为未知历史，未封存记录和本机意图仍保留。
  后台进程回收，三项计数保持，临时配置删除，283 个安装文件与候选和源码一致。
- 实际 SQLite 验证两个进程竞争封存只有一个成功、提交失败回滚、旧修订／旧回调拒绝、32 条历史上限及新进程回读。
  控制器覆盖准备、未知、已有回执、已核对四种原阶段及授权／页面／超时／存储边界。
- 真实 TXT 云端目标由 Python 和 Lua 分别读取并完整比较，KOReader HTTPS 六次读取一致。
  真实原生恢复任务再作两份完整状态读取，与宿主独立前后读取一致；测试记录仅在内存中，不封存真实记录。
  本轮真实账号数据修改、授权 POST 均为零，已消费的真实往返记录保持不变。
- 253 组 Lua、119 个 Python 文件共 1512 项测试通过，Python 无跳过；原有 XHTML 云端定位／跨章场景回归通过。

真实读取证明接口及模型一致，完整恢复 UI 使用合成账号验证；未故意制造真实账号的未知写入。
实体 KO2、断电、更多多设备竞争和发送前原生授权恢复衔接仍待验收。设备性能专项继续安排在整体功能验收后。
