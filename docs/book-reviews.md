# 书籍公开书评

从书籍详情进入「书评」。已启用微信读书 Skill 时，可浏览推荐和最新两个分类；仅使用墨水屏登录时，普通数字书号支持浏览最新书评及五星筛选，无需额外的 Skill 密钥。五星筛选只作用于当前已加载的书评，继续加载可以扩展筛选范围；离线时只筛选已保存的结果。导入书和公众号等其他书号暂未验证该墨水屏接口。推荐排序仍使用 Skill 接口，不把未经确认的内容称为推荐书评。

两种入口都可在列表末尾加载更多，并保留原来的滚动位置。评分按微信读书五星量表显示。关闭详情或书评、切换账号或取消加载会终止相应的后台任务；401 时可通过已有的受控授权续期恢复读取。查看书评不修改云端数据。

墨水屏通道会按账号保存已加载的最新书评。断网、缺少该通道授权或首次加载失败时，可从书籍详情查看本机已有的快照。Skill 通道也按已登录账号分别保存已加载的「推荐」和「最新」列表。断网时优先恢复该书的 Skill 快照，只有「最新」可用时直接进入该页；两页都未保存时尝试墨水屏快照。页面显示保存时间，并提示结果可能不完整。缓存页不请求下一页；已读取并保存的公开回复可以离线打开。重新联网后再次打开书评可读取新结果。只配置 Skill 密钥时仍可在线查看，登录账号后才保存列表。

墨水屏缓存最多保存 32 本书。Skill 推荐和最新各算一份快照，共用 32 份的上限。两个通道各有 16 MiB 总量，每份快照最多 2 MiB；达到总量限制时淘汰较旧的快照。单份超限或保存失败时保留旧快照，在线结果仍可查看。重新读取的首批与较长缓存的对应内容完全一致时保留较长缓存；内容或顺序变化时保存新结果。切换账号或重新登录后，旧页面及其后台回调失效。缓存只包含展示所需的公开书评字段，Skill 的密钥和分页游标留在当前请求中。

打开一条书评后可选择「查看回复」，浏览回复列表并打开完整文字；在线回复也支持加载更多。Skill 书评入口在同一账号具有墨水屏授权或本机账号缓存、且书籍和书评编号受支持时也提供该入口；仅有 Skill 密钥时仍可阅读书评。关闭书评详情会取消回复读取和关闭其子页面。当前只支持查看公开回复，不提供发布、编辑或删除。

书评中的可识别图片可在详情中选择「查看书评图片」，使用 KOReader 原生图片查看器。图片下载不发送登录凭据；已登录账号首次打开后可离线重看，与想法图片共用按账号隔离的缓存。只配置 Skill 密钥而未登录账号时可以联网查看，但不会创建无账号归属的离线缓存。图片缓存最多 128 张、总计 32 MiB，单张最大 3 MiB；书评列表缓存不会预先下载图片。旧书评快照需要联网重新加载才能识别图片，其他来源或格式不明确时会提示部分附件无法显示。

已查看的公开回复按账号、书籍、原内容编号和类型分别保存；想法回复也使用同一缓存机制。断网、缺少墨水屏授权或首次读取失败时显示本机快照及保存时间，并提示可能不完整；未保存的回复仍需联网读取。缓存最多 64 个回复列表、总计 16 MiB，单个列表最多 2 MiB；保存失败不影响在线结果或覆盖旧快照。重新读取的较短列表与旧列表前缀完全一致时保留旧列表，内容变化时使用新结果。缓存不包含授权信息或私密回复。

## 分页

Skill 通道沿用请求参数 `count=20`，继续加载时带上上一批末条的 `idx` 和返回的 `synckey`。服务可以在后续请求中返回 40 条新书评，每批最多接受 40 条。请求与回包投影在后台运行，凭据隔离且不随响应写入设置；账号、授权或详情变化时丢弃旧结果。重复书评编号只显示一次；缺少有效游标或游标循环时停止本次加载，保留已显示结果。当前最多显示 200 条，达到上限时提示可能仍有更多。见[微信读书官方说明](https://github.com/Tencent/WeChatReading/blob/main/skills/review.md)。

墨水屏通道返回的 `hasMore` 不可靠。它从开头请求比当前显示上限多一条，实际多出一条才提供「加载更多」；扩展前逐项核对已显示书评的编号顺序，发生变化则保留当前页面并提示重新打开。读取最多显示 200 条，达到上限会提示可能还有更多；不足时也会提示服务可能未返回全部书评。不能由此断言已获得本书所有书评。

每条墨水屏结果均校验书号、点评类型、书评编号、时间顺序和有界文本；拒绝明确标记为私密或属于其他书籍的记录。后台仅向界面传递展示所需字段。请求失败保留已显示的内容，不自动重发账号修改。

回复通过墨水屏的单条书评接口读取，核对书评编号、书号以及每条回复的归属、编号和有界文字。与书评一样，使用多取一条及前缀核对来扩展，最多显示 200 条；返回少于请求数量时也不宣称已获得全部回复。回复次序按服务端返回，未假定其严格按时间排序。

## 验证及限制

单元和组件测试覆盖两种入口、评分换算、多页合并、重复与变化的结果、错误回包、取消、账号／凭据变化和关闭详情。KOReader 原生界面在 600×800 和 1264×1680 两种模拟尺寸，使用合成数据通过后台加载、点击、扩展和滚动位置检查。

真实账号只读验证覆盖三本书的不同请求数量；各样本均为目标书籍的点评、时间倒序，扩展前缀保持一致。两本书的 20／40 条结果与 KOReader Lua 展示字段独立比较一致；另外一本书在 1264×1680 KOReader 原生界面经真实后台 HTTPS 加载并扩展，逐项与独立读取核对一致。界面保持可响应，无真实截图、书评文件或凭据文件；此次书评测试没有账号数据写入。因会话过期，验证前单独完成一次授权续期并核对同一账号。

回复在两种模拟尺寸使用合成数据走通从书评详情进入、长回复、分页、滚动位置和返回；另外在真实账号的一条 23 条回复的书评中，从原生列表打开详情并读取两批，逐项与独立读取核对一致。该次使用五次原生只读请求及四次独立只读请求，没有账号数据写入、真实截图或回复文件；仅覆盖一个有回复的样本。取消、父页面或账号改变、回包归属不符、回复次序变化和续期通过组件测试。

Skill 列表的后台分页、分类切换、滚动位置和回复入口在两种模拟尺寸使用本地合成 HTTP 服务验证；两尺寸各核对三次请求及分页参数，合成密钥没有转发给服务。另以真实账号的公开书评构造合成 Skill 列表，在 KOReader 中打开其中一条并通过墨水屏接口读取两批真实回复，与独立读取逐项一致。此项包含三批合成 Skill 列表和两次真实回复读取，没有账号数据写入或真实截图；不代表 Skill 接口本身已获真实账号验收。

最新书评缓存另经两尺寸打包插件验证：合成数据覆盖两批加载、全新进程离线重开、在线读取失败回退、打开正文及账号隔离。实际 SQLite 验证缓存上限、旧长列表保护、内容变化、损坏数据和写入失败回滚。真实账号的一本书在两种尺寸分别完成两批原生只读读取、独立逐项比较及全新进程离线重开；真实内容与凭据仅通过匿名管道和临时内存文件系统，结束后清理，没有真实截图或账号数据写入。实体设备与更多书籍仍待验收。

五星筛选在两种模拟尺寸下用合成数据验证了在线分页、切换、详情、离线缓存及在线失败回退，切换不发出额外请求。真实账号一本书在两尺寸分别通过两批加载、五星筛选和全新离线进程回读，并与独立只读结果逐项核对；没有账号数据写入或真实截图。真实账号三本书的只读抽样显示，墨水屏最新列表与 Skill 推荐列表的顺序不一致；五星筛选不代表官方推荐排序。实体设备和更多真实书籍仍待验收。

书评图片在两种模拟尺寸通过列表、详情、原生图片查看、离线重开和在线失败回退的组合验证；另用一张真实公开图片验证原生解码及全新离线进程，图片地址和临时缓存只在内存中处理并已清理。Skill 入口的已登录和仅密钥场景通过合成原生界面验证；关闭详情取消加载、无法识别附件提示及不带账号凭据下载也已覆盖。真实 Skill 图片结果、更多附件来源及 Kindle Oasis 2 实机仍待验收。

针对回复图片的只读抽查覆盖 3 本书的 6 个公开回复列表、13 条回复，未发现图片或手写附件；这一小样本不足以确定其他回复的附件格式，回复图片暂未接入。该抽查没有账号数据写入，也不保存正文或标识。

公开回复缓存也在两尺寸使用打包插件验证：合成数据覆盖两批加载、离线重开、联网读取失败回退及账号和类型隔离，真实 KOReader SQLite 覆盖容量、旧长列表保护、损坏数据及事务回滚。真实账号的一条 23 条回复书评在两尺寸分别完成两批原生只读读取、独立比较及全新离线进程重开；不产生账号数据写入或真实截图，临时内存文件系统在测试后清理。该结果仅覆盖一个真实回复列表，实体 Kindle 尚待验收。

最终候选复核前，原生授权自然过期；Python 和 KOReader Lua 各自确认 HTTP 401 后，同设备续期一次并核对账号与本机安全存储。随后的两尺寸书评验证没有授权请求或账号数据写入。

Skill 真实分页以《活着》为样本。旧实现拒绝含 40 条书评的第二批。修复后，600×800 和 1264×1680 的 KOReader 原生书评页面均通过真实 HTTPS 加载推荐和最新各三批，每类从 20 条扩展到 60、100 条，编号与顺序同独立读取一致，两类均能打开正文。两尺寸各在全新离线进程恢复两个 100 条的列表，离线请求为零。模拟服务另核对续页游标、滚动位置、账号隔离和仅配置 Skill 密钥的用法。

真实 Skill 验证使用临时内存文件系统，完成后已清理。期间只读，无账号数据写入或真实截图。实体 Kindle、更多书籍与长期接口稳定性仍待验收。墨水屏授权通道的验证脚本 `scripts/verify_native_book_reviews.py`、`scripts/verify_native_book_reviews_http.py` 与 `scripts/verify_native_review_replies.py` 默认离线，真实数据通过内存管道比较。
