# 启动时的旧公众号记录保护

入口：微信读书插件设置 → 高级选项 → **保护启动时的旧文章记录**。
默认关闭。启用或停用均须确认，重启 KOReader 后生效。
启用后，启动时遇到需要恢复的旧公众号文章，会先保存原始候选并显示记录选择，之后才创建阅读器。
普通书籍、独立版本和没有可恢复记录的文章继续使用原生打开流程。

## 加载顺序与范围

原生 `reader.lua` 在“继续上次阅读”和命令行传入文件时，先查询文档引擎，之后才初始化阅读器插件。
只在插件初始化中接入保护，无法覆盖这次早期读取。
开关使用 KOReader 原生的第二阶段启动扩展，在 UIManager／语言方向初始化之后、首个文件打开之前
接入 `ReaderUI.showReader`。没有修改 KOReader 核心文件。

只有不存在活动阅读器和文件管理器时才执行这条前置检查：

1. 按现有公众号／文章索引核对原路径，不按标题推断身份。
2. 将各位置的原始候选保存到现有账号隔离的记录数据库，核对原文身份未变。
3. 保存之后才查询原始引擎，必要时创建文件管理器及正常插件实例。
4. 复用已有的记录选择、确认和后台复制流程。明确选择后，打开完整发布的独立副本，
   保留原启动调用的引擎、参数空位、强制／无缝标记和回调。

有存档但原侧边记录已不在时仍可进入恢复选择；来源、存档或保存检查失败则停留在文件管理器，
不继续原生直开。取消、账号变化、窗口销毁、来源变化及旧回调不能继续本次恢复。
文件管理器和阅读器中的常规切书继续由已有入口保护；显式其他引擎和辅助编辑器沿用原生流程。
新副本带独立版本标记，下一次启动可直接重开，不重复询问。

## 启动文件管理

启用时在 KOReader 的用户补丁目录创建 `2-weread-startup-records.lua`。
它仅包含安装路径、启用检查和模块入口，不含账号、Cookie、书籍或阅读记录。
暂存内容完整写入并同步后发布，再独立读回核对；同名外来文件、链接或被修改内容不会被接管。
停用只删除与本插件生成内容完全一致的入口，不处理其他启动文件。
菜单中取消确认不写文件，停用和重新启用均保留文章及记录数据库。

KOReader 全局停用用户补丁时，此保护不能执行；插件入口会提示暂不可用。
停用／移除微信读书插件或原安装路径不存在时，已生成的入口自行跳过。
如果手动移动了安装目录或修改了生成入口，先备份并处理该同名文件，再从新安装位置启用；
不把不同内容当成本插件可直接覆盖的文件。已安装入口的更改仍以完全重启后的状态为准。

这不会重建启用之前已经丢失的原始字节，也不会自动判断哪份共享记录属于当前正文。
不可读的候选仍按原样保存，恢复必须由用户明确选择。

## 实际验证

使用官方 KOReader v2026.07.1 Linux ARM64／Xvfb，两种尺寸分别执行四个场景：

- HTML：原生“最近阅读”冷启动，选择旧备份后恢复，随后独立进程直接重开新副本。
- EPUB：实际 `reader.lua 文件名` 入口，选择记录、恢复原生正文／位置／笔记，独立进程直接重开；
  Python 另核对副本中原有成员的字节一致。
- 取消：真实选择窗口取消后留在文件管理器，调用旧打开回调仍不会创建阅读器；之后重启可正常恢复。
- 来源变化：确认前实际改变合成正文，恢复被阻止；测试工具恢复合成原文，再由新进程完成恢复及重开。

观察补丁在保护入口之后加载，通过实际 UIManager 循环操作原生控件；
每次原路径的早期记录读取都核对原始候选已经提交，选择完成前禁止创建阅读器。
测试仅通过原生操作关闭明确识别的首次统计迁移提示，确认框必须是当前可见窗口，
恢复和独立重开后的阅读器也须位于最上层；没有跳过遮挡窗口操作下层按钮。
各场景也通过原生设置验证默认关闭、取消不写、启用读回、停用及外来文件保护。
组件检查另覆盖入口安装、文件错误、插件禁用、缺失路径、命名空间、账号及过期回调边界。

```sh
luajit spec/startup_patch_spec.lua
luajit spec/mp_startup_open_spec.lua
xvfb-run -a python3 scripts/test_mp_startup_runtime.py \
  --koreader /path/to/runtime --run-dir /path/to/new-profile \
  --content html --scenario restore
```

`--content` 可选 `html`／`epub`，`--scenario` 可选 `restore`／`cancel`／`source-changed`。
全部账号、正文、笔记和修改均为合成数据，微信读书通道无请求，不访问钥匙串。
当前版本只在上述环境验收；实体 KO2 的启动器、按键、用户补丁设置、文件系统及断电仍待验证。
未识别旧文件、其他插件自行提前读取元数据和独立元数据归档仍在原开发清单中。
固定字段与回归见[验证证据](validation-assets/2026-11-10/mp-startup-protection.json)。
