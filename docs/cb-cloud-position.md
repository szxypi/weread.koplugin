# CB_ 云端位置与本机阅读边界

CB_ 书籍的原生正文、翻页、本机位置和离线重开继续可用。当前正常同步入口明确提示本书暂不支持云端进度同步，
保留待同步点，不提供未经核对的云端跳转或自动上传资格。书架上的已知云端进度显示保留。
这是同步能力的未完成边界；CB_ 前缀也不单独证明书籍的上传来源。

## 实际只读核对

`verify_cb_cloud_position.py` 默认离线。显式复用保存会话后，先核对同账号的 Web／墨水屏 CB_ 集合，
再逐本读取一个正常续读章节、Web 与墨水屏位置。固定目录／内容 POST 仅作正文查询，
不发进度、时长、书架、批注、购买、试读或授权修改请求。

五本书的五份 XHTML 正文、十份位置投影经 Python／实际 KOReader Lua 比较一致。
每本前后完整位置字段、可选字段存在性与已有计数保持；目录与版本保持，结束时 CB_ 集合保持。
章号只能对应目录明确且唯一的索引，缺失字段不填成一个可写位置，旧数字书号的发送校验不变。
其中三本的旧偏移落在当前过滤后来源的可见边界，两本没有；五本在该偏移处都未匹配旧摘要首部。
首尾两个额外诊断样本的旧 30 字摘要可以在章节中唯一找到，其起点没有与按当前模型解释的云端偏移对齐。首个样本的原始 XHTML、过滤后 XHTML及六种简单偏移解释也未对齐旧摘要起点。
偏移与旧摘要之间的实际语义仍需进一步核对；本项不将摘要匹配位置替换成云端位置，也不据投影一致开放写入。

一份正常续读章节有 37 个 body，原有本机模式可处理它，云端语义仍未证明。
原始／过滤后坐标与纯文本、非空白文本、Unicode 标量和 UTF-16 单位的诊断结果分别记录，避免混用。
早期比较工具缺少运行环境初始化，记录为未通过；补齐后再完成正式比较，原始失败记录保留。

## 修正不支持状态的处理

此前上传候选只接受数字书号，CB_ 会在完成来源准备后才失败，并显示稍后重试；
较早的比较结果还可能留下已确认资格，导致定时器继续准备同样不支持的上传。
现在手动、打开和恢复时均直接保持未确认状态；同步按钮显示明确限制，不启动远端读取或来源上传准备。
过期的内部决定、关书任务和直接发送入口也不能绕过限制。本机原文点及待同步记录继续保存，
旧 CB_ 任务不会撤销另一本文字书的确认／定时器，也不会把另一本文字书的位置写入错误的书籍记录。

## 原生流程验收

[固定字段记录](validation-assets/2026-11-12/cb-cloud-position.json)分别记录模型核对与界面行为。
在 600×800 和 KO2 尺寸中，各按当次完整 CB_ 书架的序号 1、5 选择单 body 与多 body 的正常续读样本。
四组分别运行联网及全新离线进程，共八个实际 ReaderUI 进程：正常书架选书、正文显示、翻页、原文定位和本机重开通过。
每个进程连续两次正常同步均显示明确限制，没有云端选择；每次按钮操作新增 HTTP 为零，确认资格和定时任务均保持关闭，
待同步点不被清除。各组独立回读 Web 完整位置、摘要、计数和字段存在性仍一致。

真实配置与正文只在内存、捕获管道和临时内存文件系统中使用，结束删除配置并回收工作进程；没有真实正文截图。
公开记录仅含固定标签、数量与布尔值。全部旧已消费的首次位置、手动、关书、定时及其他试验记录继续保留。

后续需继续核对 CB_ 云端偏移和原文语义，再用新的有界 Python 协议范围验证发送，之后才接通原生上传；
也仍需实体 KO2、其他正文格式、并发与实际设备故障验收。整体性能专项保持在功能验收之后。


普通数字书号的手动／定时／未知回执及首次同步模拟另经回归。KO2 尺寸的早期运行在发送前停止，零模拟请求；
旧候选的独立对照也记录到来源变化。失败记录保留，测试现在等待页面、原文点和百分比稳定后再操作，
没有放宽生产来源有效期或发送门槛，后续正常往返通过。
131 个 Python 模块／1668 项测试、258 组 Lua、738 份 Lua 语法及 736 份静态检查通过，零跳过、零静态警告。
