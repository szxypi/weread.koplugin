# Web 登录续期与后台读取恢复

「立即续期 Cookie」现在在后台完成固定 Web 续期和登录核对，不在界面线程联网。
目录和文章正文遇到登录失效时，可在同一账号、阅读会话和目录绑定下完成一次续期，再重新读取一次。
这项恢复只作用于读取；不重放书架、进度、时长、划线或其他账号数据写入。

## 状态与保存

每次发送前，先将当前账号、登录代次、凭据修订摘要和待确认状态写入独立的
`web-renewal.json`，排他文件写入、同步、重命名和主文件回读均通过后才允许 POST。
该文件只保存一个有界状态／回执，不使用旧备份回退，不把集合数据放入配置。

| 状态 | 后续操作 |
| --- | --- |
| 待确认 | 已允许发送，但没有可靠回执；取消、超时、进程退出或重启不自动再次 POST，需重新登录 |
| 回执已收到 | 成功回执中的同账号凭据已保留；后续只重试账号／书架 GET 核对 |
| 核对完成 | 可重试保存并回读；保存失败不会再次发送续期请求 |
| 完成 | 新登录状态已保存、同步并回读，回执副本从状态文件移除 |

只有已证明未创建执行进程／未分派请求的失败才释放本次发送意图。
一次有待确认结果的登录不会因手动改 Cookie、关闭窗口或重新打开而获得重发权限。
新的二维码登录会更改登录代次，旧账号／旧代次回执不能发布到新登录中。

后台仅调用已验证的固定续期 POST、账号资料 GET、书架 GET、再次账号 GET。
请求携带捕获的 Web Cookie，不带 Skill 或墨水屏 Bearer；不跟随跳转、不由子进程写配置。
候选 Cookie 的账号必须保持原绑定，账号响应必须匹配绑定账号，书架响应必须有可接受的数组结构。
收到合法的同账号 Cookie 更新会保留；响应省略附加头时保留原来的同账号字段，不把省略当作清除授权。
身份、字符串、响应及管道容量均有边界，日志／错误提示不输出原始响应、查询、凭据或底层异常。

父进程核对内存与当前主配置的登录修订，再将确认后的字段合并到新读取的主配置，
保留期间更新的用户设置、Skill 密钥和书籍索引；更新后同步、重新读取主文件并再核对账号。
网络期间的新本机进度及待上传意图保留。保存过程中已有主配置写入而最终确认未完成时，
只允许已核对的同代次回执协调旧／新两种已知修订，不盲目覆盖第三种凭据。
使用新协调器恢复磁盘回执时先只读重新核对，不再次 POST。
这是 KOReader 父进程中的保存协调，不宣称对任意其他进程写配置提供文件系统级比较交换。

取消、关页、关书、休眠、账号／Cookie／附加头／阅读会话变化后，旧结果不能发布。
保存失败显示「只重试保存」确认；未完成核对与未知回执使用不同提示。
损坏状态会阻止发送；用户明确清除登录信息后，在旧登录代次失效的前提下移除这份有界状态，
保留缓存书籍，重新登录即可重新开始。不会跟随状态文件的符号链接删除其他文件，也不递归清理目录。

## 读取恢复

- 目录 HTTP 401 或既有登录错误 `-2012` 最多进入一次恢复，确认保存后重取首批目录；再次失效即停止。
- 正文 HTTP 401／登录错误采用同样的一次恢复。原有附加头的只读备用变体保持有界；
  恢复后重新捕获登录读取权限、使用新的正文／图片暂存代次，不复用半成品。
- 首页／书架的可见展示进度在明确 Web HTTP 401 后现可恢复一次，
  保留有效展示前缀，只续查剩余书籍；该接口的其他业务码不自动触发维护。
  详见[展示进度的恢复范围](shelf-progress-prototype.md)。
- 续期等候期间目标缓存文件或受管文章目录已被替换时，停止原下载，保留新文件，不把事务基准重新绑定到外部替换物。
- `-2041` 继续显示验证不可用，不靠自动续期或扫码循环假装解决；HTTP 429 不重读或续期。
- 目录首批仍是最多 100 篇；成功空目录、旧目录恢复及本机缓存规则不变。
  手动续期和自动恢复共用同一发送意图，过期请求不能关闭新任务的提示或打开旧结果。

## 实际验证与限制

先有 `scripts/verify_web_renewal.py` 原型，再实现 Lua。默认离线，不打开钥匙串或联网。
本轮先复核已保存的账号及 139 本书架；独立匿名资料请求返回 HTTP 401，没有跟随跳转。
另分别完成一次 Python 和一次插件 Lua 的固定续期、核对、保存回读，各只有一个凭据维护 POST。
Lua 通过实际 HTTPS 完成续期和三次核对读取，父进程再次核对账号／书架后保存回读钥匙串。
凭据仅经内存／私有管道与钥匙串，不写开发凭据文件；没有账号数据写入。
两次续期都未返回附加授权头，不把它们视为已经取得公众号验证授权。
