# 在读状态的只读核对

书架现有筛选使用服务端明确的 `finishReading`，区分已读完与未读完。另有开源客户端使用 [`/book/markstatus` 的 `status=2`](https://github.com/teng-lin/weread-omni/blob/main/src/api/resources/shelf.ts) 标记或取消在读；这一实现本身不能证明该操作的独立回读字段、影响范围或恢复语义。

2026-11-24 使用已保存的同一账号授权，只读抽查数字书号书架的 30 本书。独立读取墨水屏进度接口，检查服务端的 `isStartReading`、章节号、`startReadingTime` 和书架的 `finishReading`，前后核对书架成员、标志及分组。仅保存[汇总计数](validation-assets/2026-11-24/reading-state-owner-readonly.json)，不保存书号、书名、具体位置或凭据；没有发送账号数据修改请求。

其中 6 本返回 `isStartReading=0` 且章节号非零；另有 4 本同时返回 `isStartReading=1` 和已读完。这个有限样本表明不能用章节位置或已读完状态推断该字段，也不能把它直接等同于用户手动设置的「在读」。字段缺失或格式异常时保持未知，不按零处理。

可使用 `python3 scripts/verify_reading_state.py` 离线检查；显式加入 `--saved-session` 才会检查钥匙串中的同账号授权并执行有界只读采样。账号核对后，墨水屏探针只允许书架与所选进度的 GET，遇到账号、书架、目标或接口异常即停止；结果只含汇总。此记录不证明写入操作成功或可逆。

## 原生界面读取

书籍详情的「书架状态」现提供「查询开始阅读状态」：用户主动触发后，在后台通过墨水屏授权读取当前书籍的明确字段，既不改动云端，也不改动本机阅读位置。普通数字书号和 `CB_` 导入书都支持；离线、登录失效、字段缺失或响应身份不符时分别保留未知状态，不推断为未开始。关闭菜单、取消或切换账号后，旧结果不会显示到新页面；读取结果不保存为持久状态。

安装打包插件的 KOReader 分别以 600×800 和 KO2 的 1264×1680 模拟尺寸，验证已开始、未标记开始、字段缺失、身份不符、登录失效与取消。另以真实账号的 5 本普通书和 5 本导入书进行只读比较，Python 读取结果与生产 Lua 投影及 Lua 原生 HTTPS 再次读取一致，书架前后未变。随后在隔离的完整插件实例中，从书架状态菜单分别查询一本真实普通书和一本真实导入书，两种尺寸的结果均与独立读取一致；此项直接打开状态菜单，未覆盖从真实书架选书进入的整条路径。授权凭据通过匿名内存传递，测试配置经扫描并清除；轮换后的网页登录授权继续保存在钥匙串。测试结果见[记录](validation-assets/2026-11-24/reading-state-native-read.json)。实体 KO2、真实书架入口及更多书籍仍待验收。

## 自造书的单次标记与恢复

另以自造 EPUB 导入一份仅用于本次实验的书，核对账号、书架、来源和明确的零章节状态后，对它发送一次 `status=2` 标记。独立回读显示 `isStartReading` 从 0 变为 1，`startReadingTime` 也变化；该书在墨水屏书架响应中观察到的状态字段未变。服务端回执没有匹配现有的成功格式，自动流程随即停止，没有重发，也没有自动取消。

随后以独立只读流程再次确认测试书、账号和两端书架稳定，并用事先持久保存的校验值核对测试前状态。单次取消后，独立读取确认该书的观察字段与测试前完全一致；取消的回执同样没有匹配现有成功格式。最后在另一轮只读预检后，精确移除这本自造书，两端书架再次核对一致；全新进程另行确认测试书已移除、原书架与分组一致。每一步使用不同的一次性记录；仅发生一次标记、一次取消、一次测试书导入通知和一次移除，未修改既有书籍。固定字段结果见[验收记录](validation-assets/2026-11-24/reading-status-fixture-owner.json)。

这个结果只证明一份导入书在本次条件下可观察到上述变化，不能推广为所有书籍或全部服务端历史都可恢复；也不能把 HTTP 200 或未识别回执当作成功。下一步仍需核对普通书、其他状态及生产界面的独立回读与未知结果处理，实体 Kindle 也待验证。
