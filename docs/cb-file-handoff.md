# CB_ 书籍的跨文件本机位置与整书验证

CB_ 书籍现可沿用普通书的本机原文交接，在单章 EPUB 与整书 EPUB 之间切换时恢复同一章节和精确偏移。
数据通过微信读书接口取得，正文仍由 KOReader 原生阅读器排版。

## 本机交接

`weread/ui/read_resume.lua` 的三处入口改用已验证的展示编号范围，接受严格的 CB_ 编号。
原有账号、登录代次、当前文档、页面、取消、回调期限与新阅读器身份检查保留。
交接必须取得目标包自己的来源回执，并确认原始正文摘要和坐标单位相同；不能把旧文件的归档身份直接移给新文件。
较新的本机位置缺少来源时不复活较旧位置，正文变化时不推测落点，已有本机记录保留。

这项改动只放开本机交接。`upload_verified` 仍须为 false；云端位置、上传、批注及其他写入的数字编号校验没有放宽。
CB_ 云端同步语义仍未验收，不能以本机精确定位通过代替真实云端读写证明。

## 原生合成验证

显式启用一条自写 CB_ 书籍夹具；默认普通书夹具不变，成员和批注写入范围也不扩展。
600×800／167 DPI 与 1264×1680／300 DPI 分别覆盖 EPUB 和 TXT，共四例，每例包含联网与全新离线进程。
每例下载六章整书，核对原始来源回执和原生正文位置，并执行保存位置到整书、当前单章到整书、整书到单章的交接。
正在准备时取消不会继续打开旧文件；账号不符、较新待同步位置、缺失目录章节和全新离线重开另有检查。
这些场景没有真实账号请求或数据修改，离线进程零 HTTP。

[TXT 离线恢复](validation-assets/2026-11-11/cb-file-handoff-txt-ko2.png)均为合成正文，已目视检查。

普通数字编号书籍的 EPUB／TXT 缓存续读与交接四例、常规阅读／同步恢复与首页／书架／书城组合四例，
也通过同生产代码的两尺寸回归。187 组 Lua、62 份 Python 的 784 项检查零跳过；
499 个静态文件零警告／错误，501 个 Lua 语法、167 个 Python 编译、命名空间和四时区检查通过。
13 份候选各 208 个生产文件与当前源码一致，12 个合成安装目录逐字节一致，ZIP CRC、截图尺寸与重绘检查通过。

## 真实整书协议与验收边界

默认离线工具 `scripts/verify_cb_full_reading.py` 在显式复用保存授权后，只选择完整 CB_ 书架排序的第一本，
读取其所有正常可读章节，不跳过失败章节，也不更换成更容易验证的书籍或章节。
每章的 Reader、正文分片和样式查询有独立次数限制；同账号、目录、版本和云端位置前后核对。
先完成 Python 实测，才增加等价的原生整书验收工具；此次生产代码只修改本机交接入口。

首轮 Python 协议读通 57／57 章，原始正文共 1,153,077 字节、两个图片引用；
其中一章包含两段连续 XHTML，受保护图片包含两个文件。目录、版本和云端位置未变。
编号、正文、位置、会话和凭据仅在内存、捕获管道和短期 tmpfs 中使用；真实界面不截图。
验收工具在显式 CB_ 整书模式允许 2–128 章，其他既有整书模式的 32 章限制保留。
包检查仍逐章核对原始摘要、实际文字、图片、spine 顺序、CRC 及新进程离线包一致性，不以部分章节代替整书通过。

同一生产候选在 600×800 下两次实际整书下载均未通过，分别在第 56／46 章收到缺少书籍身份的 HTTP 200 阅读页。
同一失败响应经 Python 校验也不通过，实际 Cookie 请求头与登录快照相同，未发现校验工具拒绝合法响应的证据。
随后各一次独立位置回读均返回 HTTP 200／业务码 -10102，无法确认下载后的云端位置。
没有为此自动续期、重发写入、跳过失败章节或更换书籍；也没有对第二尺寸继续尝试真实整书。
这仅能确认读取流程受阻，尚不能确定其服务端原因，不能宣称整书、图片或真实交接通过。
两次临时 tmpfs 均清理，真实界面和正文没有保存。计入首次协议及全部尝试，共 340 个 GET、
1,000 个只读目录／内容查询 POST，零账号数据与授权 POST。

原生整书的实际结果与失败尝试见[固定记录](validation-assets/2026-11-11/cb-file-handoff.json)。
真实 CB_ TXT、更多书籍／复杂正文、云端坐标与写入、自然失效恢复组合及实体 KO2 仍待验收。
开发授权按原约定保留至整体目标完成；本项不复用任何旧账号数据写入许可。
