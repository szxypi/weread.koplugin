# 公众号文章缓存按身份隔离

原来的 HTML 缓存只按文章标题命名。同名文章，或清理文件名后同名的文章，会共用一个文件。
下载后来的文章可能覆盖前一篇；标题更改也会让旧文件无法通过新标题找到。
图片目录虽包含文章编号，但编号清理后相同也会在原来的共享目录中冲突。

新下载采用 `mp-articles/<身份摘要>/article.html`。摘要绑定公众号缓存容器、返回的关联书籍字段、
主文章编号及编号种类；没有主编号时使用原始编号。关联字段只是本机缓存命名的一部分，不推断服务端所有权。
标题不参与身份；编号中的 `/` 与 `_` 不再因文件名清理而合并，数字编号按精确十进制归一。
每篇文章的图片目录位于自己的摘要目录内；后台下载使用独立图片代次，旧图片引用格式继续只读兼容。

## 查找与写入

- 新 HTML 头部记录同一身份摘要，读取时核对目录及头部标记。
  头部不匹配、叶子或受管父目录为符号链接时，不把该文件当作目标文章缓存。
  这不是正文完整性签名，也不证明原服务端响应与所有备用编号的对应关系。
- 书籍记录仍固定公众号根目录，避免将某一篇文章的目录误写成整个公众号的根目录。
  移动全局缓存设置后，已记录的真实缓存目录仍可使用。
- HTML 使用排他临时文件、同步、字节／身份核对和同目录重命名提交。
  创建、写入、同步或接收失败时保留旧 HTML；其他文章的正文与图片不会因同名而覆盖。
  原生列表下载另使用下述正文／图片代次暂存流程；旧低层同步辅助函数不具备这层图片保护。
  单篇强制刷新入口、旧 sidecar 协调和目录读取后台化继续待完善。
- 新路径只在用户实际下载时写入；查看列表或导出不会将旧文件悄悄复制到新身份目录。
  不更改云端书架、进度、读完、置顶、私密或批注；本机进度及待上传记录保持。

## 旧缓存

旧标题 HTML／EPUB 保留原文件。当前保存目录中，只有该文件名明确对应一个已知文章身份时才只读兼容，
界面显示「旧缓存」。此关联仍基于旧文件名及已保存目录，不是原始服务端身份的独立证明。
目录没有记录、身份缺失或超出检查上限时不猜测归属。

存在已知同名冲突时显示「旧缓存需重下」，不直接打开或导出那份不确定的文件。
选择文章会按该行编号重新下载到自己的新目录，同时保留旧同名文件。
两篇已有新缓存的同名文章可分别打开／导出；重复的同一身份条目在导出选择器中合并。
当前文章的导出识别沿用这些规则，旧文件不会因为迁移自动获得精确身份认证。
旧文件的 KOReader 书签、阅读位置和本机批注仍保存在原文件的 sidecar；
重新下载到身份目录时不猜测迁移这些坐标，旧文件及其 sidecar 不被删除。相关协调继续待完善。

参考 MiuRead 固定提交 `c1893562aa25a870b8dd076d7be062a3348f823e` 的
`miuread/mp.lua` 按公众号／文章分目录的组织方式；摘要、旧格式关联和提交保护由本仓库实现。
`weread/lib/mp_cache_identity.lua` 的纯本机规则不新增接口；原有正文 GET 协议已有真实验证。

## 文章链接前置检查

另新增默认离线的 `scripts/verify_mp_link.py`。复用已保存的同账号 Web 授权后，
只从已验证的一个正文样本读取来源元数据，再由独立匿名请求器读取一个规范化公众号链接。
公开请求不带 Cookie／Authorization，不跟随跳转，不执行页面脚本，也不提交账号数据。

本次来源、标题、作者与正文均存在；匿名源链接返回 HTTP 302，位置属于验证路径。
没有跟随该跳转，没有读取验证页面，也没有将文章链接导入标为可用。
失败后仍核对原 Web 账号并按既有规则保留／保存已确认的 Cookie 更新，不删除钥匙串条目。
[真实去敏报告](validation-assets/2026-11-09/mp-link-owner-readonly.json)只含状态、数量、布尔值与固定分类，真实链接、正文、标题、编号和凭据不进入文件。

```sh
python3 scripts/verify_mp_link.py
python3 scripts/test_mp_link.py
python3 scripts/verify_mp_link.py --saved-session --public-source
```

7 组离线检查涵盖两类分享地址、去除分享参数、重复／不合法字段、元数据、匿名请求和不暴露跳转地址。
这不是绕过验证的方案，公开链接读取和后续 Lua 导入继续待验证。

## 后台下载与图片代次

原生文章列表的下载现在由独立后台进程执行：正文 GET、被动 HTML 转换和图片流式写入均离开界面线程。
下载提示可点击／按键取消；关闭微信读书界面、关书、打开新阅读器或休眠也会取消。
完成时核对账号、授权修订、阅读会话、目录设置与现有书籍目录，过期结果不能打开文件或写入目录记录。
只向最新书籍记录合并缓存目录，不覆盖其进度及待上传意图。
如果完整文件已经提交但随后书库记录保存失败，保留完整文件并单独提示，不冒称旧正文未变化，也不让存储异常中断界面。

每次尝试先在文章身份目录内排他创建私有暂存目录，正文通过预先打开的独占文件描述符写入，
图片直接流入本次目录。校验状态、图片签名、字节数、目录身份及文件身份后，
先把完整目录改名为 `.weread-mp-<文章身份摘要>-assets-<随机代次>`，
再原子替换稳定的 `article.html`；正文引用该代次内的 `images/img-0001.png` 等文件。
同一篇文章的后续尝试不会写回旧图片目录。取消、容量超限或提交失败时保留旧正文与旧图片。
清理先关闭父进程描述符，再确认子进程停止／回收，之后只清理自己仍拥有的暂存目录；
替换过的正文／目录和未知文件不会被递归删除，符号链接不会被跟随。

图片仅从已验证的两个微信图片域名匿名 HTTPS GET，不携带 Cookie、Authorization 或微信附加授权头，
不跟随跳转。正文只使用已验证的 `/web/mp/content` GET 及有界备用编号／无附加头读取，
不在下载进程续期、不保存响应 Cookie、不跟随来源链接或执行脚本。
无正文或图片下载失败时提示检查登录、网络及空间；公开源链接的验证跳转不作为备用读取通道。
远程 CSS、脚本、任意本机图片和未经验证的图片域名不保留为自动加载资源；不支持的图片显示占位。
关闭图片下载时继续移除图片。上限为正文 4 MiB、单图 32 MiB、256 张不同图片、图片合计 64 MiB；
重复图片只下载一次。图片通过状态与文件签名检查，不宣称穷尽验证所有图片解码错误。

导出器兼容旧固定图片目录、嵌入位图和新的身份／代次目录；拒绝跨文章代次、路径穿越与图片目录符号链接。
已在文件中的缺图占位会作为文字继续导出，导出统计只统计本次仍为图片引用的缺图。
旧代次暂时保留，因为已打开的阅读器可能仍引用它。异常退出／断电可能留下暂存目录；
没有按时间自动删除其他进程的目录，也不宣称多文件系统断电持久性或跨目录清理协调已完成。
没有新增单篇强制刷新菜单，已有缓存仍直接打开；旧 sidecar 的位置、书签及批注协调继续待完善。
历史低层同步辅助函数仅为兼容保留，原生列表入口使用上述新流程。

真实图片前置由 `scripts/verify_mp_images.py --saved-session` 验证：同账号正文样本有 3 个来源图片，
仅匿名读取第一张，HTTP 200／JPEG／147,959 字节，不跟随跳转、无账号数据写入。
正文、图片、链接及凭据不落盘；结束前再次核对账号并保存已确认的 Cookie 更新，钥匙串条目保留至整体目标完成。
