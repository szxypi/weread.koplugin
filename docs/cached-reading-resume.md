# 多章缓存续读与整书阅读验证

已修复多个单章缓存下的「阅读」选章：资料中的章节号与本机不同，不应覆盖本机尚未同步的章节。
原有缓存入口只检查书籍资料；新增回归在修复前实际失败。缓存与未缓存阅读现在共用以下优先顺序：

1. 本机待同步位置。
2. 最近一次本机阅读位置。
3. 书籍记录中的章节。
4. 未缓存准备流程中新取得的远端章节。

本机记录明确属于其他书籍或其他账号时忽略。账号比较使用阅读记录及数据库相同的内部标识，
不直接与登录编号比较；原有按账号保存、缺少嵌套归属字段的旧记录仍可使用。
优先匹配章节 UID，再匹配有效的章节序号；缓存目标缺失时保留原有「最近且优先前一章」规则。
目录完全缺失时，可以直接按已缓存章节 UID 匹配本机记录，无法匹配才回到原有稳定排序。
整书缓存仍优先，由 KOReader 保存和恢复该 EPUB 的原生阅读位置。

## 原生验证

新增独立的合成 HTTP 流程，全部从插件书架／详情「阅读」及章节列表进入，文件管理器仅创建插件宿主。
先通过实际下载得到第 2、4 章文件，在第 2 章真实翻页并关闭保存。
然后把书籍资料设为第 4 章，分别验证待同步位置优先、无待同步时最近本机位置优先，
以及其他账号明确指向第 4 章时仍使用本账号的第 2 章。每次都检查实际文件、页码及可见原生位置。
另清空合成账号的目录数据库及目录文件，验证直接按本机目标 UID 打开第 4 章缓存。

随后点击详情「下载整书」，确认真实下载六章，读取每章的原始来源，跳转至整书中第 4 章的原文目标。
关闭阅读器后，用全新进程再次从插件打开整书，核对同一文件、章节、页码及可见位置；离线阶段 HTTP 为零。
测试关闭自动同步和阅读时长上报，模拟服务也确认进度／时长 POST 为零。

```sh
xvfb-run -a python3 scripts/test_discovery_runtime.py --cached-resume \
  --koreader /absolute/path/to/koreader --run-dir /absolute/path/to/new-cache-run
```

TXT 增加 `--content-format txt`；KO2 分辨率增加 `--width 1264 --height 1680 --dpi 300`。
默认模拟服务不变，TXT 模式只用于隔离测试：同书 `e_0` 回退标记后读取 `t_0`／`t_1`，
这些读取合约已在此前真实 TXT 响应核对。

`scripts/check_cached_resume_package.py` 独立比较生成 EPUB 中六章原始字节与 Python 模拟源，
核对来源密封值、渲染成员哈希及别名，并确认可选封面之后的正文顺序。
本轮 EPUB／TXT 各两尺寸共八个串行原生进程通过，24 章原始内容逐字节一致，四组无重绘错误。
正文图片和云端批注下载在此测试中关闭，封面单独生成；不能据此宣称全部资源格式或真实整本书均已验收。

当前 156 组 Lua、433 项 Python 与静态检查通过。真实云端写后回读、多设备及实体 KO2 仍待验收，
不同单章与整书文件之间的自动精确位置交接不在本次已验证范围内。
