# 多章缓存续读与整书阅读验证

已修复多个单章缓存下的「阅读」选章：资料中的章节号与本机不同，不应覆盖本机尚未同步的章节。
原有缓存入口只检查书籍资料；新增回归在修复前实际失败。缓存与未缓存阅读现在共用以下优先顺序：

1. 本机待同步位置。
2. 最近一次本机阅读位置。
3. 书籍记录中的章节。
4. 未缓存准备流程中新取得的远端章节。

本机记录明确属于其他书籍或其他账号时忽略。账号比较使用阅读记录及数据库相同的内部标识，
不直接与登录编号比较；原有按账号保存、缺少嵌套归属字段的旧记录仍可使用。
优先匹配章节 UID，再匹配有效的章节序号。目标章节没有缓存时，联网且有 Web 授权会先准备目录并下载目标章节；书籍详情的「阅读已缓存章节」可手动打开现有缓存。离线、没有 Web 授权或手动打开缓存时，若已有明确目标却缺少该章，会先提示打开其他章节可能改变本机位置；取消不会打开文件或修改待同步记录。确认后使用「最近且优先前一章」规则。
目录完全缺失时，已保存的本机章节 UID 同样可触发联网准备；离线时直接按已缓存章节 UID 匹配本机记录，无法匹配才回到原有稳定排序。
整书缓存仍优先，同一 EPUB 由 KOReader 保存和恢复原生阅读位置。

书籍详情和首页续读均采用同一规则。若下载失败，可回到书籍详情选择「阅读已缓存章节」；该入口按现有缓存的章节和位置打开，不代表找回了缺失章节。两尺寸原生模拟覆盖详情与首页下载缺失目标、手动打开缓存、断网回退，以及新进程离线重开，见[验收记录](validation-assets/2026-11-17/missing-resume.json)。已有完整缓存、精确单章缓存和没有明确目标时不会为此额外下载；账号变化或页面关闭后旧的缓存入口失效。

真实账号另在两种模拟尺寸完成书架／详情入口的只读验收：隔离配置中放置一个合成旧缓存占位文件和指向真实续读章的本机记录，通过正常按钮下载真实目标正文；核对来源、原生翻页及全新进程离线重开，合成占位文件仍保留。该测试不是对真实旧缓存内容或首页入口的真实账号验收；首页与手动缓存入口由上述合成流程覆盖。云端位置前后相同，账号数据与授权写入均为零，临时配置已删除。早期两次验收因护栏拦截个人书籍的只读书架进度刷新而记为未通过；修正为仅允许本次书架实际存在的对应只读请求后重新通过，失败记录没有改写，见[脱敏记录](validation-assets/2026-11-17/missing-resume-owner.json)。

离线提示与取消在两种尺寸分别通过原生合成流程和真实账号隔离配置验证；真实账号验收中的旧缓存仍是合成占位，取消后核对待同步书籍／章节及占位文件，随后恢复联网可正常下载目标，独立云端位置不变。合成流程另核对取消后的章节序号、百分比及账号归属；账号切换、页面关闭、目标变化或缓存变化期间的旧弹窗回调也经过组件测试。见[验证记录](validation-assets/2026-11-17/resume-warning.json)及合成界面：[600×800](validation-assets/2026-11-17/resume-warning-600.png)、[KO2 尺寸](validation-assets/2026-11-17/resume-warning-ko2.png)。实体 KO2 仍待验收。

章节序号只有在当前目录中唯一时才用于选章。若待同步记录只提供了重复序号，则继续尝试最近本机记录、书籍记录和可用的云端章节；明确匹配的 UID 仍优先。同序号并不证明章节相同。无法从任何记录确定章节时，缓存阅读仍采用既有的进度估算或稳定回退，未缓存阅读仍从目录首章开始，不会将该回退认定为精确恢复。

两种模拟尺寸已在原生阅读器中用两个已缓存章节和重复目录序号验证：模糊的待同步序号不会遮盖最近本机章节，实际打开的文件及页面与本机记录一致；原有待同步优先、账号隔离、缺失目录与整书离线重开继续通过。单元检查也覆盖唯一序号、明确 UID 和云端章节回退；修复前的实现会在重复序号场景失败。测试使用合成数据，实体设备仍待验收，见[记录](validation-assets/2026-11-17/ambiguous-resume.json)。

## 单章与整书之间的原文位置交接

此前单章和整书是不同的 EPUB，切换后只恢复目标文件自己的位置；新增原生回归已复现这一缺口。
从插件「阅读」、缓存章节、下载完成后的「立即阅读」进入另一份同书文件时，现在尝试恢复最近的本机原文位置。
已经打开该书时，先异步采集当前页面，再切文件；从书架进入时，使用同账号的待同步／最近本机原文记录。
较新的本机记录缺少来源信息时，不复活更旧的原文位置。

仅当书籍、章节、原文摘要和坐标类型一致时才交接。允许同一原文在整书中的路径及文件标识不同，
也允许书籍版本变化但该章原文完全不变；XHTML 和 TXT 的坐标模型不能混用。
目标文件没有该章时按正常选章处理；同一个文件不覆盖 KOReader 的原生恢复。
有明确云端跳转回调时，仍优先执行用户已经选择的目标。

界面线程只读有限的来源元数据，原始字节核对仍由现有独立后台任务完成，再通过原生 DOM 定位。
切换准备期间翻页、换账号、休眠、关闭或发起新导航会使旧请求失效，旧回调不能再切文件。
新文件的启动保存及自动云端比较在交接期间暂缓；跳转失败且用户未移动时保留原来的本机记录。
跳转成功才保存当前文件位置并重绑已有待同步意图；不会因此创建上传授权或把本地原文坐标当作云端坐标。
若启用了打开时比较，成功后会进行一次新的普通比较，仍受原有确认及同步规则约束。

先通过实际下载得到第 2、4 章文件，在第 2 章真实翻页并关闭保存。
然后把书籍资料设为第 4 章，分别验证待同步位置优先、无待同步时最近本机位置优先，
以及其他账号明确指向第 4 章时仍使用本账号的第 2 章。每次都检查实际文件、页码及可见原生位置。
另清空合成账号的目录数据库及目录文件，验证直接按本机目标 UID 打开第 4 章缓存。

随后点击详情「下载整书」，确认真实下载六章，读取每章的原始来源，跳转至整书中第 4 章的原文目标。

## 旧章节缓存键的兼容

书籍详情的「阅读已缓存副本」现在能识别内存中以数字作为章节键的旧缓存，并按本机待同步的明确章节打开；章节下载列表也能正确显示此类缓存。标准保存的 JSON 对象会把键规范为字符串，已有字符串键及旧非数字字符串键继续按原值读取。数字回退仅用于可精确表示的章节编号，超过数值精度范围时不会将相邻章节混为同一键。

无目录续读在后台核对期间也采用同一匹配规则：若原精确键被移除，不能用取整后相邻数字键继续完成旧操作。组件测试覆盖误报缺章、旧数值键、相邻大编号和失效回调；两种 KOReader 模拟尺寸在书架详情注入合成的旧内存格式，验证直接打开正确章节并保留待同步位置。首次原生夹具尝试将数字键写入 JSON 后再读取，键被规范为字符串，因此没有验证目标情形；改为在界面取书边界注入后重测。该结果不代表发现了用户的旧格式数据，也不代表实体设备已验收。详见[脱敏记录](validation-assets/2026-11-19/numeric-cache-resume.json)。
