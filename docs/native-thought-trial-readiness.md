# 原生想法三步测试准备

原生多行编辑器、确认界面、后台服务和实际 SQLite 已接通新建私密测试想法、编辑该新记录、删除该新记录的限定执行器。
本批真实账号仅做零写入预演，尚未执行原生写后回读。此前 Python 实验的三次许可已使用，不能复用。

## 一次执行与逐步核对

执行前由独立 Python 两次读取完整书架标记、所选书的本人想法、划线及精确阅读位置，绑定所选划线引用、书籍版本和新随机测试文字。
准备记录保存在独立钥匙串条目，不含凭据、书名、正文、引用或请求体；没有准备记录或当前状态已变化时停止。
新测试仍需本人明确授权，运行参数不能代替授权。

获得新三步许可后，启动原生进程前一次性持久占用三次额度。
每次实际 POST 前，测试专用 SQLite 门槛会核对唯一操作、完整请求、非原有记录的目标，以及生产操作记录已经处于 `pending`。
实际请求由插件生产客户端、生产编辑服务和后台进程发送，Python 不代发账号修改。
原生页面完成一步后等待宿主独立读取；宿主确认唯一新增私密记录、准确文字和引用，以及原有想法、划线、书架标记和位置未变后，才放行下一步。
编辑和删除只能指向独立核对得到的同一条新记录。最终完整状态恢复后才完成并清理测试意图，再独立确认条目不存在。

三次额度在启动前全部占用：即使启动失败、实际未发请求或中途退出，也不能重新启动旧测试。
结果不明确或原状态变化立即停止，不重发、不自动续期、不自动删除可能留下的测试想法。
原有生产编辑器自身的一次提交和后续只读核对仍保留，见[想法编辑](thought-editing.md)。

## 真实账号零写入预演

KOReader v2026.07.1、Linux ARM64、1264×1680／300 DPI 的打包插件通过实际 FileManager 进入本人划线，

测试门槛在网络发送前拦截，实际账号数据 POST 为零；生成的完整请求与独立 Python 计划一致。
本地生产操作记录保留 `pending`，证明确实走到派发边界；由于测试门槛已证实未发送，随后删除整份隔离临时配置，不影响日常插件配置。
原生过程执行 9 次实际 GET，宿主本轮独立读取 23 次，前后完整原状态不变。

早期预检三次均在首个书架 GET 收到 401 后停止，没有准备意图或账号修改。
既有维护工具仅续期一次，独立核对同账号／书架并保存更新后的授权，随后准备和预演通过。
含失败预检、续期回读、准备及预演，本批真实请求共 48 GET、1 次授权 POST、零账号数据 POST。
测试意图仍为未占用额度的 `prepared`，授权继续按要求保存在本机钥匙串。

凭据经捕获的双向管道和匿名描述符进入原生进程；登录字段从设置保存中剥离，并检查有效凭据未进入临时文件。
