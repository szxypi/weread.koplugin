# 旧阅读记录保留与原生恢复

公众号「文章缓存与版本」提供「恢复阅读记录」。本项支持身份目录中的受管 HTML，
以及能由当前保存目录明确关联单一文章的旧标题 HTML／EPUB。
包括从文章列表、阅读缓存及已保存版本打开尚无独立版本标记的文件。
已有记录先保留到独立存储，再由用户明确选择，恢复到单独的正文副本。
启用插件时，文件管理器的常规 CRE 打开入口也已接入保护，限当前保存目录可唯一关联的文章。
阅读器内的原生历史选择与直接切书也已接入；目录／历史列表的信息预读及启动直接打开仍需单独完善。

## 使用方式

1. 打开「文章缓存与版本」，选择文章，再选择「恢复阅读记录」。
   打开需要保护的旧受管或标题 HTML／EPUB 时，也会先进入此流程；无记录且无恢复历史时保留直接阅读。
2. 原生列表显示可用的主记录、备份、随书记录、集中目录记录、历史兼容记录，以及当前关书前记录。
   每项显示保留时间、笔记和书签数量；确认框展示同一条划线的原文与附注预览，以及是否有保存位置。
   列表时间是保留时间，不能用它推断记录属于哪个正文版本。
3. 明确选择与这份正文相符的记录，再确认「恢复到新副本」。也可以选择「不恢复记录，打开新副本」。
   没有自动根据路径、标题或时间拆分共享记录；已经覆盖且没有保留副本的数据无法重建。
4. 新副本正文及其阅读记录完整保存、回读成功之后，才设为当前缓存并打开。
   原正文不覆盖，已保存快照不删除；正常刷新仍不复制旧坐标，恢复操作需要单独确认。

所有控件和正文都由 KOReader 原生模块绘制，不加载网页，也不请求微信读书。

## 数据保护与提交顺序

旧文件可能共用 KOReader 的抽样哈希。已复现：从哈希切换到随书保存后，
直接打开原文件可能带入另一份位置和笔记，关书时再清理共享主记录及备份。
早期[独立恢复原型](validation-assets/2026-11-09/mp-legacy-record-recovery-runtime.json)
验证了 42 次实际 ReaderUI 打开与独立进程回读；当前已接入产品流程。

- 在关闭旧菜单或进入事件循环前，读取并保留可用原始记录。
  同时通过阅读器的保存设置事件采集尚未关书的状态，避免定时保存或窗口关闭先移动旧记录。
- 快照按当前账号写入独立 SQLite，保持原始字节、摘要及来源，批量提交并核对回读。
  这是恢复快照的账号隔离，不改变 KOReader 本机记录原有的全局范围。
  新账号、切书、缓存移动或阅读会话变化不能沿用旧操作的结果。
- 每篇最多 128 份快照、合计 32 MiB，每份最多 4 MiB。超过容量停止，不截断、不覆盖旧记录。
  快照集合不进入小型配置；原记录和正文不因取消被删除。
- 恢复只接受有界的 Lua 数据字面量，不执行旧记录中的 Lua 代码；限制节点与嵌套深度，
  核对关键批注字段。无法解析的快照保留但禁用恢复，可以选择其他记录或不应用记录。
- 正文复制和记录列表解析在后台执行。受管 HTML 副本保持正文及相对资源引用，只替换头部版本标记；
  原路径保持，恢复副本重建引擎缓存与文档摘要，避免继续共用旧记录。
- 正文完整发布为未选中的版本，再保存和回读新位置的记录，最后提交当前版本选择。
  记录保存失败时清理本次未选中的正文；如果选择记录的提交状态无法确认，
  保留可能被使用的完整正文及归属记录，提示重新核对当前版本，不冒险删除它。
- 取消后台复制时，先终止并回收子进程，再清理本次暂存。保留的快照继续可用。
  这些检查不等同于任意外部进程并发修改、整机断电或所有文件系统的事务保证。

## 旧标题 HTML 与图片

旧标题文件依据当前保存的文章目录核对归属；同名歧义、目录被移除、标题或源文件变化时停止。
第一次恢复可以建立文章身份目录；其他文章建立公共容器不影响本篇，
本篇已有正文、选择记录或父目录被替换则不能沿用旧操作。

在选择记录前保存原始快照。确认后只改头部身份标记及图片 `src` 的值，
不重排正文节点、文字、空白或属性引号。没有显式 `<head>` 的旧 `<html><body>` 可补入头部，
正文位置和批注仍需通过实际阅读器回读核对。
原 HTML 及旧图片不移动、不重写，恢复版本拥有独立图片代次：

- 接受原缓存目录中标准 `.weread-mp-…-assets/img-数字.扩展名` 引用，包括前导 `./`。
  PNG、JPEG、GIF、WebP 逐块复制，重复引用只复制一份；不重新请求图片。
- 源目录／文件身份在准备、复制前后及发布前再次核对。符号链接、越界路径、不可确认的读取错误停止。
  已缺失图片指向新代次中独立的缺失路径，不会误读另一篇旧图片。
- 内嵌 `data:image/`、远程 URL 和锚点保留原值，复制过程不联网。
  这不代表远程图片已离线保存。外链 CSS、`base`、图片 `srcset` 及样式块中的 `url()` 会拒绝；
  CSS 背景、字体、SVG／AVIF 和其他资源类型不属于本次资源迁移支持范围。
- 复制正文上限 4 MiB；本地图片每份 32 MiB、总计 64 MiB；本地唯一引用（含缺图）最多 256 项。
  超限不截断。没有任何记录的普通旧标题阅读不需要复制或资源解析，仍可直接打开更大的原文件。

这里只实现旧插件缓存的标准图片迁移，不是任意 HTML 导入器。
恢复失败或取消保留原正文、原图片和已保存的记录快照；选择记录的提交状态不明时，
完整恢复正文及其图片一起保留，避免产生指向缺失图片的当前版本。

## 旧 EPUB 与受管 EPUB

旧标题 EPUB 使用相同的目录归属、记录快照、原生选择及最后提交当前版本的流程。
恢复副本继续是 EPUB：不转换成 HTML，不改 OPF、章节顺序、正文节点、样式或资源路径。
已恢复的 EPUB 可直接阅读，也可以明确选择另一份记录再次恢复到新副本。

- 在第二个本地 ZIP 文件头加入私有记录标识，使标识位于 KOReader 的第一个哈希抽样块。
  `mimetype` 仍是第一个、不压缩且没有额外字段的成员。
  仅调整必要的 ZIP 字段和目录偏移；所有原有成员名称、解压内容、压缩数据、中央目录属性及 ZIP 注释保持。
  再次恢复已有副本时替换本插件的同一文章标识，不叠加字段；冲突或不属于该文章的标识会拒绝。
- 后台独立打开压缩包，核对中央目录与各本地头，完整读取成员并验证 CRC。
  原包 SHA-256 在准备及复制前后核对，源路径、大小、文件身份变化不能沿用旧结果。
  复制按 64 KiB 分块进行，不将整本 EPUB 读入 Lua 字符串，不解压到磁盘，不联网。
- 支持单卷 ZIP 的 stored／deflate 成员及空目录；拒绝重复名称、链接、越界路径、加密 ZIP、
  ZIP64、头部／目录不一致和无法确认的读取错误。
  原包最多 72 MiB、4,096 个成员、4 MiB 中央目录；单成员解压最多 64 MiB、合计 128 MiB。
  这些是本项的格式和资源边界，不是完整 EPUB 合规、DRM 或所有字体格式的验证。
- EPUB 为自包含版本，不依赖外部图片代次。版本列表、当前选择、清理与中断检查识别受管 EPUB；
  当前／打开版本仍受保护，清理空图片代次不会删除包内资源。
  后续正常刷新可以另存 HTML，保留 EPUB 及其记录，不将 EPUB 坐标应用到新正文。

ZIP 头部约束参照 [W3C EPUB OCF ZIP 容器](https://www.w3.org/TR/epub-33/#sec-zip-container)，
独立读取使用 KOReader 自带的 [libarchive ZIP 接口](https://github.com/libarchive/libarchive/blob/v3.7.9/libarchive/archive.h)。
本项不改变 KOReader 的全局哈希算法或记录保存偏好。

## 从文件管理器打开

插件在实际文件管理器实例中接入其文档打开方法，不修改 KOReader 核心文件或启动脚本。
根据轻量书籍索引先匹配缓存目录，仅加载目标公众号的已保存文章目录，再核对准确路径与文章身份。
同名歧义、已识别来源的文件／目录变化或无法确认的受管身份会停止，不根据显示标题猜测记录归属。
没有索引或目录证据的旧文件不能推断归属，仍属于后续需要完善的范围。

- 对需要保护的文章，在查询原生阅读引擎之前持久保存当时可用的原始记录。
  原生引擎查询本身可能读取 DocSettings，不能等到阅读器创建后才保留快照。
  只有用户明确选择并确认后，才创建副本并进入原生阅读器；取消时保留文件管理器。
- 新副本使用为原文章选定的阅读引擎，避免所选旧记录里的另一份打开方式改变交接目标。
  明确指定的引擎、文档打开前回调、打开后回调以及参数中的空位继续传递。
  辅助编辑器维持原生路径，不进入记录选择；普通本地文件及已独立的版本仍直接打开。
- 恢复操作同时绑定文件管理器实例、插件实例和本次打开请求。
  关闭／替换文件管理器、另一份打开请求、账号／来源变化及插件停用后，旧确认或后台结果不能发布或打开。
  休眠及关闭继续取消并回收实际子进程，再清理本次暂存。
- 列表绘制、书籍信息预览等可能更早读取或迁移记录；本入口不宣称拦截这些行为。
  启动直接打开最近文件、未识别的旧文件和 KOReader 的独立元数据归档仍待补齐。

两尺寸各 12 项原生场景、3 份恢复副本，首进程 14 次 ReaderUI 打开、新进程 3 次，

无记录文章、普通文件、辅助编辑器、来源变化、同名歧义、旧确认、暂停检查及新进程回读均通过。

## 阅读器历史与直接切书

启用插件时，原生阅读历史选择文件会先保留可用原始记录，再允许原生代码查询打开方式。
实际切书在关闭当前 ReaderUI 之前进入现有记录选择／确认流程；完整副本与记录保存后才关闭原书并交接。
直接调用原生 `switchDocument` 的普通打开入口也受保护，不改变 KOReader 核心文件或启动脚本。

- 如当前书与目标共用旧哈希，先保存已有原始候选，再采集当前尚未关闭的笔记及位置；
  原生保存或引擎查询可能移动共享记录，不能等到目标阅读器创建之后再保存。
- 保留“打开前询问”设置。对需保护的旧文件，询问前已保存记录，确认时再次核对来源；
  取消、来源变化或旧确认都不能切书。取消记录确认也保留当前阅读器。
- 保留所选原生引擎、显式强制状态、无缝交接参数和打开后回调；参数空位不被截断。
  普通本地文件、已有独立标记的版本及辅助阅读方式继续走原生路径。
- 操作绑定当前阅读器、文档、账号、阅读会话和请求。关闭、替换、休眠或换账号后不能沿用旧结果。
  恢复流程自己关闭插件窗口时不会误取消本次操作，迟到结果也不能清理新的窗口。
- 历史菜单与直接切书之间有两层适配：前者在引擎查询之前保护原始记录，后者在实际关书之前保护交接。
  列表绘制或其他插件的信息预读仍需独立处理，不宣称统一拦截所有 DocSettings 读取。
