# 旧阅读记录保留与原生恢复

公众号「文章缓存与版本」新增「恢复阅读记录」。本项支持身份目录中的受管 HTML，
包括从文章列表、阅读缓存及已保存版本打开尚无独立版本标记的文件。
已有记录先保留到独立存储，再由用户明确选择，恢复到单独的正文副本。
旧标题缓存、旧 EPUB 和直接从 KOReader 文件管理器打开的情形仍不在这些保护入口内。

## 使用方式

1. 打开「文章缓存与版本」，选择文章，再选择「恢复阅读记录」。
   打开需要保护的旧受管 HTML 时，也会先进入此流程；无记录且无恢复历史时保留直接阅读。
2. 原生列表显示可用的主记录、备份、随书记录、集中目录记录、历史兼容记录，以及当前关书前记录。
   每项显示保留时间、笔记和书签数量；确认框展示同一条划线的原文与附注预览，以及是否有保存位置。
   列表时间是保留时间，不能用它推断记录属于哪个正文版本。
3. 明确选择与这份正文相符的记录，再确认「恢复到新副本」。也可以选择「不恢复记录，打开新副本」。
   没有自动根据路径、标题或时间拆分共享记录；已经覆盖且没有保留副本的数据无法重建。
4. 新副本正文及其阅读记录完整保存、回读成功之后，才设为当前缓存并打开。
   原 HTML 不覆盖，已保存快照不删除；正常刷新仍不复制旧坐标，恢复操作需要单独确认。

所有控件和正文都由 KOReader 原生模块绘制，不加载网页，也不请求微信读书。

## 数据保护与提交顺序

旧文件可能共用 KOReader 的抽样哈希。已复现：从哈希切换到随书保存后，
直接打开原文件可能带入另一份位置和笔记，关书时再清理共享主记录及备份。
早期[独立恢复原型](validation-assets/2026-11-09/mp-legacy-record-recovery-runtime.json)
验证了 42 次实际 ReaderUI 打开与独立进程回读；当前已接入产品流程。

- 在关闭旧菜单或进入事件循环前，读取并保留可用原始记录。
  同时通过阅读器的保存设置事件采集尚未关书的状态，避免定时保存或窗口关闭先移动旧记录。
- 快照按当前账号写入独立 SQLite，保持原始字节、摘要及来源，批量提交并核对回读。
  这是恢复快照的账号隔离，不改变 KOReader 本机记录原有的全局范围。
  新账号、切书、缓存移动或阅读会话变化不能沿用旧操作的结果。
- 每篇最多 128 份快照、合计 32 MiB，每份最多 4 MiB。超过容量停止，不截断、不覆盖旧记录。
  快照集合不进入小型配置；原记录和正文不因取消被删除。
- 恢复只接受有界的 Lua 数据字面量，不执行旧记录中的 Lua 代码；限制节点与嵌套深度，
  核对关键批注字段。无法解析的快照保留但禁用恢复，可以选择其他记录或不应用记录。
- 正文复制和记录列表解析在后台执行。新副本保持正文及相对资源引用，只替换头部版本标记；
  原路径保持，恢复副本重建引擎缓存与文档摘要，避免继续共用旧记录。
- 正文完整发布为未选中的版本，再保存和回读新位置的记录，最后提交当前版本选择。
  记录保存失败时清理本次未选中的正文；如果选择记录的提交状态无法确认，
  保留可能被使用的完整正文及归属记录，提示重新核对当前版本，不冒险删除它。
- 取消后台复制时，先终止并回收子进程，再清理本次暂存。保留的快照继续可用。
  这些检查不等同于任意外部进程并发修改、整机断电或所有文件系统的事务保证。

## 验证范围

默认合成配置，不读取日常账号、钥匙串或真实笔记。
原生验证调用实际文章入口、保存版本菜单、记录选择和确认框，使用真实 SQLite、后台子进程及 ReaderUI。
覆盖哈希主记录／备份、随书和集中目录记录、关书前状态、三种保存位置的独立副本、
无记录副本、保存失败、选择记录已提交但回读失败、活跃检查／复制子进程取消、账号变化及大列表。
每次关闭后重新读取磁盘配置，确认公众号容器进度和待上传状态保留。

测试使用 600×800／167 DPI 与 1264×1680／300 DPI。每种尺寸 13 个原生场景、8 份恢复副本，
实际 ReaderUI 打开 32 次，再由全新进程打开 8 次，两尺寸合计 16 份副本／80 次打开。
另使用 KOReader 自带切书与异步打开流程各完成一次真正的自动交接，验证新阅读器加载了所选记录。
原型手工建立副本与本次原生选择／提交／打开的证据分开记录。

## 重现

仅接受尚不存在的运行目录，创建全新的合成配置，不复用日常 KOReader 设置：

```sh
xvfb-run -a python3 scripts/test_mp_metadata_runtime.py --record-recovery \
  --koreader /path/to/runtime --run-dir /path/to/new-run \
  --width 1264 --height 1680 --dpi 300
```

不传模式参数时仍验证正常保存方式切换；传 `--legacy-shared` 则执行早期共享记录丢失对照与恢复原型。
这些模式互斥，均使用合成正文和笔记。
