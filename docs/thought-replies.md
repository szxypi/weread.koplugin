# 阅读中的想法回复

阅读时点击微信读书划线，长按弹窗中的一条想法，选择「查看回复」。列表可打开完整回复并继续加载；需要当前账号的墨水屏授权和网络。居中及底部两种想法弹窗均提示长按入口。此功能只读取公开回复，不发布或修改回复。

插件先在后台读取本机已保存的章节来源，核对当前书籍、章节、划线范围，以及弹窗中所有想法的顺序和展示内容；再核对选中想法的内外编号、所属书章、类型与公开状态。只有匹配成功，才按该编号读取回复，并再次核对服务端返回的书籍、想法及每条回复归属。关闭想法弹窗、切换阅读文档或账号、取消任务和授权变化都会阻止旧结果显示。

无需改变已有数据库结构或预先重写缓存；来源数据完整且与弹窗一致的旧缓存可直接使用。来源缺失、记录变化或无法确认归属时会保留原想法并提示刷新本章后重试，不能保证刷新一定使所有旧数据可关联。回复最多显示 200 条；服务端未返回足够数据时提示可能不完整。分页和授权恢复沿用[书评回复](book-reviews.md)的读取流程。

## 验证范围

两种屏幕尺寸、居中和底部弹窗共四组 KOReader 模拟场景使用合成数据：从 SQLite 中读取不含想法编号的旧式展示缓存，在后台重新核对保存的来源，长按选中想法并显示回复；关闭弹窗后子页面和任务一并清理。600×800 的两种弹窗布局另用合成截图检查，个人数据没有截图。

真实账号只读获取一章的 96 条公开想法，确认其书籍、章节和内外想法编号；其中一条想法有一条回复。在 KOReader 原生弹窗和覆盖层入口中，用内存模拟阅读器上下文和章节缓存，后台核对该想法并通过实际 HTTPS 读取回复，与独立读取逐项一致。独立核对包含六次只读请求，其中目录和想法查询使用只读 POST；原生界面另发一次回复 GET。没有账号数据写入、真实内容文件或真实截图。该次只覆盖一章和一条有回复的想法，不代表已经在真实 ReaderUI、所有书籍或实体 Kindle 上验收。

`scripts/verify_thought_replies.py` 默认离线；显式使用保存的会话和私有进程时，真实数据仅通过内存管道比较。
