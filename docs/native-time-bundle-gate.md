# 新采集记录的单次发送保护

新的跨日采集包含原 EPUB、账本和覆盖数据库。为未来的原生界面验收新增独立单次发送保护，当前组件**没有网络发送能力**，也没有接入真实账号的发送流程。

保护逻辑要求先由调用方完成新鲜的双通道只读预检，再核对当前会话和完整采集是否仍与预检一致。原生选择器必须返回同一文件、版本、时区、所有原账本行及其准确时间片；选区确认后、请求领取前再次核对，不能仅比较总秒数。请求体使用独立实现重新计算并比较，包括原始小时归属、设备、版本、随机数和签名；布尔值不能冒充数字，原文位置字段和额外字段不能混入。

领取前后再次检查本地采集和会话；领取状态先持久保存，调用方才可能将许可交给原生请求。时间戳及北京时间自然日会在持久领取前再次核对。领取后的错误或中断不会释放这次机会；记录已有领取时，重新启动也不能领取同一范围。若会话在领取后失效，保护逻辑拒绝交出许可，但仍保留已领取状态。

明确的响应只能记录为“收到回执”，不能等同于服务端入账；本阶段没有实现将该记录标为入账成功的方法。真正的验收还须接入实际原生菜单和严格限域的传输通道，在发送前独立取得签名所需数据，核对真实 HTTP 回执，并经两轮独立稳定回读确认原日期、当前日期、逐书计数和两端位置等状态。不能用合成结果或单次回执替代这些步骤。

合成验证已将 KOReader 原生队列选区及签名请求交给此保护，测试领取、回执记录、新进程重开及拒绝重领；同时测试了两进程竞争、持久保存后报错、选区／签名／会话变化和领取前时钟变化。本机钥匙串另用独立合成范围完成跨进程回读并清理，不影响真实采集或真实发送范围。[合成结果](validation-assets/2026-11-18/native-time-bundle-supervisor.json)不含真实账号数据。

真实采集在北京时间 2026 年 11 月 19 日 00:00:01 前由实际时钟阻止进入历史发送范围；未安排自动发送。实体 Kindle、真实入账与断电恢复仍待验收。

另以无网络的合成原生子进程，经过实际进程间消息传递执行五种情况：正常选区与签名、选区被修改、请求体被修改、领取后子进程中断、重复请求领取。请求体不匹配时，在预检阶段拒绝且不占用发送机会；保护逻辑先保存领取再回复，后两种情况均保留已领取状态，重开不能再次领取。许可交出前还会再次核对领取记录、请求和实际时钟；若此时请求已过期，记录仍保持已领取。[进程间合成结果](validation-assets/2026-11-18/native-time-bundle-rpc.json)不涉及真实账号或网络。

## 实际原生菜单的合成预演

在 600×800 与 Oasis 2 对应的 1264×1680／300 DPI 模拟屏幕上，实际 KOReader ReaderUI 经“离线阅读时长 → 检查本机时段 → 补传此批时长”进入后台子进程，由隔离测试桥接到单次保护。八种合成场景覆盖正常确认、选区或请求体被修改、响应丢失、无明确回执、后台进程退出、重复领取，以及回执已保存但账目未变化时的只读复查。成功场景核对了原生账本保留的两次回读审计；不明确场景核对了界面提示和待核状态，只读复查没有再次发送。

测试使用真实 SQLite 和归档校验，但远端正文、统计、回执、账号及预检均为合成数据；网络连接被阻止。两尺寸测试完成后，临时资料和工作进程均已清除。[合成界面结果](validation-assets/2026-11-18/native-time-bundle-ui-rpc.json)不代表 Kindle 真机或真实入账。桥接仍属于隔离验收工具，真实账号的受限传输和独立回读尚未接入。

另准备了只读签名输入读取器：必须先通过新采集的完整跨日预检，且预检完成未超过 30 秒；账号、设备、采集范围和未使用的发送记录在读取前后均须保持。它只允许各一次固定的配置及特性读取，不续期、不发送，也不将读取到的密钥写入报告。真实采集因尚未跨日，在任何网络读取之前已被拦截。

## 独立账目核对

新增独立的只读核对逻辑：发送前的基线与完整采集、账号和设备绑定，并可保存在独立钥匙串范围中；发送后要求三份稳定的独立观察，原日期和逐书阅读时长必须恰好增加采集秒数，其他统计、位置、书架和来源保持一致。只有原来为零的统计日期允许消失；同设备续期后可继续只读核对。回执和这些比较结果本身都不能证明真实入账，观察还需要由受限的真实读取流程提供并验证来源。

该基线存储和核对逻辑**尚未接入真实发送流程**，也不能自行发送、领取或更改成功状态。合成测试包含跨月、其他计数变化、统计延迟和零值日期消失，并与原生核对规则交叉验证；[测试结果](validation-assets/2026-11-18/native-time-bundle-accounting.json)不包含真实账号数据。

隔离保护流程现已将基线保存排在领取之前：先保留待处理范围，完整保存并回读基线，再领取；交出许可前再次核对基线和领取记录。保存失败、记录变化、会话失效或预检过期时不会交出许可，已写入的记录保留以防重发。两尺寸原生菜单的八种合成场景已复测这一顺序；保存前失败、保存后报错和领取后记录变化另经单元测试。预检数据的真实来源验证和真实传输仍需接入，合成桥接不能用于实际账号发送。

只读预检现可在内存中交付本次两轮检查所使用的基线和统计，绑定采集、账号、设备和完成时间；普通命令行报告不输出这些私密内容。签名输入读取、基线保存及领取前后均检查同一份证据，任何变动都拒绝继续；预检跨越自然日、月份或时钟回退时也会停止。合成链路已从受限预检走到基线保存与领取，但真实传输及发送后的独立回读仍未接入，不能据此声称真实入账。
