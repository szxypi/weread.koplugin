# 阅读过程中的定时位置同步

入口：微信读书插件设置 → 进度管理 → 定时同步进度。
默认关闭，可选择每 1、5、10、15、30、60 分钟。配置范围为整数 1–60 分钟，其他值按关闭处理。
开启后仍须先手动同步一次，或通过“打开时拉取进度”完成位置核对；不会自行开启其他同步或时长设置。

当前支持有原文来源记录的普通 XHTML 书籍。只有已核对会话中的位置发生变化才安排截止时间，
没有新进度时不保留定时任务，不发请求；翻页期间短暂重新采集来源点不会不断推迟原截止。
暂停、无可用来源、关书、重开、账号变化、手动定位／重新比较及关闭设置会撤销旧任务。
休眠后沿用原同步会话核对门槛，不补发错过的多个周期；断网时保存本机意图，不唤醒 Wi-Fi。

到期先读取当前云端位置，与最近一次核对或明确写后回读的章节 UID／序号／偏移比较：

- 云端已经与当前本机来源点相同：清除对应待同步意图，不重复上传。
- 云端仍是上次观察的位置：复用 `SourceUpload` 核对当前原生视口、归档和远端原文，再发送一次零时长位置更新。
- 云端已变化或两个来源不一致：打开正常的位置选择窗口，不静默覆盖或跳转；即使旧配置 `ask_on_conflict=false` 也须选择。
- 核对失败：保留本机意图并撤销本次自动发送权限，等待后续同步重新比较。

前置 Web 进度读取明确返回 HTTP 401 时，可复用一次已核对的同登录续期，随后重新读取两个进度通道。
翻页、超时或关闭定时设置取消旧比较；存在进度发送待确认记录时拒绝恢复，不重发已可能发送的位置。
入口和验证边界见[进度登录恢复](source-authentication-recovery.md#进度拉取阶段)。

正常位置上传及周期时长的明确坐标回读都会更新“已知云端位置”，避免把插件自己的写入当作外部变化。
周期结果只更新该云端基线，不清除报告期间发生的新翻页意图，临时摘要不进入位置检查点。
这只是当次观察后的冲突保护，不是服务端原子条件写入；比对与发送之间其他设备仍可能改变云端，
不能据此宣称多设备并发协调已经完成。

位置更新仍为零时长，阅读时长开关保持独立；报告任务正在准备或发送时，本轮推迟而不争用准备器。
第一次可能发送前保存每书待确认记录，明确回执后独立位置回读一致才自动清除。
结果不明时提示保留本机进度、停止自动重发，显式重新比较后再恢复；设置变化不能抹去已可能发送的记录。
关闭设置会取消正在进行的未发送准备，迟到计划无法派发。相关机制见[关书与发送记录](source-position-prototype.md#正常同步的原文发送适配)。

验证使用官方 KOReader v2026.07.1 Linux ARM64／Xvfb，600×800 和 1264×1680 分辨率模拟。
实际原生菜单、翻页、来源工作进程、取消／回收、位置请求、独立回读及持久化均走真实插件代码；
定时器时钟受测试控制，没有为每个用例实际等待一分钟，也不代表真机调度或耗电验收。
连续翻页保持截止、提前回调零 HTTP、云端一字变化进入选择、未知回执不重发和只读比较恢复均已验证。
关书、周期报告、离线重开、双向重连选择、跨章／跨文件定位继续回归。
固定字段、包字节及代码哈希见[定时同步证据](validation-assets/2026-11-10/progress-interval.json)。
