# 进度与原文来源核对的登录恢复

正常阅读的位置准备和关书后的独立来源准备现支持一次 Web 登录恢复。
只有固定来源读取任务得到明确的数值 HTTP 401，且账号与任务仍有效，才向主进程申请恢复。
403、429、其他状态、业务响应错误、重定向、超量响应及仅含“401”字样的异常均不会触发续期。
子进程只返回固定错误码，不返回或采用其登录凭据。

主进程复用已有的 `web_renewal` 发送意图／回执／保存机制：

- 固定续期及账号／书架核对仍使用此前验证过的协议，不增加来源任务内的续期路径。
- 只接收本次服务核对成功的同账号、同登录代次回执，并与内存及主登录文件重新核对；官方密钥也须保持原值。
- 所选书已有进度发送待确认记录时，不开始凭据恢复。
- 取消、翻页、换账号／登录代次或任务替换撤销旧恢复；回执不明确时保留既有持久记录，重建服务也不再次 POST。
- 成功后从头重新打开归档、准备当前来源候选并读取远端原文；不复用续期前的归档／来源回执。
- 续期失败或重新核对仍为 401 时停止本会话的自动报告，提示检查登录并重新同步；不会循环续期。

普通发送准备仍受原有三十五秒准备窗口及三十秒来源回执约束。
关书重试只使用冻结的文件／来源元数据，整体三十五秒窗口不延长；每次工作请求有独立序号，旧结果不能代替新核对。
它不读取已经关闭的原生文档，也不会把旧来源位置转成估算偏移。
新凭据只用于本次尚未发送的读取准备，正常位置发送仍须通过自己的当前计划和发送记录；
不会重放已可能发出的进度、时长或其他账号数据写入。

固定协议的此前实际证据见 [Web 登录续期](web-authorization-renewal.md)、
[实际原生续期](validation-assets/2026-11-09/web-renewal-native-owner.json)及
[来源字节核对](validation-assets/2026-11-10/source-currentness.json)。
这些既有验证不能代替本次来源自然失效组合的真实账号验收。

本轮使用官方 KOReader v2026.07.1 Linux ARM64／Xvfb，两尺寸模拟服务验证：

- 401 后一次父进程续期，随后观察到新的归档／来源工作进程并取得新计划，准备本身不写阅读位置。
- 403／429 不续期；第二次 401 停止自动报告；进度发送待确认时拒绝续期。
- 不明确续期回执保留，重建服务不重发；原生翻页取消和工作进程回收通过。
- 合成的同账号新登录更改登录代次，旧记录不能授权新会话；随后只读比较恢复原位置会话。
- 实际关闭正文后遇到 401，完成一次续期、重新准备、一次零时长位置更新与独立回读，全程不触碰已关闭文档。

固定字段、代码及包字节见[来源恢复证据](validation-assets/2026-11-10/source-recovery.json)。

## 进度拉取阶段

打开书籍、手动同步及定时位置核对现已接入同一恢复服务。复用已验证的有界进度读取，
固定本次 Web Cookie 与官方密钥，不保存读取响应中的 Cookie；HTTP 401 以固定返回标记传递，
不从异常文本猜测登录状态。仅配置官方通道的旧读取方式保持可用。

Web 返回明确 401 时，即使官方通道先取得位置，也不直接采用该旧比较结果。
先保存当前本机意图，在同账号／登录代次及同一原生视口内最多续期一次，再通过正常在线任务重新读取两个通道。
恢复后的读取还须与已核对回执产生的访问修订一致。续期失败或第二次 401 保留本机进度，
撤销自动报告门槛并提示重新检查登录；403／429 和普通传输失败不触发续期。

恢复窗口为三十五秒。翻页、关书、休眠、换账号、任务替换及关闭定时同步都会撤销对应消费者，
取消它所拥有的续期并回收工作进程；已可能发出的持久续期记录仍按既有规则保留。
翻页监听直接读取正文引擎的位置，避免 KOReader 尚未更新的缓存位置使旧比较晚一步取消。
所选书有进度发送待确认记录时仍拒绝续期，可通过后续明确的只读比较恢复。
本路径只处理发送前的进度读取，不改变位置 POST 之后的回读策略，不续期或重放已可能发送的位置／时长。

两尺寸原生模拟已覆盖打开／手动／定时三种入口、无官方密钥、两个通道重新读取、
403／429、第二次 401、待确认进度阻止续期及只读恢复、不明确续期回执与服务重建防重放、
原生翻页立即取消和工作进程回收。上述前置恢复用例没有发送阅读位置数据。
固定字段、候选包及代码哈希见[进度拉取恢复证据](validation-assets/2026-11-10/progress-fetch-recovery.json)。

## 保存失败与回执接续

进度拉取、原文来源准备、定时核对及关书独立准备均已通过保存失败组合验证。
续期完成核对后，如果回执文件、主登录文件或完成标记的同步确认失败，会停在原生「只重试保存」提示；
当前消费者不提前继续。重试保存不会再次发送续期 POST，成功后才重新比较或准备来源。
期间更新的本机设置和原生阅读位置保留；完成标记移除状态文件中的凭据副本。

修复了取消后重建服务的一处门槛：主文件已经写入新凭据、内存还保留旧修订时，
消费者现在固定内存中的同账号／登录代次，交由原有续期服务核对持久回执与主文件。
服务只允许已核对回执所描述的旧／新修订接续，并重新只读核对，不再次 POST；
未知的第三种主文件修订不会被采用、覆盖或续期。最终成功仍须重新核对内存和主文件。

取消保存提示保留已核对回执及本机待同步意图。翻页、关闭定时设置或恢复窗口超时会撤销提示与旧消费者，
迟到按钮不能恢复旧任务。实际关书后的重试先完成凭据保存，再独立准备和更新位置，不访问已关闭文档。

两尺寸各覆盖七组保存重试、取消后重建、未知主修订拒绝、三个撤销入口及关书重试。
测试注入的是同步函数失败返回，不是真实断电或磁盘损坏；全部网络为本地模拟服务。
