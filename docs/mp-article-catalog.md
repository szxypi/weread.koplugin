# 公众号文章目录后台读取

原先打开／刷新公众号目录会在界面线程读取网络、解析 JSON；验证失败后还会自动续期并重读。
真实两个目录此前均返回 `-2041`，一次已验证续期也未解决该错误。
现将既有首批读取移至后台，每次用户刷新只发一个 GET，不自动续期或重放。
本次是既有读取流程的交互与缓存保护改造，没有把真实公众号目录、分页、订阅或链接导入标成完成。
Web 授权续期及确认回执后单次恢复读取的原生协调仍待完善；后台读取不代替这项能力。

## 原生行为

- 已保存的普通目录和有效空目录都直接在原生菜单打开，不因打开列表而联网。
  刷新前仅检查网络连接状态；离线时现有列表保持，不在界面线程做 DNS 或网络请求。
- 提示支持点击／按键取消；关页、关书、新阅读器、休眠或新刷新取消旧任务。
  账号、Cookie／附加头、阅读会话、目录设置或该公众号缓存目录变化后，旧结果不能保存或重新打开菜单。
- 请求失败、验证不可用、异常数据或超限时，保留目录记录，重新显示已保存列表并给出固定提示。
  `-2041` 保留准确的验证不可用提示；登录错误沿用登录引导，不以循环续期或扫码重放处理。
  HTTP 429 只返回保存的目录，不自动重试。错误响应、正文、查询和底层异常不进入日志或提示。
- 有效空数组会更新为空目录并显示「没有文章」，离线重开仍可看到空目录及刷新入口。
  这不会删除已下载 HTML、图片、EPUB 或原 sidecar。
- 本次只读取 `maxIdx=0&count=100`，满 100 篇时显示「已加载前 100 篇文章」。
  不推测后续游标，不声称取得全部历史文章；真实分页仍待验证。
- 保存时重新读取最新书籍记录，只合并目录及更新时间，保留网络读取期间更新的进度和待上传意图。
  继续使用原有每书 `articles.json`，不把文章集合放入小型配置文件。
  存储异常给出独立提示，并读取仍可用的保存记录；不宣称现有多文件书籍存储具备整体回滚事务。

## 读取与验证边界

`weread/lib/mp_catalog.lua` 使用已由 `scripts/verify_mp_catalog.py` 及原生 HTTPS 验证的固定 GET。
捕获同账号 Web Cookie 和附加头，只发送至固定微信读书域名；不发送 Skill／墨水屏 Bearer 凭据，
不保存子进程响应 Cookie，不跟随跳转，不执行续期 POST。
源码复用已验证的首批目录／嵌套文章字段，本轮没有对已知 `-2041` 再做无变化的真实重试。

响应限 4 MiB，管道结果限 2 MiB，最多 100 个分组／文章。
仅保存有稳定编号的展示字段、候选编号和既有来源元数据；关联书籍字段不作为服务端所有权证明。
校验数组连续性、编号、UTF-8、字符串和时间范围；缺失目录、空对象、错误形状或超限均不能冒充成功空目录。
JSON 解码器提供数组标记时，明确区分服务端空数组与空对象；固定运行环境已验证该区分。
子进程和父进程均校验保存字段，未知响应字段不进入保存记录。

真实成功目录及所有字段／备用编号的语义仍待取得可验证响应；
新成功、空目录及 100 篇场景均为合成数据。来源链接不被自动读取，公开源的验证跳转结论不变。
旧标题缓存的关联与 sidecar 协调、单篇刷新入口、文章代次清理另列为待完成项。
