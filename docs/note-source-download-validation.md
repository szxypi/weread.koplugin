# 缺章下载后定位引用

已补齐数字 EPUB 的真实组合验收：从「我的云端划线」或「我的云端想法」打开原文，缓存缺失时确认下载目标章节，下载完成后核对来源并进入原生阅读器。
本批不修改生产逻辑，补充了之前缺少的实际接口与正常下载器组合验证。

## 场景与结果

划线和想法各选择最多 3 条、同一章节的明确引用，在 600×800 和 KO2 尺寸 1264×1680、300 DPI 各运行一次。
每份配置最初没有该书的章节／整书缓存；第一次取消下载确认，HTTP 计数仍为零；再次明确确认后，走正常后台目录准备和下载器。
对应章的目录、正文及样式全部通过实际 HTTPS 读取，不以父进程预取的正文代替插件下载。
父进程预先两次读取的正文只用于独立目标和字节摘要对照。

每个实际配置下载 1 章、8 次读取（3 GET、1 次目录 POST、4 次正文／样式 POST），所有回包 HTTP 200。
随后 3 次原生定位的目标均在当前视口，原始范围没有直接作为阅读进度。
全新离线进程从实际下载的单章缓存逆序定位 3 次，零请求。四份配置共 4 次章节下载、24 次定位。
对应书籍的全部原有标记或想法，以及原生与 Web 两通道的精确阅读位置独立核对不变。
划线只选择原 52 条中的 3 条，不据此宣称 52 条均走了缺章下载；想法选择所选书全部 3 条。

## 只读与凭证边界

确认前的后台读取被禁止；允许的地址仅限已选书籍的阅读页、目录，以及已选章节的 `e_0` 至 `e_3`。
请求中的编码书号、章节、字段集、来源页、账号 Cookie、调用进程和次数均检查。
未知 URL、其他账号／书／章、资源请求、授权维护、原生 API 以及所有账号数据修改均被拒绝，不允许 UI 主进程联网。
为避免诊断输出私密响应，测试入口统一设置敏感请求标志，没有伪造响应、成功回执或正文。

登录信息只经捕获管道和匿名描述符，实际缓存及阅读记录只存隔离 tmpfs，安装和文件检查后删除，无真实截图或人工目视验收。
保存文件时剥离登录字段，检查最初和最终的有效凭证值未进入临时文件；短状态标记不作为凭证搜索。
首次运行已经下载并定位成功，但最终文件检查对短状态值误报，因此该轮记录为未通过，没有冒充完整成功。
修正检查后完整重跑；验证器也补齐了界面结果不完整时对返回 Cookie 的独立账号核对，以及原有笔记／位置的只读回读。
开发登录继续按要求留在钥匙串。

## 自动化与范围

新增 Python 9 项，验证默认不登录、固定样本选择、完整双进程证明、严格状态／计数、零请求离线及私密字段过滤；Lua 请求范围控制另有 29 项。
两入口、两尺寸共 4 个合成缺章配置通过，覆盖 6 条引用／2 章、零请求取消、正常下载、独立目标与新进程离线恢复。
原有缓存模式另有 4 个配置回归，确保默认路径仍零 HTTP，未接受缺章模式专用字段冒充旧结果。
所有生产包仍为相同的 227 个文件，与上一轮已通过首页／书架／书城／统计／授权及阅读／同步组合的生产字节完全一致；没有把这些旧组合描述为本轮重新运行。

本次真实验收不包含图片资源、TXT／CB_ 范围、付费或不可访问章节、下载中断／断电，以及实体 KO2 按键／联网／休眠。
账号数据和授权 POST 均为零，目录和正文只读 POST 单独记账；实际想法写后回读仍需新的具体授权。
固定候选、范围及请求记录见[本批证据](validation-assets/2026-11-11/note-source-download.json)，整体剩余项见[开发清单](development-roadmap.md)。
