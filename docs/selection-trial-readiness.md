# 新选区原生三步与条件划线清理：执行准备

已补齐独立的一次性执行器，目标是验证真实新选区的原生私密想法新建、编辑、删除，以及可能遗留的关联划线。
**目前只完成准备与禁止发送预演，未运行真实 `--apply`，也未取得本次最多四次修改的新许可。**
此前[原生私密三步](native-thought-trial.md)使用已有划线，三次许可已全部使用；本执行器不复用旧许可或旧意图。
本批没有修改生产代码，两份候选的 236 个文件与基线 `441af21`、当前源码及实际安装内容逐字节一致。

## 待授权的具体操作

1. 从已核对原文中选择与已有云端标记不重叠的唯一片段，经实际原生选区菜单、编辑器和生产服务新建一条私密测试想法。
2. 独立宿主读取完整原有想法、划线、书架标记和精确位置，核对新记录的私密属性、章节、范围、引用及测试文字，之后才允许原生编辑该新记录。
3. 再次独立核对编辑结果和原记录，之后才允许原生删除该新记录；删除后仍须独立核对。
4. 如果尚有**最多一条新出现、与该选区完全匹配**的划线，独立再读取并核对其编号、整条记录摘要、章节、范围和引用，才允许 Python 原型发送一次清理请求。没有遗留划线就跳过该次修改。

上限为三次原生想法修改加一次条件划线清理。`/book/removeBookmark` 清理接口尚未实际写入验证，
仅存在于 Python 原型，没有加入生产 Lua；不能把合成成功当作真实服务端验收。
新划线的关联判断依赖唯一新增编号、相同章节／范围／引用及不变摘要；这不能排除用户同时在完全相同位置进行相同操作，不能声称具有因果证明。

所有原有想法、划线、章节描述、书架标记和两通道精确位置都受保护。
允许服务端为所选章节新增一项章节索引，必须单独报告；即使测试想法和划线消失，也不能据此声称所有服务端状态完全恢复。
排序、操作时间与历史不保证恢复。异常或中断立即停止，可能留下测试记录；不会改写原记录来强行恢复快照。

## 一次性执行与中断处理

`scripts/verify_selection_trial.py` 默认离线，真实准备、预演和执行都需要显式选择保存的登录。
`--prepare` 在独立钥匙串条目中保存账号／书籍绑定、随机测试标记、数量和摘要；不保存凭据、原文或引用。
执行前重新读取来源、目录、完整基线及原生书籍版本，任何变化都会在领取额度前停止。

`--apply` 仅是技术入口，不能替代本次用户许可。宿主在启动可发送的原生进程之前，一次性持久占用全部四个可能的修改额度。
每步独立核对结果并持久记录后才应答下一步；限定门槛同时核对完整载荷、生产 SQLite `pending` 和新记录编号。
原生进程只可发送三种想法操作，条件划线清理由 Python 独立实施。

回执丢失只进行有界只读核对；读取滞后最多重读三次，不重复写入。
中断后即使尚未发送任何 POST，也禁止旧测试重跑、重新领取或自动续期。
准备状态可以按精确摘要显式丢弃；已占用状态不能通过丢弃来重置。
成功须独立核对恢复、完成原生进程与临时目录清理、保存必要登录轮换，最后才清除本次测试意图。
已有 Web 与墨水屏登录继续保存在钥匙串。
