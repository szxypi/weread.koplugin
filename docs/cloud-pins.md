# 云端置顶

书籍详情 →「书架状态」→「修改云端置顶」。插件先读取墨水屏书架及所选书的阅读位置，再提供确认：明确已置顶时可取消；明确未置顶或云端未提供状态时可发起置顶。未提供状态会在确认窗口中标明，不假定原状态为未置顶。需要墨水屏登录及网络；支持普通数字编号书籍和个人导入书，公众号尚未接入。

置顶后必须收到明确成功回执，并独立读到该书 `isTop=true`；取消后必须收到明确成功回执，再读到 `isTop=false` 或原先存在的置顶标记消失。若标记消失，界面只报告成功请求和标记不再返回，书架状态仍显示「未提供」，不将缺失推断成明确 false。更新的书架快照会保存并刷新显示。用户还可以单独使用[本机置顶](local-shelf-pins.md)，该功能不与云端同步。

请求使用 `/shelf/top`，目标书籍与空的专辑／分组数组都写入请求；参数依据[开源客户端实现](https://github.com/teng-lin/weread-omni/blob/fe8609071af33b013c7d2e34a70976fec906dc0c/src/api/resources/shelf.ts)及[真实四步协议核对](pin-observability.md#真实置顶与取消2026-11-22-后续)。已真实验证 Python 客户端的置顶和取消、三通道回读及清理；另以真实账号的书架与所选书位置做只读核对，Python 和 KOReader Lua 的置顶／取消计划逐字段一致；[去敏报告](validation-assets/2026-11-22/cloud-pin-real-model.json)不含书籍或账号内容。真实账号原生确认界面已在 600×800 与 KO2 尺寸完成[只读验收](#真实账号原生只读预览)，生产写入界面另经合成服务与 SQLite 验证；真实账号原生置顶和取消的[写入往返](#真实账号原生置顶与取消)已通过；实体 KO2 仍待验收。

## 保护与验证

- 确认前后绑定当前账号、授权、界面和完整书架状态，并比较其他书籍的可见标记、分组与所选书章节、偏移及百分比；变化时不发送请求。
- 与私密阅读共用按账号持久化的操作记录，并与读完标记、书架成员操作在界面互斥。发送前原子领取记录；每次只发送一个请求，未知回执、中断和重启均不自动重发。回读成功后先保存书架，再结束记录。待核对入口只读取并允许用户确认保留当前状态，不自动恢复云端状态。
- 空数组必须编码成 JSON 数组；不支持的身份、异常标记、组或无法核对的位置阻止发送。取消置顶仅从明确的 `isTop=true` 出发；返回缺失与返回 false 分别保留。
- 合成服务使用实际打包插件、KOReader 界面、后台进程和 SQLite：两种尺寸验证置顶／取消、位置及其他状态保护、确认取消、回执丢失后跨进程只读核对和不重发，后台进程均回收；真实私密阅读模拟流程另作回归。报告：[600×800](validation-assets/2026-11-22/cloud-pin-ui-600.json)、[KO2 尺寸](validation-assets/2026-11-22/cloud-pin-ui-ko2.json)。

更多书籍、实体设备，以及服务端未公开的操作历史和排序时间仍待验收。

## 导入书的真实协议试验

2026-11-24 只读核对发现账号中 5 本导入书在原生与网页书架均未返回置顶标记，阅读状态稳定。选取其中一本已有书执行两次限定请求：置顶回执明确，两端独立回读都返回置顶；取消置顶回执也明确，但之后的完整状态指纹与测试前不同，流程停止，没有重发。连续两轮独立只读复查稳定：两端均不再返回该书的置顶字段，当前两端书架成员、分组和可见标记一致。

字段缺失不等于明确的 `false`；本次也无法证明测试前所有状态已经恢复。测试前只保存了组合指纹，未保存分项指纹，因此无法判断差异来自书架、分组还是阅读状态，也不能推断差异一定由本次请求造成。两条单次请求记录继续保存在本机钥匙串，取消记录保持「已收到回执、未完全核对」；已为同账号同设备续期建立只读复查绑定，不允许重发。此结果不构成原生导入书置顶功能的验收，当时插件入口保持关闭。去敏结果见[记录](validation-assets/2026-11-24/imported-cloud-pin-unconfirmed.json)。

后续试验的本机记录新增书架、网页与阅读状态的分项指纹，可帮助定位差异；本次历史记录不会被改写或补造。`python3 scripts/verify_imported_pin_trial.py --saved-session --inspect` 可只读复查本次目标；不输出书名、书号或凭据。
