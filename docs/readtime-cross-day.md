# 真实跨日窗口的只读预检

本阶段继续[真实计时采集](readtime-history-recovery.md)，不改动钥匙串中的两秒窗口、设备摘要、来源证明或采集日期。
`verify_readtime_cross_day.py` 默认离线，显式复用已保存登录后才执行只读核对：

```bash
python3 scripts/verify_readtime_cross_day.py --saved-session
```

本机时间与服务器时间均须经过原记录的下一北京时间日期边界。
工具重新核对采集账号、设备、完整原始来源计划、目录、Web／原生版本、原始精确位置和逐书三项计数。
随后间隔两秒进行两轮原生版本、计数及采集月份统计读取，月份由采集时间确定，不能用当前月份代替。
原标记、想法、书架状态和 Web 位置另行核对，结束时原采集记录必须仍逐字节一致。
统计、正文和凭据仅留在内存；报告只包含固定标签、状态、数量与布尔值。

工具没有构造时长载荷、领取发送次数、上传、续期或编辑采集记录的方法。
读取失败不触发写入重试，读取成功也不授予后续发送权限，更不证明历史时长已入账。

## 实际验证

2026-11-17 北京时间的实际预检通过，原记录跨日条件满足，来源、设备、版本和计数均保持；
两轮采集月份统计一致，原有位置、标记、想法与书架记录保持。新工具全部为只读请求。

初次运行在来源前置读取中遇到自然 HTTP 401，独立书架读取也返回 401。
经独立新的一次性标记，既有授权工具仅发出一次续期请求，验证同账号并将新登录保存在钥匙串；
该过程没有账号数据写入。原跨日采集以及旧首次位置、阅读器、关书、定时和未确认时长范围前后逐字节保持。
新的预检在续期后重新从来源准备开始，没有复用失败前的观察。前两份失败记录继续保留；
首份报告未含来源网络状态，补齐固定状态诊断后才记录到明确 401，没有因此重发任何数据修改。

新增 11 项 Python 测试覆盖日期尚未到达、缺失／替换采集、外来账号与设备、来源／目录／版本变化、
原位置与三项计数变化、服务器时间、统计变化、跨月份查询、超时不重试、只读白名单、授权替换及报告去敏。
当前完整 Python 检查为 132 个模块／1679 项，零跳过。
生产插件内容不变，继续使用此前已通过两尺寸原生流程的 288 个文件；本阶段没有重跑未变的绘制流程。
固定记录见[跨日预检证据](validation-assets/2026-11-17/readtime-cross-day.json)。

## 单次历史发送参考工具

`verify_readtime_cross_day_upload.py` 默认离线，`--saved-session` 仅准备和预检，
`--saved-session --apply` 才使用已有开发授权执行一次请求。
本次协议只覆盖已实际采集的北京时间两秒窗口，不声称已验证其他时区或实体设备账本。
它先重新运行完整跨日只读预检，再获取新签名资料，绑定原采集、设备／授权、请求和月度统计摘要。
原来的两份已消费时长记录继续保留；新协议使用独立钥匙串条目，已占用或已完成均不能再次领取。

发送前复核版本、完整原记录、位置、逐书计数和采集／当前月份统计；请求时间必须新鲜且未跨当天边界。
先持久保存领取再发送，最多一个修改请求，禁止登录续期、失败换路和重发。
明确回执先持久保存，随后最多四轮只读等待，须连续两轮核对原日期日桶和逐书阅读时长恰好增加两秒，
其他计数、日桶及当前月份保持。`readDays` 的服务端资格阈值不明，只允许零或一的增量；
时长和所有日桶仍要求精确，不能用该例外解释额外秒数。
若数据落在当天、响应不明、位置／来源变化、读回退化、配置保存失败或中断，保持已消费状态并停止。
成功后保留封存记录，不删除领取记录或恢复额度。

17 项新增测试覆盖真实小时桶保持、领取／回执保存顺序、模拟两次独立目标、延迟、丢失／拒绝回执、
当天误入账、其他日桶／计数变化、月份分离、午夜停止、配置保存失败、不可复用及 Web 登录轮换。
完整 Python 检查为 133 个模块／1696 项，零跳过。
一次实际只读准备已通过，零数据修改、零授权请求；首次报告中“保留范围”标签过宽，
随后修正为只在实际已领取并完成时为真，未把该准备记录当作已消费请求。
生产插件 288 个文件继续保持；Lua 历史发送器及补传界面尚未接通。

## 实际单次发送与停止后的只读核对

`78098bf` 的 CI 通过后，以固定提交、独立启动标记和新的持久范围执行一次：
重新来源准备、同计划只读预演均通过，随后领取先于唯一 HTTP 请求。
HTTP 200 的明确成功回执已先保存，第一次完整统计比较停止为 `cross_upload/unrelated_delta`。
原范围为 `acknowledged/posts=1`，启动标记已消费，未重发、未续期、未删除或改为已验证。
本次数据修改恰好一次；原采集及所有旧已消费范围、新登录前后保持。

第一次读回观察到逐书 `readingTime`、原日期日桶和该月份总时长各增加两秒，
`recordReadingTime`／`ttsTime` 不变，当天日桶增量为零。完整比较没有通过，不能据这几个数值宣告原试验成功。
后续全部为独立只读核对，未调用原发送流程。

最初只逆推日数和当前／历史零桶存在性的诊断没有匹配，记录保留。
扩展诊断只在采集月份枚举最多两个值为零的日桶存在性变化，并按保存的完整统计 SHA-256 精确筛选。
两轮读取均只得到一个重建结果：原日期与月总数扣除两秒后，再补回两个被删除的零桶，
完整统计摘要与发送前密封的摘要一致；日数不变，其余日桶和数值一致。
另一个新进程重复两轮读取，独立核对原生／Web 位置、目录及版本、原记录和原采集均保持，范围也未变化。
该诊断支持“本次两秒归入原日期，额外结构变化为两个零桶被移除”的观察，
不会将未通过的原范围倒改成已通过，也不授予重发或新发送次数。

原试验已在本机封存为未通过，保留原回执、计划和消费记录，不重发。
