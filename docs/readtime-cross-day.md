# 真实跨日窗口的只读预检

本阶段继续[真实计时采集](readtime-history-recovery.md)，不改动钥匙串中的两秒窗口、设备摘要、来源证明或采集日期。
`verify_readtime_cross_day.py` 默认离线，显式复用已保存登录后才执行只读核对：

```bash
python3 scripts/verify_readtime_cross_day.py --saved-session
```

本机时间与服务器时间均须经过原记录的下一北京时间日期边界。
工具重新核对采集账号、设备、完整原始来源计划、目录、Web／原生版本、原始精确位置和逐书三项计数。
随后间隔两秒进行两轮原生版本、计数及采集月份统计读取，月份由采集时间确定，不能用当前月份代替。
原标记、想法、书架状态和 Web 位置另行核对，结束时原采集记录必须仍逐字节一致。
统计、正文和凭据仅留在内存；报告只包含固定标签、状态、数量与布尔值。

工具没有构造时长载荷、领取发送次数、上传、续期或编辑采集记录的方法。
读取失败不触发写入重试，读取成功也不授予后续发送权限，更不证明历史时长已入账。

## 实际验证

2026-11-17 北京时间的实际预检通过，原记录跨日条件满足，来源、设备、版本和计数均保持；
两轮采集月份统计一致，原有位置、标记、想法与书架记录保持。新工具全部为只读请求。

初次运行在来源前置读取中遇到自然 HTTP 401，独立书架读取也返回 401。
经独立新的一次性标记，既有授权工具仅发出一次续期请求，验证同账号并将新登录保存在钥匙串；
该过程没有账号数据写入。原跨日采集以及旧首次位置、阅读器、关书、定时和未确认时长范围前后逐字节保持。
新的预检在续期后重新从来源准备开始，没有复用失败前的观察。前两份失败记录继续保留；
首份报告未含来源网络状态，补齐固定状态诊断后才记录到明确 401，没有因此重发任何数据修改。

新增 11 项 Python 测试覆盖日期尚未到达、缺失／替换采集、外来账号与设备、来源／目录／版本变化、
原位置与三项计数变化、服务器时间、统计变化、跨月份查询、超时不重试、只读白名单、授权替换及报告去敏。
当前完整 Python 检查为 132 个模块／1679 项，零跳过。
生产插件内容不变，继续使用此前已通过两尺寸原生流程的 288 个文件；本阶段没有重跑未变的绘制流程。
固定记录见[跨日预检证据](validation-assets/2026-11-17/readtime-cross-day.json)。

## 后续工作

需要另行实现有界 Python 历史发送验证：重新预检原窗口，绑定新鲜载荷和独立的历史月／日基线，
保存一次持久领取，再核对明确回执、逐书两秒增量以及原日期唯一日桶的两秒增量。
总数增加但落在当天不能算通过；未知结果不能重发，旧未确认范围不能重新领取。
只有真实历史入账验证通过，才接通 Lua 历史发送器和本机账本补传入口。
该采集仍是受控测试窗口，并非实体 Kindle 的离线阅读账本；实体 KO2 和设备故障验收继续待完成。
