# 原生封面接收限制与只读验证

书架封面原有单张 3 MB、缩略图 300×450、总缓存 32 MB 的限制。
原来单张限制只在完整响应已进入内存后检查；现在后台下载时逐块检查，
超过上限即拒绝当前块、停止接收，不生成或覆盖缩略图。
正常响应保持原字节，重定向时丢弃前一响应的块并重新计数；
未指定上限的原有正文资源请求保持原行为。
公开封面继续不发送账号 Cookie，不保存响应 Cookie；诊断隐藏封面地址。

## 验证结果

- 传输检查覆盖无长度分块响应、刚好上限、超限即停止、重定向内容隔离、
  现有重定向回调及非法上限不联网；原生 HTTP 另用合成 PNG 与较小上限确认实际接收器拒绝超限。
- Python 先核对真实账号、读取 139 本书架，再匿名读取其中第一张有效封面。
  该样本为 JPEG；不输出书名、书籍编号、封面链接、摘要或图片。
- 打包插件独立匿名读取同一封面，长度和 SHA-256 与 Python 一致；
  实际书架后台进程生成缩略图，退出并回收后移除原图暂存，缓存只留下一个缩略图。
  原生封面控件实际解码且不进入占位图分支；强制绘制后断网重开，命中原缩略图且不再请求图片。
- 官方 KOReader v2026.07.1 Linux ARM64／Xvfb，600×800／167 DPI 与
  KO2 对应的 1264×1680／300 DPI 均通过，零重绘失败。
  两份最终运行共 8 个真实 GET（每份账号、书架、Python 图片、Lua 图片各一次），
  没有授权维护 POST 或账号数据写入；[公开报告](validation-assets/2026-11-09/shelf-cover-owner-readonly.json)仅含计数和状态。

首次原型另完成 3 个 GET；前三次界面尝试各完成账号／书架／Python 图片读取，
因测试脚本未调用正式书架快照入口而在图片工作进程启动前中断，已修正测试初始化。
修正后的首次原生运行另完成 4 个 GET。本项合计 24 个真实 GET，无真实写入；
失败尝试没有被计作通过证据。

## 隐私与复验

`scripts/verify_shelf_covers.py` 默认离线，只有显式 `--saved-session` 才读取项目钥匙串。
Python 的账号请求使用既有会话；经核对的 Cookie 轮换在可选图片／Lua 验证前保存。
Lua 只通过捕获管道收到图片地址、字节数和摘要，不收到账号凭据或书名。
Python 图片请求拒绝重定向；Lua 探针只允许同一地址的一次匿名 GET，拒绝其他路径或凭据头。
产品原有重定向行为另由合成传输检查，不从这一个无重定向真实样本推断所有 CDN 行为。

Linux 执行包装器 `scripts/run_shelf_cover_probe.py` 先确认 `/dev/shm` 为 tmpfs，
将候选包、隔离配置和封面缓存置于临时内存目录，退出删除目录。
显示名称为合成文字，截图功能禁用；真实图片、地址和原生运行日志不进入磁盘报告。
钥匙串继续保留到整体目标完成。

已准备官方运行环境与候选包时，可按以下方式复验。此处不包含凭据或真实地址：

```sh
python3 scripts/verify_shelf_covers.py --saved-session --lua-command \
  docker exec -i -w /source weread-validation xvfb-run -a \
  python3 scripts/run_shelf_cover_probe.py \
  --koreader /validation/runtime/lib/koreader \
  --candidate /validation/candidate.zip \
  --width 1264 --height 1680 --dpi 300
```

## 关闭、切换与休眠时取消封面任务

原生延迟图片场景已复现旧行为：服务端确认图片请求仍在处理时，关闭书架不会终止当前子进程。
原实现只靠视图／代次核对阻止后续刷新；当前请求仍会完成下载或等待超时。

现已接入统一取消：关闭微信读书界面、切换账号、刷新书架、换页、改为列表、
切换首页／书城，以及阅读器就绪、关书和休眠时，终止被替换的封面任务。
取消会立即使旧代次失效；保持该任务和读取管道，直到确认子进程退出并回收、读取关闭管道，才启动排队任务。
只保留最新视图的请求。取消与完整缓存提交同时发生时，保留已经有效提交的缩略图，但不再刷新旧页或下载旧批次余项。
已取消但仍活跃的同一子进程会在轮询中继续收到终止请求，覆盖信号早于进程组建立的启动窗口；
每次先确认该子进程尚未回收，不对已经结束的任务继续发送信号。

休眠只记住当前可见页的最新请求。唤醒后可继续加载；若旧子进程尚未回收，则先排队，
不会同时写缓存。休眠期间关闭界面或切换账号会清除待恢复请求；重复唤醒不重复启动。
终止函数抛出异常时不丢弃任务归属，保留后续重试与退出检查。

`spec/shelf_cover_cancel_spec.lua` 新增 27 项检查，覆盖退出、重开、最新页替换、
同页重复、提交竞争、终止失败、早发信号重试、超时及阅读生命周期入口。
`spec/koreader/shelf_cover_cancel_smoke.lua` 使用实际原生插件、延迟本地 HTTP 和真实子进程，
先由服务端确认请求活跃并验证主界面心跳，再检查关闭后重开、账号切换、列表切换、书城切换、
休眠恢复及休眠期间关闭六个场景。每种尺寸共启动 9 个图片子进程，6 个收到终止请求；
9 个均回收，9 个管道分别读取关闭一次，重新打开和恢复的封面经原生解码绘制。
全部图片和账号均为合成数据，本项没有读取真实钥匙串或访问微信读书。

修复后首轮测试漏放底层窗口，导致关闭最后一个测试界面时 SDL 退出并清空事件队列；
补齐等效于实际文件管理器／阅读器的底层窗口后通过，未把该中断样本算作验收通过。
最终证据与两尺寸回归见[取消验证报告](validation-assets/2026-11-09/shelf-cover-cancellation-runtime.json)。
本项不证明实体 KO2 的系统休眠、无线网络中断或强制退出文件系统行为已验收，
不改变集中性能优化的整体先后顺序。
