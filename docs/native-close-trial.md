# 真实阅读器关书同步与恢复

开发分支已在真实账号完成一次 TXT 关书发送及原位置恢复，尚未发布。
首次请求来自正常 ReaderUI 关闭流程，经生产 `SourceClose`、`ProgressSync` 和原生发送服务执行；
第二次在阅读器保持关闭时，独立重新核对原始归档，再恢复完整原位置与原摘要。

## 验证约束

新协议 `native-reader-close-literal-raw-30-zero-time-v1` 使用独立钥匙串记录，最多两个修改槽位。
关闭前在原位置做一次只读同步比较，再移动一个原文字符并关书。关闭后生成的计划绑定实际整数显示百分比；
原完整摘要和目标原文片段只通过钥匙串、内存管道和临时内存文件系统传递。

宿主独立核对完整请求、签名、原生版本、零时长和空小时数组；请求前持久领取槽位，明确成功后先保存回执，
再独立读取来源、目录、元数据、双通道完整位置／摘要、三项时长计数和可见书架。未知回执或中断停止，不能重发。
本轮记录已封存且两个槽位均消费；此前手动往返、原文摘要及旧未验证记录均保持原状态。

## 结果

[固定字段记录](validation-assets/2026-11-12/native-close-trial.json)包含：

- 两个尺寸的模拟服务先完成禁止发送预演，再验证正常关书发送及关闭后恢复；各两个合成请求、两个成功回执和两步独立核对。
- 真实账号首次只读预检遇到实际 HTTP 401，零修改、零领取后停止；独立启动记录限定一次续期，并核对同账号和钥匙串保存。
- 续期后真实零写入预演完成，实际文档关闭后生成完整请求并拦截，再绑定新测试记录。正式往返恰好两个原生请求，均有明确成功回执和独立回读。
- 原完整位置和摘要恢复，时长计数及可见书架保持。正式往返没有授权 POST、Web 修改或历史时长行；本轮仅前述过期恢复产生一次授权 POST。
- 最终补充一次真实零写入核对，临时测试记录仅在内存中，已封存的真实钥匙串记录保持不变；再次确认完整关闭／保存／清理流程没有访问关闭文档。
- 后台进程回收、父进程文档限制、配置凭据审计、零正文截图和临时配置删除通过；279 个安装文件与候选和源码一致。

新增 16 项 Python 测试覆盖新协议隔离、显示百分比冻结、领取／回执顺序、未知结果、中断、关闭证明和共享试验屏障。
完整 Python 回归为 118 个文件、1497 项、零跳过；原手动 ReaderUI 模拟往返也通过回归。

真实关书验证使用 600×800／167 DPI 的官方 KOReader 运行环境；KO2 尺寸为模拟验收，不能替代实体 KO2。
真实定时和更多异常场景、待确认回执的恢复界面、更多格式、断电与实体设备仍待验收。
已有[关书实现及异常场景](native-source-close.md)和[手动写入验收](native-reader-trial.md)继续保留各自证据。
