# 单章译文的单次派发与独立回读

本项是桌面 Python 的真实协议验证器，尚未接入 KOReader 生成菜单。
现成译文的[原生副本下载](translation-fetch.md)已经单独验收；[缺失译文准备](translation-generation.md)提供新鲜的免费／已购买章节、原文与云端基线。

## 派发与不可重放

默认运行完全离线。真实操作要求显式选择，并且只能使用已保存的同账号、同授权、同目录／原文／基线计划。
模式 GET 与生成 POST 都先持久领取并回读，再允许一次网络请求；两次操作之间重新核对整个计划。
每次都核对当前钥匙串授权、账号和原有采集记录。旧采集的书籍不能成为本试验目标。
没有自动续期、重发、重定向、购买、试用、下一章、进度或时长操作。

生成只包含当前章，`reference.texts=[]`、`freeTrial=0`。模式操作必须有明确成功回执。
旧的纯语义回执可保留读取，但不能授权新传输；真实派发必须有可核对的 HTTP 回执。

响应在读取时限制为 8 KiB，加一个字节检测截断。先保存状态码、精确正文的 Base64 和截断事实，
然后解释 JSON／成功状态。HTTP 错误、非 JSON、重复键、非法 Unicode 和未知结构都保留原始事实；
超限只保留明确标记的有界前缀，不称为完整回执。失败或未知不批准下一次修改。
无可用响应的断网／中断保持领取状态，不释放请求额度。清理连接的错误不丢弃已经收到的正文。

## 原文与后续只读核对

请求前在同一不可覆盖记录中保存原文可见文字摘要、译文字段原始存在性／值，以及最多 16 KiB 的实际基线。
它们绑定原计划摘要；完整原文和凭据不写普通文件。两份最大回执加最大基线仍在 64 KiB 钥匙串限制内。

生成回执区分就绪、等待和停止但不可用。等待期间最多六次读取目录／正文／基线，间隔两秒，
不通过重复 POST 轮询。实际非空译文、正译文版本、原文可见文字、两轮稳定正文和目录投影，以及原有可观察状态都要独立核对。
目录投影除本章的三个译文字段外必须保持；已有计数要求和明确未返回位置的基线沿用准备器的区分，不补零。
初始回执仍为等待时，可由后续真实正文与目录证明完成，原始回执不改写成就绪。

`--inspect-result` 只读核对已提交记录，不领取或派发任何修改，也不更改原计划／回执。
它使用请求前保存的原文摘要与目录字段，不能从当前译文反推一个旧基线。
同账号的新授权可以只读核对旧请求，原计划中的旧授权摘要保持。
失败后另作有界只读基线检查，不据此把未知生成结果改成成功。

## 验证与当前范围

48 项新增测试覆盖请求字段、持久顺序、传输／回读失败、HTTP／JSON 异常、截断、钥匙串大小、
原文与目录变化、不可重放、等待后的只读观察，以及新授权下的只读核对。
完整 Python 回归为 141 个模块／1850 项，零跳过。
真实账号的零写入预演通过，确认原文与缺失译文、两轮基线、旧采集保持及原文核对信息可保存；没有领取生成额度。
随后实际自然过期返回 401，经独立 401 见证后仅续期一次，同账号／钥匙串回读与旧范围保持。
