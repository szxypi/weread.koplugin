# 同步期间原文位置晚到

手动同步可能在本机原文位置仍在后台采集时开始，例如刚切换账号或重新进入阅读器。发送前，插件仍会独立准备并核对原文坐标；若准备成功、服务端位置确认成功，且同一账号、阅读会话、导航代次、原本的待同步记录和完整页面视图均未变化，采集到的原文点会与开始时的页面绑定。这样不会仅因为位置从“尚未采集”变为“已采集”而误判成翻页，重复留下待同步记录。

页面、排版、原文点或待同步意图发生变化，以及无法核对完整页面视图时，仍保留后续位置，不以该规则清除；账号或导航失效时不继续旧任务。这里的页面绑定只是本机变化判断，不代替发送前的来源核对、云端回读或未知回执保护。

自动化测试先重现了相同页面因原文点晚到而留下待同步记录，再覆盖页面变化、排版变化、布局信息缺失、新待同步意图、发送期间原文点变化和导航失效。600×800 与 1264×1680 两种尺寸使用打包插件、实际 KOReader 阅读器、后台任务及本地模拟服务，从原文点尚未准备好时开始同步；确认只发送一次、独立回读成功且没有重复待同步位置，随后继续执行休眠、离线账本和模拟补传回归。测试未写入真实账号；真实网络异常、跨设备并发及 Kindle Oasis 2 实机仍待验收。

加入额外独立回读后，一次 600×800 运行通过了本项位置检查，但在后续模拟时长的“回执后取消”场景等待超时；该次完整回归记为失败，原因未确定。随后独立重跑同尺寸完整流程通过，1264×1680 的最终完整流程也通过；不能据此断言先前超时的原因。
