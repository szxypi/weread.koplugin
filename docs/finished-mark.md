# 原生读完标记

入口：书籍详情 → 书架状态 →「修改读完标记」。先重新读取云端书架与所选书的原生阅读位置，
然后按实际 `finishReading` 显示「标记已读完」或「恢复未读完」的确认框。
当前支持书架中普通数字编号、明确的读完标记和可核对原生位置的书籍；未提供或异常数据不猜测为未读完。
读完标记独立于阅读百分比及 `finished` 字段。

## 每次确认只操作一次

请求字段沿用此前分别实测的标记与取消：`bookId`、`auto=0`、`finishInfo=0`、`status=4`，
两方向分别为 `isCancel=0/1`。此前两次实际修改及原状态恢复已经由独立读取确认；
原先严格连续往返因回执未知而停止的记录保留，没有改写成成功，见[协议历史](finish-status-prototype.md)。

本入口是一项单次操作。每次都需要新预览、新确认，不自动标记后再恢复。
生产实现与 Python 模型独立核对完整请求摘要、全体书架成员／置顶／私密／读完字段和原生章 UID／序号／偏移／精确百分比。
只允许缺失字段保持缺失；异常字段不能准备写入。任何预览后变化、账号／阅读会话改变或超过 120 秒，都不能派发原请求。

确认后先在账号独立 SQLite 中以 `synchronous=FULL`、`BEGIN IMMEDIATE` 保存 `prepared`。
后台发送前原子领取为 `pending`，只调用一次固定 POST；同时开始的任务、取消、关闭或重开不能重复领取。
取消已证明未派发的准备可以清理；可能已经派发的操作保留待核对记录。
意图只有有界摘要和目标，不保存全体书架、原始位置、正文或凭据，不增加主设置中的数据集合。

不根据 HTTP 200、`status=1`、`finishReading` 或未知返回对象猜测成功回执。
最多三轮独立书架／位置 GET，完整预期状态出现、其他字段及原位置一致后才确认“状态已核对”。
仅目标仍为原值时可以等待下一轮；其他标记、成员或位置发生变化则立即停止核对。
未知回执、超时、401、429、中断均不重发；没有自动续期、条件恢复或阅读位置写入。
先成功保存完整本机书架快照，才结束待核对记录；保存失败也不会为此重复修改云端。

## 中断后的只读核对

「核对上次读完标记修改」只读取当时目标，不发送标记请求。
先显示当前状态，再经第二次确认明确保留刚刚读取的云端状态，更新本机快照并结束本机等待。
目标被其他设备移出书架、未返回标记，或位置变化／暂不能读取时，也可如实展示并明确选择保留当前状态。
不会把这些情形当作原操作成功、恢复原位置或排除服务端延迟生效。
读取或保存失败则继续保留记录；损坏意图不会被新操作覆盖。
书架成员与读完标记的待确认操作互相阻止新写入，避免同机两个未核对修改相互覆盖。
