# 2026-11-08—09 原生详情与书城验证

本轮跨夜工作延续[开发清单](development-roadmap.md)；界面采用原生 KOReader 控件，
先完成功能与验证，再进行 Kindle 等墨水屏设备的集中性能优化。
本轮没有合并或发布，仍在现有草稿 PR。

## 已完成的行为

首次实现无 Skill 密钥时的 Web 资料读取和官方查询优先；后续已增加墨水屏资料优先通道，见下文。
读取、解析在独立后台进程完成，资料在账号 SQLite 中缓存；简介转换成原生文字。
刷新详情不再读取云端进度，更不会用旧网络结果覆盖阅读期间更新的本机位置或文件版本。
重读最新本机记录后只合并展示字段；取消、账号／凭据变化、旧页面回调和保存失败均有处理。

与已保存的 Web 会话使用独立条目，按用户要求保留至整体目标验收收尾。

- 真实 Python 原型先于 Lua 实现，核对搜索、个性化推荐、相似书籍的固定 GET 合同。
  搜索 20＋2 本、相似 20＋3 本，游标前进、无重复、会话保持一致；真实个性化推荐为空。
- Python／Lua 对相同真实响应的展示投影一致；KOReader 原生 HTTPS 独立完成 5 个 GET 的搜索／相似分页，
  结果数量一致，无账号数据写入。[去敏报告](validation-assets/2026-11-09/native-discovery-owner-readonly.json)
  仅含时间、字段名、数量和断言，不含私有查询结果、书名、ID 或凭据。
- 搜索／推荐／相似列表采用原生控件，后台进程解析数据；相似推荐保留会话，后续页绑定原通道及凭据修订。
  首批故障可按规则回退 Skill；429 不回退，失败保留当前页。刷新清除旧游标。

## 原生授权书籍资料

参考 MiuRead `eink_client.lua` 的书籍读取，先完成 Python 原型和两本真实书籍验证，再接入 Lua。
详情页优先使用当前账号的墨水屏授权，未授权时继续使用 Skill／Web；资料仍由原生控件显示。
无 Skill 密钥时原生接口可直接提供简介、出版信息、评分及字数，不必拉取 Reader HTML。

- [真实去敏结果](validation-assets/2026-11-09/native-metadata-owner-readonly.json)：139 本书架中抽取 2 本，
  Python、Lua 模型及 KOReader HTTPS 展示投影全部一致；原生只发送 2 个固定 `/book/info` GET。
  两本均有出版信息、字数、简介及评分，一本有译者。`totalWords` 有界转换为展示字数，
  原生版本、读完状态和阅读进度不进入资料缓存；没有账号数据写入。
- 600×800 和 KO2 1264×1680／300 DPI 完整合成 HTTP 验收通过：无密钥原生读取、字数／简介／评分／出版信息、
  原生详情、SQLite、加载时 UI 心跳、本机进度 83→84 及 EPUB 版本 47 保护、
  授权修订变化、取消／关闭、Skill／Web 回退、原生 429 不继续其他请求并保留缓存。
  同时回归原生书城、授权／续期、无密钥 Web 资料、下载／EPUB／原文导航及离线时长。
- [600 截图](validation-assets/2026-11-09/native-eink-metadata-600.png)与
  [KO2 尺寸截图](validation-assets/2026-11-09/native-eink-metadata-ko2.png)已检查，均使用合成书籍。
- 107 组 Lua、151 组 Python、261 个 Lua 文件静态分析通过（0 警告／错误）。

Web 和原生开发凭据继续保留在两个本机钥匙串条目内，直到整体目标验收收尾。
