## 关闭详情时的重绘修复

本轮继续处理上节保留的 TextBox 警告。合成账号诊断堆栈定位到：
KOReader 先向详情页子控件发送 `CloseWidget` 并释放文字缓冲，再执行父页关闭回调，
最后才从窗口栈移除父页。回调取消资料／相似书籍读取时，`closeBusy()` 又立即重绘整个栈，
因此尝试绘制仍在栈中的已释放标题文字，触发 `_bb` 空值。

- 等待窗仍立即关闭，子进程／自有续期仍立即取消。只移除 `closeBusy()` 中同步强制重绘，
  使用 KOReader `close()` 已排入的正常重绘，让页面先完成关闭。不修改 KOReader、文字控件或异常捕获。
- 增加 8 项关闭顺序／等待窗归属／下一帧检查，实际原生用例直接关闭详情、
  检查子进程／等待窗／页面已清理，再强制绘制关闭后的页面；移除重复关闭同一测试控件的操作。
- 两个原生运行工具现在将重绘警告视为失败。
  修复前，仅添加此检查的 600×800 候选仍完成原有流程，但捕获两次重绘警告并返回非零；
  因而未把隐藏警告的旧成功结果当作回归通过。
- 修复后，600×800 和 KO2 1264×1680／300 DPI 的完整原生核心与发现界面通过，
  四次运行均为零重绘警告。详情取消、书城／资料后台读取、统计／离线、下载／EPUB、
  授权恢复、休眠和原文导航继续通过。[去敏验证记录](validation-assets/2026-11-09/repaint-close-regression.json)
  仅含合成运行结果、数量与安装包摘要，不使用真实账号。
- 修正原 Python 时长测试夹具的八处 SQLite 连接管理，保留事务提交并明确关闭连接。
  110 组 Lua、171 组 Python 通过；启用资源警告后测试日志不再出现连接泄漏警告。

## 云端原文目标的跨文件续接

本轮补齐上节的跨文件边界，仍由原生 KOReader 控件／EPUB 引擎完成。

每个候选都独立核验文件身份、同章原文 SHA-256／字节数及渲染摘要，再允许切书。
交接仅在内存中单次使用；新 ReaderUI 安装后重新绑定目标文件，不重放网页读取。
原有开书自动拉取被本次精确选择替代，不能覆盖已选目标或重新授予上报确认。

- 没有匹配缓存时显示原生目标章节确认框，确认后复用现有单章下载器。
  下载清理完成后，重新取得完整的稳定云端快照，仍在同章则按最新偏移验证下载文件；
  换章则停止并提示重试。不会连环下载，不用百分比猜位置。
- 取消只终止本次拥有的前台下载，包括实际等待中的子进程。
  旧确认框、取消后的下载完成、翻页、账号／导航变化、关书、文件替换及超时不能迟到切书。
  已完成的缓存可保留。已有其他下载时保留其任务并结束本次续接。
- 新增单本索引读取，避免为三个候选路径加载所有书籍的资料。
