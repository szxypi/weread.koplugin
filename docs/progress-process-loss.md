# 同步期间的完整进程中断验证

使用实际候选插件、官方 KOReader v2026.07.1 Linux ARM64、原生 EPUB 引擎和本地合成服务，
验证手动位置同步、关书位置同步和周期阅读时长上报在完整进程丢失后的行为。
本轮新增验证工具和 CI 检查，没有修改生产同步逻辑或新增微信读书接口。

| 中断点 | 中断前的实际状态 | 新进程的预期行为 |
| --- | --- | --- |
| 发送记录落盘，尚未派发 | 生产发送记录已保存，尚未启动该请求 | 保留原待同步位置和发送记录；只读核对发现差异，要求明确选择 |
| 服务端已接收，回执尚未送达 | 合成服务已按实际请求更新位置，响应仍被阻塞 | 保留待确认状态；新鲜只读比较确认同一原文位置后解除待确认，不重复上传 |
| 明确回执后，独立位置回读之前 | 实际服务已返回成功，独立位置读取被阻塞 | 与上述相同，由新进程重新读取并核对，不借用已丢失的内存回执 |

每个中断点分别运行三个发送流程和两种尺寸（600×800、1264×1680／300 DPI），共 18 组。
周期上报使用 30 秒合成时长，手动和关书位置同步为零时长；定时回调由工具触发，
没有实际等待完整阅读周期。每组先从插件书架／书城选书、下载和进入正常原生阅读，
完成基准同步，再实际翻页并显式保存本机检查点及原生阅读记录。
发送记录均由生产 `SourceDispatch.begin` 生成，工具不构造待确认记录或伪造成功回执。
因此本项证明的是已提交检查点之后的进程丢失恢复，不声称未保存的最后一次操作也能恢复。

外部 Python 监督进程将 KOReader 放入独立会话。KOReader 后台任务会建立自己的进程组，
仅终止主进程组不足以覆盖它们；监督进程实际停止并向整个阅读器会话发送 `SIGKILL`，
确认主进程以 `-9` 退出，并采用 Linux 子进程收养机制回收孤立工作进程。
周期上报在已派发的两个中断点还核对实际报告子进程确实被终止；不调用插件正常退出、
休眠、停止报告或取消任务来替代完整中断。监督器自身的边界检查另验证其他会话不受影响。

中断后先由独立 Python 直接读取磁盘状态，确认原发送记录及本机意图仍在；
按合成原文重新计算来源哈希、UTF-16 坐标、章节序号和发送摘要，并核对服务端实际接收状态。
随后启动两个全新 KOReader 进程：

1. 首次离线打开缓存书籍，核对原生页码和原文位置、账号内的同一发送记录，
   并确认周期报告受待确认状态阻止。联网后仅读取位置；已接收的报告可解除待确认，
   未发送的报告保留差异和选择窗口，不替用户选择或再次发送。
2. 再次离线重开，核对解除或保留后的状态确实落盘，HTTP 请求总数保持不变。

三次进程之间共用实际文件设置、每书 JSON 和 SQLite，而非内存设置或重建的预期值。
第一次重开全过程的账号数据 POST 必须为零，第二次离线进程的所有 HTTP 必须为零。
测试结束前关闭新周期，避免完成核对后再产生一轮合法的阅读时长报告。

```sh
python3 scripts/test_process_loss_runtime.py
xvfb-run -a python3 scripts/test_discovery_runtime.py \
  --koreader /path/to/runtime --run-dir /path/to/new-profile \
  --reading-flow --process-loss after-apply --process-loss-kind periodic
```

`--process-loss` 可选 `before-dispatch`、`after-apply`、`before-readback`；
`--process-loss-kind` 可选 `periodic`、`manual`、`close`。
完整中断监督需要 Linux `/proc`，不在 macOS 主进程上运行；本地合成服务始终绑定回环地址。
固定字段报告见[验证证据](validation-assets/2026-11-10/progress-process-loss.json)。

这不等同于断电、磁盘写入中断或 Kindle 文件系统验收。尚未提交的翻页、落盘中途故障、
定时位置分支的专门强杀、真实账号的新组合写后回读、其他格式、多设备并发及实体 KO2 仍待验证。
既有真实写入许可没有复用，开发凭据继续按原要求保留；集中性能优化仍在全部功能验收之后进行。

不启用中断选项的正常阅读流程另做两尺寸回归：选书／下载、离线重开、双向重连、
普通／周期／定时／关书同步、来源／进度授权恢复、保存重试及成员操作全部通过。
两份候选各 204 个生产文件同样与源码及安装目录逐字节一致，ZIP CRC 和重绘检查通过。
