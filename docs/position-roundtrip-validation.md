# 真实位置的一字写入与恢复验证

`scripts/verify_position_roundtrip.py` 在本人明确授权后，完成一次真实账号的限定实验：
同章前进一个 UTF-16 单位，独立读回，再恢复原位置并核对通过。
这是 Python 工具对一个普通 XHTML 样本的写入证据；插件内完整同步、其他坐标模型与多设备尚未通过。

## 准备和允许的实验范围

默认不读取凭据、不联网。明确使用已保存授权后，工具选择一本已有位置的普通书籍，
核对云端／Reader 内嵌位置、同书章节、原文与唯一目标，以及已有进入阅读／上报请求的签名结构。
只读预览确认了一个同章、连续、唯一的相邻原文目标，偏移增加一个 UTF-16 单位。
空白、合并字符、控制字符、标签／实体内部和两个单位的标量不会作为一字探测目标。
没有合适目标时不改选偏移、不扩大范围。

工具提供两种需要单独授权的实验：

| 模式 | 最多进度 POST | 核对 |
| --- | --- | --- |
| `same` | 2 | 进入阅读、相同位置且零时长的上报，再读取位置。没有明确回执时仍为未确认，位置不变本身不证明写入成功 |
| `probe` | 4 | 上述两步之后，在同一章前进一个单位，独立读回，再有条件恢复原位置并核对 |

每次实际执行都重新准备上下文和签名，固定已预览的账号与书籍；
`--apply` 必须同时提供 `--mode`、`--book-id`、`--expected-owner`，不在写入模式下自动选书。
同位置／探测／恢复上报都固定 `rt=0`，进入阅读请求按现有协议不含时长字段。
身份、阶段顺序、请求目标、精确字段集、签名、位置、时长与发送上限在传输前再次核对。

独立读取最多四次以观察异步结果，不重发 POST、不续期、不换账号、不追加其他坐标试探。
HTTP／回执不确定的发送仍消耗名额。探测请求已被尝试时，即使异常或中断也先检查当前位置；
只有当前书籍／章 UID／偏移仍等于本次探测点，才发一次恢复。若已经回到原位则不重复写入。
读取到其他坐标时保留新位置并停止，不能覆盖其他阅读器的新进度。

服务器可能自行归一百分比等元数据：探测按书／章／偏移独立核对，恢复仍须核对原来的章节序号和百分比。
仅坐标已恢复而元数据不同，报告明确保持未确认，不为制造通过结果而再次发送。
这些检查不是服务端原子比较交换，不能识别另一个设备恰好写入同一坐标；
进程被强制结束、断电或恢复读取失败时，也不能保证自动恢复。

最近阅读时间、位置摘要或同步记录可能更新。本次写入前的摘要不能按既有二十字载荷原样往返，
工具明确标记这一点，并使用已核对原文目标的二十字摘要；不承诺恢复服务端历史记录或原摘要。
探测的目标是验证章节／偏移的写入与恢复，不累计阅读时长，也不修改书架／批注。

## 使用和证据

```sh
python3 scripts/verify_position_roundtrip.py
python3 scripts/verify_position_roundtrip.py --saved-session
python3 scripts/test_position_roundtrip.py
```

以下入口仅用于已经批准的具体实验，两个变量来自本机私有预览，不是凭据：

```sh
python3 scripts/verify_position_roundtrip.py --saved-session \
  --book-id "$ROUNDTRIP_BOOK_ID" --expected-owner "$ROUNDTRIP_OWNER_VID" \
  --mode probe --apply
```

本人授权只保留在原有项目钥匙串条目。选书及账号绑定只在任务内存中保留，不新增授权条目。
正文、完整位置、Reader 会话、签名、账号和书籍编号均不进入报告或普通文件；
读取响应后核对账号，并保存／回读合法的 Cookie 轮换。恢复不确定时明确保留未确认状态。

23 项离线检查覆盖默认零请求、显式授权参数、同书及零时长载荷、重新签名后的篡改拒绝、
账号变化、回执缺失、不确定发送、中断恢复、并发位置、服务器元数据归一、无效目标及隐私边界。
新增三项检查核对 Lua 私有管道、严格结果结构与失败信息不含私人内容。
历史[只读准备报告](validation-assets/2026-11-10/position-roundtrip-preview.json)保留原状。

## 2026-11-10 限定实验结果

本人回复“允许执行并核对恢复结果”后，使用 `dbb09d7` 中的工具执行一次 `probe`：
进入阅读、同位置上报、一字前进、恢复共四次 POST；同位置有明确回执，探测位置独立读回成功，
原书／章 UID／偏移以及章节序号／原始百分比均核对恢复。无 POST 重试、授权 POST 或检测到的并发位置冲突。
上报载荷均为 `rt=0`，进入阅读不含时长；本轮没有独立核对服务端时长统计。
原摘要没有按原值恢复，最近阅读时间及历史也不承诺恢复。该次实验授权已使用，不包含后续写入。

随后仅通过私有内存管道，把新鲜真实上下文的进入／同位置／探测／恢复四种载荷交给生产 Lua 协议生成器，
与 Python 逐字段比较通过。Lua 未获得 HTTP 客户端，HTTP 数为零，没有再次写入。
使用 `--saved-session --lua-command ...` 可单独执行此只读比较；它不能代替实际插件写后回读。
结果及工具摘要见[本次固定字段证据](validation-assets/2026-11-10/position-roundtrip-owner-authorized.json)。
原有 `upload_verified=false` 安全门保持，尚未启用通用原文坐标上传。

## 原生阅读器与实际上传服务的禁止发送预演

随后补齐 `verify_owner_progress_preview.py` 与配套 `--progress-preview` 原生验收入口。
默认离线；显式复用已保留授权时，先选定同书、同章、原位置及相邻一个 UTF-16 单位的唯一文字目标，
核对云端与 Reader 上下文、目录及原文字节，再从真实插件书架、详情「阅读」进入原生阅读器。
本入口没有 `--apply`，没有执行真实位置写入的分支。

插件经生产 `openSourcePosition` 导航原位置、相邻一字及原位置，逐点核对同一 EPUB 的原文来源、
DOM 锚点往返、锚点在当前页可见，以及仍为只读的保留目标；结束后恢复进入预演前的阅读位置。
分页引擎的 `getXPointer()` 可能返回页首，不能据此认定任意一字目标已正确定位。
本轮初次检查恰好复现页首与指定目标不同，随后改为检查精确文字锚点和保留的逻辑坐标，
没有把“跳到了同一页”当成字符位置核验，也没有把失败状态强改为通过。

每个已验证目标作为验收工具的显式输入交给插件实际 `ReadReport:upload_position` 服务，
使用它自己读取的新鲜同书 Reader 上下文和生产签名生成器。
这验证的是指定目标到上传服务的组合，不代表 `ProgressSync:capture_local()` 已切换为原文坐标。
传输前拦截器只为第一份进入阅读请求返回一次合成成功回执，让实际服务能够生成后续报告；
同位置、一字前进、恢复三份报告全部在真实 HTTP 派发前抛出受控停止。
三次服务调用均保持未确认，没有伪造进度上传成功或触发回读成功。
配套拦截模块没有获得原始派发函数，不能从预演模式切换为真实发送。

四份实际生成的请求及其签名上下文只经捕获的内存管道交给独立 Python 检查。
逐项核对阶段顺序、同书／章／序号／偏移、零时长、摘要、签名、令牌派生值和本次原生进程的时间窗口；
每份请求仍须通过既有严格校验器，数值型合法 Reader 计数器也保留其类型。
私有正文、位置、上下文和凭据不进入公开报告；原生临时配置仅在 tmpfs，结束后移除且工作进程回收。
失败只公开固定原因、阶段和行号，缺失私有回执不能被判为通过。
