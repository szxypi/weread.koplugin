# 原生位置书签两步验证准备

位置书签的生产界面、API 原型及独立坐标核对见[功能说明](cloud-bookmarks.md)。本批补齐实际原生执行器，
先从插件书架进入原生阅读，在滚动视口精确定位已核对的章首正文点，再通过阅读菜单「保存云端书签」调用生产界面。
当前视口、原文归档、单点范围和完整预览须与独立 Python 模型一致，不能把任意原文选区代替当前视口。
测试结束恢复原阅读模式和原文位置；实际手机／服务器历史不属于完整恢复保证。

## 发送范围

默认离线；`--dry-run` 在生产派发前拦截，零修改、零发送额度；`--apply` 启动前在独立原生书签钥匙串意图中一次保留两次额度。
只允许新建一条 type=0、style=0、原文单点范围的书签，以及删除这条新记录；不提交颜色或猜测的原生章节序号。
宿主不执行数据 POST，每步由宿主独立读取完整本人标记、想法、章节描述、书架标记与精确位置后才放行下一步。
根进程的 SQLite 限制器再次核对账号、请求正文、生产发送记录及新编号，先原子领取，再调用传输。
原记录编号不能作为删除目标，其他路径、其他章节、重复请求、旧意图重启均拒绝。
新建确认后还会通过「我的云端书签」原生列表定位回保存点，再进入删除确认。

未知结果、中断或宿主核对失败立即停止，保留待核对意图，不重发；临时原生配置被回收不等于清除了宿主发送记录。
对已派发但回执不明确的删除，`--resolve --expected-intent …` 仅在完整重建原计划、确认目标消失与原状态一致后清理，不发送任何修改。
Python 原型与原生书签、划线、样式和想法使用独立协议／额度，不能互相借用。

## 已完成核对

两种尺寸各 11 组封闭合成场景，共 22 组：正常、回执丢失、未创建、未删除、原记录被其他设备修改、
新增章节描述、宿主不匹配、宿主中断、延迟回读、禁止发送，以及最后标记／章节描述移除。
每组检查临时配置清理、工作进程回收、未知结果禁止重跑；不访问真实账号。
旧普通划线与四步样式执行器另在两种尺寸各回归正常流程，共四组。

真实只读准备在墨水屏书架遇到 HTTP 401，尚未启动原生进程、未保留发送额度。
按已有授权只续期一次，核对同账号 140 本书架与钥匙串回读；没有账号数据修改。
之后初两轮原生预演停在书架刷新：独立 Python／Lua 140 本、5 个分组的投影与实际 Lua HTTPS 三次只读请求均通过，
失败诊断限定为固定枚举与布尔值，没有保存响应、书名、编号或数据库异常。

最终发现只读预检更新了 wr_skey，而执行器向原生进程传入的仍是旧快照。
新增交接前的同账号核对、保存回读及有效快照替换，复用于书签、普通划线和样式执行器。
保存失败、读回不一致或其他会话替换均在派发／额度保留前停止；本轮没有再次续期或放宽书架解析。
修复后的真实禁止发送预演通过：插件书架进入阅读、当前视口与精确原文点、完整预览和生产确认控件一致，
发送前拦截一次，重复提交被阻止；12 次原生 GET、零数据／授权 POST、零额度保留。
原记录与 Web 位置一致，原阅读模式及本机位置恢复，工作进程与私有 tmpfs 配置清理通过；真实截图为零。

全部本地检查为 90 份 Python／1,084 项零跳过、221 组 Lua、618 个静态文件零警告／错误、620 个 Lua 语法、275 个 Python 编译，
另有四时区、命名空间、TLS 和 249 个生产文件的候选／源码一致性核对。
固定记录见[准备证据](validation-assets/2026-11-11/native-bookmark-trial-readiness.json)。

## 验收边界

本准备批次真实数据修改为零；后续实际两步必须使用新的一次性启动记录，并在每一步独立回读。
开发授权继续保留在钥匙串，正文与凭据仅经捕获管道／匿名描述符传递，私有临时配置在 tmpfs 中清理。
真实预演使用 600×800；1264×1680 使用合成数据，均为官方 KOReader v2026.07.1 Linux ARM64。
实体 KO2、非空真实集合写入、更多书籍／来源格式、多设备与整机断电仍待验收，集中性能专项未开始。
