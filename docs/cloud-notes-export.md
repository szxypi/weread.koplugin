# 导出已保存的云端笔记

打开一本书的「我的云端划线」「我的云端书签」或「我的云端想法」，选择「导出已保存的云端笔记」，再选择 Markdown 或 JSON。入口也可从「我的笔记本」进入。文件保存在插件数据目录的 `exports/notes/` 下，完成后显示路径。

导出使用当前账号、当前书籍在本设备保存的云端划线、书签和想法快照，不发起网络请求，不修改云端或本机笔记。当前列表的筛选和搜索不影响导出范围；确认框分别显示两类快照的条数，未保存或不可读取的类别会明确标出。需要更新或补齐数据时，可先联网分别刷新相应列表，再导出。

Markdown 记录书名、作者、快照保存时间、章节、划线／书签、想法、引用和可见性；JSON 同时保留划线样式、颜色及服务端记录时间。两种格式均表示不可用的快照，不把未保存当作空列表。导出不包含账号凭据、书籍编号、服务端笔记编号或原始坐标，也不作为重新导入或云端同步格式。它与[本机 KOReader 笔记导出](local-notes-export.md)互不替代。

导出在后台处理确认时的快照；取消、关闭列表、账号或阅读会话变化时移除本次未完成文件。文件排他创建，不覆盖已有文件；成功后保留供用户复制。存储失败时不会将半成品报告为成功。设备异常断电后的临时文件清理不在本次保证范围内。

每类最多导出 5,000 条已校验记录，单个文件上限 32 MiB；超过上限或写入失败会停止并清理本次文件，不截断后报告成功。

## 验证范围

模型和界面组件测试覆盖两类快照、单类缺失、空数据、Markdown 转义、JSON 字段过滤、账号变化、取消、写入失败和旧回调。普通书与导入书均在 600×800 和 1264×1680 两种 KOReader 模拟尺寸，从划线和想法入口导出 Markdown／JSON：在筛选只显示一条时，仍独立回读到全部 45 条当前快照和另一类的一条合成记录；新进程离线重开也完成导出，期间没有发起网络请求。这些界面测试使用合成笔记和临时配置，未读取真实笔记；实体 Kindle 尚未验证。见[脱敏记录](validation-assets/2026-11-19/cloud-notes-export.json)。

另对一本真实账号书籍只读获取 52 条云端划线／书签和 3 条想法，在隔离 KOReader 进程中用真实内容分别生成两种格式，只通过内存管道返回独立比较。JSON 的逐条字段及 Markdown 的引用和想法文本与独立读取一致；之后重新读取两类笔记及书架，结果不变。此次没有保存真实笔记文件、截图、账号凭据或正文日志，也没有账号数据写入或授权请求。该比较覆盖一册书的数据和格式模型，不代表真实笔记的界面导出或实体设备已验收。

本机组件测试可运行 `luajit spec/cloud_notes_export_spec.lua` 和 `luajit spec/cloud_notes_export_ui_spec.lua`；`python3 scripts/verify_cloud_notes_export.py` 默认离线，只有显式选择保存的会话和私有原生进程时才进行只读真实账号比较。
