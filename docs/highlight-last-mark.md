# 最后一条划线的删除确认

微信读书删除某章最后一条划线时，可能同时移除该章在划线列表中的派生索引。
此前原生规则要求删除后所有章节描述完全不变，因此会把已经成功的删除保留为待确认状态。
现在允许这一种索引移除：只有所选章节没有剩余标记、所选描述确实消失、其余描述完全一致，
并且划线集合恰好少了目标、完整本人想法未变时，才确认成功。
更改标题、移除其他章节、同章仍有其他划线、其他标记或想法变动仍不能确认。
创建与删除载荷没有扩大，SQLite 发送门槛及未知回执不重发规则保留。

## 真实发现与只读恢复

初轮使用已通过 CI 的 `4ca8c95` 执行实际原生选区保存和本人列表删除。
原生派发两次，创建由宿主独立确认；删除后生产服务没有解除 pending，执行器按约定停止，未重发。
随后独立只读检查确认目标已经消失，原有完整划线、想法、书架标记和原生位置均与基线摘要一致。
再按原计划重建原文、版本、目录和两通道位置，完整匹配后，只清除本机测试意图，没有账号数据 POST。
监督器删除了私有配置；另查 Linux 进程和 tmpfs，旧阅读器、工作进程及私有目录均不存在。
初轮原生中途停止，不作为导航恢复、正常审计或两步完整成功的证明。

另用一个独立两次计划，新建并删除一条新的普通测试划线，捕获的私有快照仅在内存与管道中分析。
真实观测为：删除前有所选章节描述，删除后描述消失、该章无剩余划线，其他描述、精确剩余标记与本人想法均未变。
原有 Python 与 Lua 生成的删除计划及失败判定完全一致，确认是同一条过严的规则。
这一独立实验两次 HTTP 200、逐步回读及最终两通道位置一致，测试划线和本机意图均清理。
服务端排序、历史及未返回字段不属于完整恢复保证。

## 修复与验证范围

独立 Python 模型先覆盖这个真实返回条件，再修正生产 Lua 的相同判断；不依赖 HTTP 回执直接判定成功。
新增只读实验恢复入口，要求指定意图、delete_pending 及完整原计划恢复；原文、目录、位置或原记录不一致时不清除。
其他实验仍会在划线测试待确认时停止；只读恢复仅豁免它正在核对的那条原生划线意图。

官方 KOReader v2026.07.1 Linux ARM64，600×800／167 DPI 和 1264×1680／300 DPI 共 22 组封闭合成运行通过。
新增空书籍一条划线的完整原生保存／列表删除；原有正常、丢失回执、无变化、并发修改、宿主中断、读取延迟、
派生索引保留和禁止发送场景均回归。全部私有配置清理、工作进程回收，真实账号写入为零。
81 份 Python／1009 项零跳过、213 组 Lua、598 个静态文件零警告／错误、600 个 Lua 语法、
248 个 Python 编译、四时区、命名空间和 TLS 核对通过。
生产候选仍为 241 个文件，本次生产变更仅在删除结果判断；实际安装内容与候选逐字节核对。

修复候选的真实预演在写入前遇到明确 HTTP 401，零占用额度、零数据修改。
保存了授权维护待确认记录后，仅续期一次，核对同账号书架及钥匙串回读；原刷新凭证保留。
续期后重新完成 1264×1680 原生禁止发送预演，实际请求与独立模型一致，原记录及精确位置未变。
授权维护计作一次授权 POST，和账号数据修改分别记录；没有对旧划线请求续期重发。
