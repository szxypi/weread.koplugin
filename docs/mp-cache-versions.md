# 公众号单篇刷新与已保存版本

文章列表新增「文章缓存与版本」，通过原生列表选择已缓存文章后，可阅读、刷新、查看已保存版本或导出。
文章行仍直接打开当前缓存；新增入口可通过 KOReader 的菜单按键操作，无需长按或网页。
刷新确认说明旧版正文及阅读记录保留。没有缓存的文章仍按原入口下载。

## 新旧正文与阅读记录

显式刷新使用既有、已真实验证的正文及匿名图片 GET，不新增接口或账号数据写入。
仍由后台进程下载、转换和暂存，沿用原有取消、账号／授权／阅读会话／目录变化保护，
登录失效最多进行一次确认后的续期与读取恢复，429 与验证不可用不循环续期。

首次下载的 `article.html` 保持兼容。显式刷新另存同目录内的 `article-<随机编号>.html`，
图片继续使用独立代次；旧 HTML、图片和 KOReader 的阅读记录文件不移动、不覆盖、不复制坐标。
当前版本由同文章目录内最多 128 字节的固定格式 `current` 记录选择，不执行其中内容，也不加载旧备份。
只有新正文及图片完整发布后，才排他写入、同步、核对临时选择记录，再原子改名并回读。
以后即使由普通下载入口进入，只要已有版本选择记录，也会保留旧版本并写入新路径。

下载期间捕获原选择记录、活动正文及受管目录身份。发布前再次核对，
其他操作修改选择记录或替换文件后，旧下载不能覆盖它；登录恢复时也不能重新绑定到外部替换的版本。
取消、正文／图片错误、最终正文或选择记录改名失败，保留此前的完整版本及阅读记录。
尚未被选择的新文件按身份清理；已被选择的完整正文及图片不因后续错误被删除。
不宣称对任意其他进程提供文件系统级事务或多文件断电持久性。

「已保存版本」将当前缓存列在前面，其他版本按保存时间列出。选择旧版打开原文件，
已有独立标记的版本由 KOReader 读取其位置、划线和笔记；有旧记录的未标记受管或标题 HTML／EPUB 先保留记录并明确选择恢复。
已打开旧版的「导出文章为 EPUB」
导出正在阅读的版本，不改为最新正文。新版的图片同样可导出为独立 EPUB。
正常刷新没有将旧文字坐标直接应用到变化后的正文，也没有删除其他版本的阅读记录；手动恢复另需明确选择与确认。

旧标题 HTML／EPUB 只在保存目录能明确关联单一文章身份时列入版本列表。
刷新这类缓存会保留旧文件和其阅读记录，并下载至新身份目录；歧义旧缓存仍按原规则提示重新下载，
不猜测其归属，也不自动迁移旧坐标。当前可选版本错误、损坏或缺失时不悄悄回退到其他正文。
明确恢复旧标题 HTML 时，标准本地图片复制至新代次，正文节点与文字保持；
原 HTML／图片及快照保留。旧 EPUB 恢复仍生成 EPUB，保留包内成员与压缩数据；原包和快照保持。

## 边界

- 每篇最多 128 个受管正文版本（HTML／EPUB），目录扫描最多 1,024 个条目；容量或读取异常停止，不静默截断后继续刷新。
- 选择记录、正文和受管父目录拒绝符号链接；版本文件名严格限制，不能指向其他文章或任意本机文件。
- 元数据仍由 KOReader 管理。随书、集中目录和按内容哈希三种位置的版本隔离、
  清理保留、新进程回读及正常保存方式切换迁移已在合成原生环境验证，详见下文；
  受管及旧标题 HTML／EPUB 的[记录保留与恢复](mp-legacy-record-recovery.md)已接入原生入口，其他资源格式与实体设备仍待验收。
- 旧正文和图片代次不自动删除；原生[文章缓存清理](mp-cache-cleanup.md)现可预览未引用图片及明确选择旧正文，
  确认后分批删除，保留当前／打开版本和阅读记录。[中断下载修复](mp-download-recovery.md)新增可靠记录清理及未知目录的明确隔离／恢复；
  不按时间猜测归属，整机崩溃／断电及剩余清单继续待验收。
- 真实公众号目录仍受 `-2041` 限制；本项复用已有正文／图片协议实证，
  所有刷新、版本菜单、变化正文及笔记截图均使用合成数据，未重复请求真实账号。

## 验证

- `spec/mp_cache_versions_spec.lua`：选择记录、不可变文件、路径／符号链接、替换及容量边界。
- `spec/mp_article_actions_spec.lua`：原生操作、保存确认、取消、过期菜单及账号／会话／目录变化。
- `spec/mp_export_ui_spec.lua`：已有导出保护及正在阅读旧版本的来源保持。
- `spec/koreader/mp_versions_smoke.lua`：实际后台 HTTP、原生控件、文件系统、KOReader DocSettings、CRE 和 EPUB；
  新旧正文不同、旧阅读记录字节保留、新文件不复制旧坐标、旧标题缓存保留、取消／选择记录失败与外部替换保护。
- `scripts/check_mp_versions_package.py <原生运行目录>`：独立核对两份 EPUB 的 ZIP CRC、XML／manifest／spine、
  对应的新旧正文及 PNG CRC／像素；不打开钥匙串或访问账号。

最终运行证据及适用限制另记于[本轮验证](validation-2026-11-09.md)，
版本与回归报告见[去敏记录](validation-assets/2026-11-09/mp-versions-runtime.json)。
原有缓存身份规则见[文章缓存说明](mp-article-cache.md)。

## 随书、集中目录与哈希记录

KOReader 的哈希位置采用抽样字节计算文档摘要。已在官方 v2026.07.1 实际复现：
两份等长文章只在未抽样的中段文字不同，摘要仍相同；新版因而读到了旧版位置和划线。
这属于阅读记录身份冲突，不能只靠给新版换文件名解决。

原生后台下载现在把本次不可变缓存的 16 位编号写入 HTML 开头的受限元信息，
位于第一个抽样块内。纯文字文章和同样正文的再次下载也使用独立编号，
新版不会因上述抽样盲区沿用旧记录。编号不进入正文、可见标题或云端身份，
不会修改 KOReader 的全局保存偏好或哈希算法，也不扫描整篇正文计算额外摘要。
编号在发送正文请求前验证，非法编号不能发送请求或注入 HTML。

只影响后续原生下载生成的新文件。旧缓存及其笔记不重写、不移动，
已经发生共享的旧哈希记录不自动拆分或猜测坐标。
后续实测已复现：直接打开旧文件并迁移保存位置，可能带入另一份的位置，并删除共享主记录及备份。
当前受管及无歧义旧标题 HTML／EPUB 的旧版本入口已先持久保留可用记录，再由用户明确选择，恢复至独立副本。
这避免依赖共享记录持续留在原位置；正文与记录回读成功后才切换当前缓存，见[原生恢复说明](mp-legacy-record-recovery.md)。
文件管理器的常规文档打开入口现已接入[相同保护](mp-legacy-record-recovery.md#从文件管理器打开)，
限已索引且可明确关联的文章；目录信息预读、启动直开和阅读器内直接切书仍需补齐。
明确删除旧正文后保留记录文件不等于仍可打开该正文，重要笔记应先导出。

`spec/koreader/mp_metadata_smoke.lua` 在三种保存位置分别实际下载管线生成三份合成版本：
原文、中段修改及相同正文再次下载。对照未标记文本仍能复现抽样碰撞；
标记后的三个路径及记录互不混用，旧笔记回读、原生历史菜单、CRE 正文、
明确删除旧正文和中断暂存修复后记录字节保持通过。
该场景的传输使用本机函数返回合成响应，不代表联网下载或后台心跳验收；
同轮原有真实后台 HTTP 下载、取消及 EPUB 场景另行回归。

完整核心运行后，再在同一个隔离配置下启动全新进程：

```sh
KO_HOME=/path/to/run/profile WEREAD_EVIDENCE=/path/to/run/evidence \
  /path/to/koreader/luajit /path/to/repo/spec/koreader/mp_metadata_reopen.lua
```

命令需在该 KOReader 运行目录执行。它重新计算哈希并读取仍保留的两份版本，
核对三种位置的独立划线／位置和本机待上传状态，没有微信读书接口请求。
两尺寸结果及修复前后对照见
[去敏记录](validation-assets/2026-11-09/mp-metadata-runtime.json)与[本轮验证](validation-2026-11-09.md)。
后续的保存方式切换验证见下文；旧共享记录恢复和实体 KO2 文件系统仍待验收。


## 阅读器实际打开后的保存方式切换

`scripts/test_mp_metadata_runtime.py` 在全新隔离配置中安装候选包，
只加载该插件，使用真实 ReaderUI、CRE 和 KOReader 自带保存位置菜单项的实际回调。
覆盖随书、集中目录、内容哈希三种位置之间的六种定向切换。
每种切换通过原生文章下载管线生成三个独立版本：旧正文、中段修改及相同正文再次下载；
正文和图片读取由本机合成函数提供，不访问真实微信读书。

各版本先在原位置实际打开，移动到不同页面，使用内置书签入口添加书签，
从 CRE 选出实际范围并通过阅读器批注模块添加划线／附注，正常关书保存。
选择新的保存方式后，实际阅读器重新打开各版本：核对完整记录投影、保存位置及目标在当前页可见，
正常关书触发 KOReader 的记录迁移；再核对新位置、旧候选文件移除、HTML 摘要不变，
并重新读取磁盘上的插件配置，确认公众号容器进度和待上传记录保留。

全部迁移完成后退出进程，另起全新进程再次按各版本目标位置打开并正常关书，
核对位置、书签、划线和附注，覆盖后续迁移对先前版本的影响。
每种尺寸保留 18 个版本、完成 54 次实际 ReaderUI 打开；
600×800／167 DPI 和 KO2 对应 1264×1680／300 DPI 均通过，合计 108 次。
两份候选包各 173 个安装文件与源码／安装目录一致，零重绘失败，
本地服务未收到请求。[去敏报告](validation-assets/2026-11-09/mp-metadata-migration-runtime.json)仅含状态、数量和保存位置。

```sh
xvfb-run -a python3 scripts/test_mp_metadata_runtime.py \
  --koreader /path/to/runtime \
  --run-dir /path/to/new-run \
  --width 1264 --height 1680 --dpi 300
```

工具自动执行迁移与新进程回读两个阶段；全部书籍、正文及批注为合成数据。
本项属于既有 KOReader 迁移行为的验收；旧共享哈希记录恢复，以及实体 KO2 的文件系统、按键与触摸仍待验收。
