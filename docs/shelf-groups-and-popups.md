# 书架分组与弹窗生命周期

关闭书架后，旧分组回调曾能重新打开已经退出的页面；分组和选项弹窗也没有随所属书架关闭。
此外，封面或进度完成后的整页重绘会打断弹窗。关闭后的回调已用隔离组件测试复现。

现在分组、选项、排序、筛选和搜索共用所属书架的弹窗生命周期：

- 同一本书架只保留一个弹窗，替换、关闭或重开书架时关闭旧弹窗。晚到和重复回调不继续操作。
- 用户操作核对当前书架、账号／登录代次、阅读文档／会话、书架快照和读取通道；旧选择不修改新页面的设置。
- 封面和进度照常后台读取、保存；弹窗打开期间延后整页重绘。取消后显示新数据；完成选择后保留用户的新页面，旧重绘不能覆盖它。
- 正常分组不再因所有普通成员暂不可用而消失，仍可显示为空组。明确只有公众号容器的组继续由公众号入口承载。

本项是本机分组浏览与交互完善，不包含云端分组创建、改名、移动或删除。目录、正文、同步及书架写入权限没有扩展。

参考项目将系统「归档」作为未分组书籍的承载容器，见其[分组接口说明](https://github.com/tanyaqiongcode/weread-shelf-organizer/blob/main/references/api.md)。当分组编号唯一且为 `1`、名称为「归档」时，插件保留该分组入口，但不会仅因为书在其中就将它排除出「未分组」；同一本书若还属于其他分组，仍按其他分组处理。只有编号或名称匹配，或编号重复时，按普通分组处理，避免误判同名用户分组及有歧义的快照。

两种屏幕尺寸的实际 KOReader 页面已使用合成书架验证系统分组入口、未分组和重叠成员；真实账号的原生与网页书架均未返回编号为 `1` 的分组，常规分组的 Python／Lua 投影一致，未修改账号数据。因此系统分组的实际服务端语义与实体 Kindle 仍待验证，见[记录](validation-assets/2026-11-18/shelf-system-archive.json)。

## 分组信息不完整时保留书架

刷新响应没有 `archive` 字段时，不能据此认定用户没有分组。已有完整书架时，插件保留上次完整的书籍和分组，不用新书籍列表拼接旧分组，也不覆盖离线缓存；首页刷新同样使用该完整快照。首次使用且没有完整快照时，可临时浏览返回的书籍，但会提示分组缺失，临时列表不会写入离线书架。服务端明确返回空分组数组时，仍按真实空分组处理。

当 JSON 解析器能区分空数组和空对象时，原生及标准通道拒绝把空对象当成空书架、空分组或空成员数组。书架成员、读完和私密状态操作也要求读到明确的分组数组，避免用缺失分组的结果覆盖完整缓存；已经发送但回读不完整的成员修改保留为待确认，不自动重发。

标准连接现在也会检查每本书的标识和书名、重复书籍、分组成员及大小上限。响应不合格时尝试已有的网页书架回退；网页连接不可用时显示错误并保留原有书架。校验通过的标准响应仍保留其他书籍资料，未返回分组时继续按上述不完整规则处理。组件测试覆盖重复编号、缺失字段、无效成员及网页回退；两种模拟屏幕的打包插件使用重复编号响应核对了当前书架及 SQLite 缓存保留。测试使用合成数据，实体 Kindle 与真实异常响应尚未验收。

部分标准书架响应可能混用数字和字符串编号。较大的数字经 Lua 默认字符串转换可能变成科学记数法，旧版 JSON 写入还可能舍入，使分组漏书或将缓存关联到错误编号。现在标准连接在保留其他资料的同时将可精确表示的编号转换为十进制字符串，SQLite 写入也以字符串保存书籍和分组编号。旧书籍缓存只有在 JSON 数字与 SQLite 主键的序列化结果一致时才从主键恢复精确编号；冲突的字符串记录不用于书架或状态查询。旧分组缺少独立编号凭据，对可能已舍入的 15 位及以上数字不猜测其身份，相关成员可能暂时无法在分组中显示，刷新书架后可重新获取。

两种屏幕尺寸的实际 KOReader 界面使用合成数据核对标准连接、旧版舍入缓存、分组和全新离线进程；测试包含原 SQLite 主键恢复及不匹配分组成员的保护。随后真实账号的正常书架在原生／网页两通道及 Lua 分组投影只读核对一致；墨水屏登录自然过期后续期一次并保存，没有账号数据修改。该真实核对不包含异常编号或实际界面／SQLite 交互。相关记录见[编号验证](validation-assets/2026-11-20/shelf-mixed-identities.json)；真实异常响应及实体 Kindle 仍待验收。

旧分组存在无法确认的成员时，不能把剩余书籍直接认定为未分组。受影响的分组会标示「信息不完整」，分组选择菜单提示刷新书架；暂不提供未经核实的「未分组」结果。若之前选择了「未分组」，单选回到全部书籍，多选保留选择并显示全部书籍；完整书架重新获取后可再次使用。系统「归档」仅承载未分组书，其无法确认的成员不改变其他分组的归属判断。

两种尺寸的实际 KOReader 使用舍入后的合成 SQLite 分组，核对不完整提示、单选与多选回退、完整刷新恢复和新进程离线重开；没有访问真实账号或修改云端书架。补充多选菜单检查时发现一处翻译调用错误，修正后两尺寸重测通过。异常真实响应及实体 Kindle 仍待验收，见[验证记录](validation-assets/2026-11-20/shelf-unknown-membership.json)。

两种模拟屏幕的实际 KOReader 界面及 SQLite 用合成数据核对了书架／首页保留、首次临时列表、既有未保存完整快照和新进程读取；没有发送 HTTP。空数组、缺失字段、错误类型、状态修改前后不完整回读以及账号隔离另经组件测试。实际账号在这些异常返回条件下及实体 Kindle 尚未验收。

正常响应另用真实账号只读核对：原生授权失效后仅续期一次并保存；原生 Lua 及 Python 的原生／Web 书架投影一致。最初的组合核对因网页读取后会话更新，而执行器仍收到旧会话而失败；修正验证工具在交接前保存并回读已核对的同账号会话后通过。续期后先前未确认的分组试验经只读复查，测试书、原书架与分组状态保持；没有重发分组请求或修改账号数据。该结果不证明异常响应在真实账号中发生过。

## 书架搜索

书架搜索匹配书名、作者及书籍编号，仍受当前分组和筛选条件约束。旧缓存或不完整条目缺少作者等字段时，搜索现在会继续检查其余字段；编号既支持文本，也支持数字形式。输入前后多余空格会被去掉，文本中的空格保留；仅输入空格会清除搜索词并显示当前范围内的书籍。

缺失字段、两种编号字段、数字编号、大小写和筛选范围经组件测试；两种屏幕尺寸的实际 KOReader 分组页面另使用合成条目，经过原生输入框搜索并在新进程离线重开后重复核对。实体 Kindle 尚未验收，见[记录](validation-assets/2026-11-17/shelf-search-sparse-fields.json)。

书名、作者和编号现在使用 KOReader 的 Unicode 大小写折叠及兼容字符归一：例如组合形式的重音、德语 ß 和全角字母可与对应输入匹配。搜索仍限定于当前分组和筛选范围；无法使用该组件或遇到无效文本时保留安全的基础匹配。两种模拟屏幕的原生输入框和新进程离线重开已使用合成书目验证，见[记录](validation-assets/2026-11-18/shelf-unicode-search.json)。

## 书架排序

书架可选择按作者升序或降序，继续适用于当前分组、筛选和搜索。作者名称会去除首尾空格，并使用与书架搜索相同的 Unicode 大小写及兼容字符归一；例如大小写和全角形式相同的作者保持原书架顺序。排序按归一后的字符顺序进行，不转换中文拼音。作者缺失或无效的书排在同一置顶层级的最后；已确认置顶的书仍优先显示。旧记录只有 `authors` 文本时，排序和搜索也会使用该字段。选择保存在设备上，不修改云端书架。

两种屏幕尺寸的原生书架及新进程离线重开验证了作者排序、同名稳定性、缺失作者、置顶和分组搜索；排序菜单已用合成内容绘制检查。真实账号书架也在两尺寸的隔离原生界面完成正反序及离线重开核对，没有账号数据写入或私人截图；该只读验收在排序期间暂停封面和进度的后台读取。实体 Kindle 尚未验收。

书名正序和倒序现先去除首尾空格，并使用与书架搜索相同的 Unicode 大小写及全角归一；归一后相同的书名保留书架顺序，空书名排在各自置顶层级的最后。中文仍按字符顺序而非拼音排序。两种模拟尺寸的原生分组页面已验证正反序、全角字母、置顶、空书名和离线新进程；实体 Kindle 尚未验收，见[记录](validation-assets/2026-11-20/shelf-title-sort.json)。

按时间或书名排序时，相同值的书籍保留原书架顺序，避免重建或翻页后同值书籍互相换位。明确置顶的书仍位于前面，同样保留相同值之间的顺序；排序不改写云端书架顺序。旧缓存中无法识别的时间按未记录处理。

四种排序方向、相同值、置顶、混合时间和源列表不变已通过组件测试；两种模拟屏幕的实际 KOReader 页面使用 48 本合成书核对时间／书名排序、置顶和翻页，并在新进程离线重复验证。实体 Kindle 尚未验收，见[记录](validation-assets/2026-11-17/shelf-stable-sort.json)。

旧缓存或服务端数据中的阅读时间可能是数字字符串，也可能为无效类型、非有限数或超出日期范围的数值。书架列表和旧版列表现在安全显示可识别日期；无效值不显示日期，按未记录时间稳定排序。首页最近阅读也忽略超出范围的云端及本机时间，避免异常记录排在最前。阅读百分比、读完和私密标记仍按原规则显示。两种尺寸的实际 KOReader 书架使用合成数据完成 SQLite 回读、列表绘制和排序检查；设备日期接口失败及旧版列表另经组件测试。未注入真实账号异常数据，实体 Kindle 尚未验收。

按最近阅读时间排序时，书架与首页一样比较云端时间和当前账号在本机打开书籍的时间，取较新的有效值；离线打开后返回书架也会重新排序。列表没有优先显示的阅读百分比或读完状态时，日期采用同一时间。账号或书籍身份不匹配的本机记录不会参与，明确置顶与相同时间的稳定顺序保持不变；该处理不改变云端时间或书架顺序。两种模拟尺寸的实际原生书架以合成记录验证了打开记录、返回重新排序、账号切换及全新离线进程重开；真实账号组合和实体 Kindle 尚未验收。

## 同时查看多个分组

书架顶部的内容选择菜单提供「多选分组」：勾选多个分组后选择「应用所选分组」，书架显示这些分组的合并结果，同一本书只显示一次，并继续遵循当前排序、筛选和搜索。选择「全部书籍」或在多选菜单中清除并应用，可恢复完整书架。

多选结果按微信读书账号保存在本机，离线或重启后仍可使用；取消多选菜单不保存改动。若分组快照不完整、所选分组消失或标识不唯一，插件保留原选择并显示全部书籍，避免遗漏书籍；在多选菜单中可取消「不可用的已选分组」。已选「未分组」在最后一本书移入其他分组后仍作为空分组保留。保存失败时维持原选择并提示。该功能不修改云端书架或云端分组。

单选也会核对分组标识：若刷新后的两个分组共用标识，之前的单选失效并返回全部书籍，菜单标出「不可用」，点击时提示刷新；同名且有不同标识的分组仍可分别选择。不会把有歧义的标识当成第一个分组，也不会沿用旧的分页结果。两种尺寸的实际 KOReader 界面已用合成数据验证，包含点击提示和新进程离线重开；实体设备尚未验证。合成界面：[600×800](validation-assets/2026-11-18/shelf-duplicate-groups-600.png) · [KO2 尺寸](validation-assets/2026-11-18/shelf-duplicate-groups-ko2.png)。

单选「未分组」时，若最后一本未分组的书移入其他分组，刷新后保留空结果；之后有书再次变为未分组，结果随之恢复。两种尺寸的实际 KOReader 页面已使用合成书架验证这一变化，不修改云端书架；实体 Kindle 尚未验证。范围见[验收记录](validation-assets/2026-11-18/shelf-single-ungrouped.json)。

两种模拟屏幕尺寸的实际 KOReader 菜单、分页选择、取消、缺失分组、保存及新进程离线恢复已用合成数据核对。真实账号的隔离配置也只读核对了多选结果及离线操作；之后补充的空「未分组」边界仅经合成数据验证，实体 Kindle 仍待验收。
