# 官方译文请求的单章计划

阅读语言菜单现提供“请求本章官方译文（试验功能）”。它会核对当前章节、会员与权限、两端阅读状态和书架，再请求单章译文；实际收到译文后交给已有译文下载流程，生成中则提示稍后下载。该流程已通过合成服务和 KOReader 模拟测试，但合格正文的真实生成结果尚未验证。
曾对后经核对为版权页的样本发送一次真实生成请求，返回停止但不可用；该记录已消费且不可重放。
现成云端译文的[独立副本下载与离线重开](translation-fetch.md)已另行接通，不代表缺失译文生成已经验证。
已有译文的原生双语显示继续见[显示说明](official-translation-prototype.md)。

Python 重新实现单章计划及回执解释，没有迁移上游自动续期和重复请求流程。

Python 协议试验只接受明确的付费会员、EPUB、同账号、目录中唯一且明确免费／已购买的英文正文章节；原生入口同样检查会员、章节权限及正文，但不以英文筛选作为通用可译性判断。
计划绑定书号、章号、来源版本、译文版本、当次授权，以及目录、原文、两端位置／字段存在性、逐书计数和书架摘要。
会员身份不把未知价格变成免费；原文必须实际存在；正文已有译文时不创建“缺失译文生成”计划。
已知版权／目录／封面／扉页不作为样本；正文还需实际英文词汇与字母，不以目录字数替代内容。
未知标题下的长链接目录也排除。此筛选用于协议试验，不能当作通用语言或所有章节的可译性判定。
`hasTranslated`／译文字数仍只是元数据，不代替译文内容核对。

纯模型生成的请求只包含当前章，`reference.texts` 明确为空数组，`freeTrial=0`。
不携带下一章、购买、试用或阅读时长请求。
模式修改 `GET /trans/pdfepub` 与生成 `POST /en/bookread` 在语义上都是服务端操作；只读准备器没有这两个网络通道。

每书一批最多检查四个明确免费／已购买的正文章节，`--chapter-offset` 可在权限筛选和排序后选择后续批次。
偏移不扩大章节权限，也不影响已保存计划的准确章号复核；超出范围时不重复之前的章节。

基线区分已有阅读记录和明确未返回阅读位置的响应。已有记录仍要求完整的三项原生时长计数。
另一类只接受同书、明确四字段的服务端响应，两端必须都没有位置；保存实际书籍信息和其中返回的时长字段，
不生成零进度点，不把缺失计数补零。两轮原文、目录、字段存在性／值、完整书籍信息与书架必须一致。
混合位置状态、空响应、错误、错书或未知类型均不建立计划。这一基线仅用于译文操作准备，不改变位置上传或首次同步的要求。

## 回执与不可重放

独立钥匙串范围最多领取一次模式操作和一次生成请求；先持久保存领取，再允许调用方派发。
原始有界 JSON 回执先保存，之后才解释成功。未知／拒绝／错书回执保持可读，不批准后续操作；
进程中断、回执丢失或重复调用均不重新领取。
两份回执及计划总大小受实际 64 KiB 钥匙串边界限制，单份回执最多 24 KiB。

模式操作必须明确 `succ=true/1`；存在的书号／账号必须与计划一致。
生成状态区分等待、已停止但不可用、版本就绪；错误码、错误章号、重复章号、版本倒退、未知类型或冲突包裹均不接受。
版本就绪要求明确停止以及当前章正译文版本，仍必须另行取得实际非空译文才能确认下载。
当前单次范围不提供轮询重发或未知结果恢复额度，真实状态协议验证后再实现有界接续。

## 原生请求基础

原生 Lua 模型限定一个章节、空参考文本和 `freeTrial=0`，并检查账号、书籍、章节及服务端状态。
原生只读预检现可连续两次读取会员、书籍信息和完整目录，核对同一账号、EPUB 版本、目录摘要和指定章明确免费／已购；
缺失或冲突的会员、权限、章号和版本均不能通过。预检只证明读取许可，不能替代正文、基线或派发前的再次检查。
账号隔离的 SQLite 记录先以完整同步提交领取，再允许调用方派发；模式操作和生成操作各只能领取一次。
进程中断、登录变化或回执不明时保留已领取状态，不自动重发。只有 HTTP 200、响应完整且业务回执明确时才能推进记录。
记录只保存计划摘要、操作状态和有限结果类别，不保存凭据或原文；`ready` 仍仅表示版本状态，必须独立获取非空译文才算实际可读。

原生入口在后台执行预检与派发；限定派发器只有在新鲜原文与账号基线核对、且持久领取成功后才能发送一次请求。原生只读预检也会校验当前 EPUB 的封存原文与渲染章节，两次读取云端同章并比较字节摘要，
在读取前后重新核对权限及目录。若云端已有非空译文则报告可下载；若无译文，只有本地与云端原文完全一致且有正文时才返回原文已核对。
预检不上传正文，也不写入阅读进度。派发器对回复使用 8 KiB 上限、严格 JSON 和重复键拒绝；超时、错误或无法解释的回复保留已领取状态，不自动重发。未发送且已过时的计划可安全替换；模式修改已有明确成功回执时，可在重新核对后继续生成，已经领取但结果不明的请求不会被覆盖或重发。
收到完成或准备中的回执后，仍需独立读取实际译文，并核对原文文本及两端阅读状态和书架成员／标记／分组；可用时转入独立译文副本下载。此检查不保证所有服务端历史字段未变化。
本地测试不证明真实服务端支持生成；真实缺失译文、不同书籍和 Kindle 真机仍需验证。
