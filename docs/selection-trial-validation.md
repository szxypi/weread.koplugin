# 真实新选区的原生私密想法三步

已在一本普通数字书号的 XHTML 书籍中，完成新选区的实际原生私密想法新建、编辑和删除。
选区与原有云端标记不重叠，完整引用和请求与独立 Python 原文模型一致。
用户已授权直接继续本轮开发和验证；本次仍按一个独立计划、最多四次修改执行，没有复用此前已消费的三次许可。

## 实际执行与清理

1. 使用当前候选重新运行一次禁止发送预演，核对原文、目录、书籍版本、本人想法、划线、书架标记和两通道位置未变。
2. 启动前在独立钥匙串意图中一次占用全部四个可能的修改额度；原生生产编辑器新建一条私密测试想法。
3. 宿主独立完整读回，核对新编号、私密属性、章节、原始范围、引用和测试文字，以及原有记录，之后才允许原生编辑。
4. 再次独立核对后，原生删除该新记录；删除之后，宿主再次独立核对。
5. 删除后的独立读取没有发现新增划线残留，跳过 Python 条件清理；最终再次核对原记录及原生／Web 精确位置。

实际恰好 **三次原生账号数据 POST**，每步均独立确认，没有写入重试或授权续期。
没有发送第四次 `/book/removeBookmark` 请求，因此该接口仍未获得真实写入验收，不能据此接入生产 Lua 划线删除。
这些观测也不证明服务端从未产生过临时关联划线，只证明删除后的独立读取没有新增划线残留。

原有想法、划线和章节描述、书架标记及精确位置均与基线一致，没有新增章节索引。
测试想法已消失，一次性意图清除后又由新实例确认不存在；四个已占用额度不退回，也不能用于重跑旧测试。
服务端排序、历史及未返回字段不属于完整恢复保证。
