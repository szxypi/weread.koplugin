# 我的笔记本

“工具 → 微信读书 → 我的笔记本”集中显示账号下有笔记的书籍。选择书籍后可以分别进入已有的云端划线、想法和书签页面；也可在首页设置里添加“我的笔记本”快捷入口。笔记正文的显示、搜索、原文定位及编辑仍由原有单书页面处理。

列表支持按书名、作者或书籍编号搜索；搜索忽略首尾空白，并复用书架的大小写及 Unicode 匹配规则。可切换原有顺序或按笔记总数从多到少排列，总数为划线、想法／点评和书签数量之和；数量缺失的书排在数量已知的书之后，同数保留原顺序。搜索和排序仅作用于已保存的列表，不联网、不改写云端或缓存；退出列表后恢复默认视图。

“本机想法草稿”可跨书查看并继续编辑；选择后自动进入该书的划线或想法列表，核对草稿版本及原引用后恢复。选区草稿还会核对本机原文；所需引用或文件不可用时保留草稿。草稿仍需用户主动提交，联网时沿用原有云端预检与回读。

“搜索所有已保存笔记”可跨书检索当前账号在本机保存的划线和想法，包括不在已保存笔记本列表中的快照；可按笔记内容、原文或已保存的章节名匹配，并直接打开对应笔记。长内容的结果预览从命中位置附近开始，优先显示匹配内容，右侧显示笔记类型和书名；原文不受修改。搜索不联网，尚未缓存的笔记不会出现在结果中；结果会显示已检查数量、笔记本列表中尚未保存的快照数量和读取失败数量。最多显示 200 条，达到上限时提示结果可能不完整。标记和想法快照各最多保存 5,000 本、各受 32 MiB 数据总量限制；切换账号、关闭页面或取消时会停止当前搜索。

“保存所有笔记供离线使用”按笔记本列表原顺序读取每本书的云端标记（包含划线和书签）及想法，逐项保存后可离线搜索。一次处理当前列表中可识别的书，笔记本列表最多支持 5,000 本；不支持的书会在结束时计入跳过数量，进度以每本书两项计算。保存可随时取消，已完成的项目保留。读取失败、登录续期失败或本机空间配额不足时停止，已保存的笔记不会为本次批量操作被淘汰；联网后可再试。明确的授权过期可按现有方式续期一次，仅继续未完成项目。保存标记后，当前阅读器中同一本书的标记图层也会更新。此功能只读取云端笔记，不提交标记、想法或阅读进度。

列表只保存书籍标识、标题、作者、数量、排序和读取时间，按账号保存在本机数据库。第一次需要联网和墨水屏授权；成功保存后可离线打开。再次联网时可手动刷新；授权过期时可使用现有续期流程。读取失败、数量不完整或保存失败时保留上一次缓存。列表中不支持云端笔记的书籍会显示提示。

## 验证与限制

真实账号只读探测中，服务端对 `count=2` 和 `count=100` 返回了相同的 15 本书，返回总数与列表长度一致。以第一本书的排序值传入 `lastSort` 后，墨水屏接口仍返回完整列表，不能据此假定它与 Skill 接口的游标分页行为相同。暂未证明其他账号的分页行为：如果服务端报告还有更多记录，或总数与返回数量不一致，插件会拒绝覆盖原缓存，而不会显示不完整结果作为完整列表。

模型和界面测试覆盖了空列表、格式错误、重复书籍、数量不完整、网络错误、取消、缓存写入失败和账号切换；模拟 KOReader 的 600×800 与 1080×1440 两种尺寸中，45 本合成书籍经完整插件加载、真实菜单、三个笔记入口及 SQLite 验证，另以真实账号的 15 本书验证原生 HTTPS 读取结果、逐页展示、三个单书入口、账号隔离和全新进程离线重开。单书入口在离线状态下核对导航，并未在本次测试中重新读取单书笔记内容；单书内容另有独立验证。测试只读，未修改笔记或书架，临时配置及缓存位于内存文件系统并已清理。尚未在 Kindle Oasis 2 实机上验证本入口。

搜索与排序另在 600×800、1264×1680 两种模拟尺寸通过 45 本合成书及真实账号 15 本书的原生界面和离线重开；包含搜索结果、清空、按数量排序及恢复原序，操作期间没有额外网络请求。测试覆盖筛选与排序组合、缺失数量、相同数量、输入过长、关闭后的旧回调以及后台刷新期间输入。真实样本未覆盖所有语言、异常数据及实体设备。

跨书笔记搜索在上述两种尺寸以合成数据和真实账号的划线、想法各一份快照验证：均能搜索并打开目标笔记，全新进程离线重开后再次通过；搜索期间没有额外网络请求。真实内容仅用于内存文件系统中的临时配置，验证后已清理；测试只读取账号数据，未修改云端笔记。尚未在 Kindle Oasis 2 实机上验证该功能。

跨书草稿入口已在 600×800 和 KO2 尺寸的合成原生环境验证：离线恢复已有划线草稿、全新断网进程恢复选区草稿、待核对状态不重发，以及账号／引用／草稿版本变化保护通过。原始截图见[小屏](validation-assets/2026-11-20/cross-book-drafts-small.png)和 [KO2 尺寸](validation-assets/2026-11-20/cross-book-drafts-ko2.png)，其中部分表情显示缺字框；后续已增加列表局部字体回退，修复后的合成截图见[小屏](validation-assets/2026-11-20/note-list-font-small.png)和 [KO2 尺寸](validation-assets/2026-11-20/note-list-font-ko2.png)。真实账号的此入口及实体设备仍待验收，见[记录](validation-assets/2026-11-20/cross-book-drafts.json)。

长笔记命中预览已在 KOReader v2026.07.1 的 600×800 和 1264×1680 合成环境验证：核对实际屏幕字形、跨书结果打开、离线重开，以及全角字符、组合重音和大小写折叠；本次未访问真实账号。超长搜索词或较窄界面仍可能因单行空间而省略部分文字，打开结果可查看完整笔记。实体 KO2 尚未验收。

批量离线保存已在两种模拟尺寸的实际原生菜单、后台进程、合成接口及 SQLite 中验证两本书的四项保存、取消后保留已完成项目，以及全新离线进程读取；原有笔记表的当时 64 本及总容量上限另经真实 SQLite 回滚测试。账号变化、错误响应、一次续期、取消续期及阅读器图层通知经组件测试，见[合成验证记录](validation-assets/2026-11-20/notebook-bulk-save.json)。

移除 64 本数量限制后，两尺寸的原生流程另用 65 本合成书完成 130 项保存和离线重开；真实 SQLite 使用 130 本合成书验证两类快照保存及跨书搜索末尾书籍，并核对空间不足时回滚。每类 32 MiB 的原有总容量上限保持；达到该上限仍会停止并保留已保存内容。5,000 本全量、真实账号超过 64 本及实体 Kindle 未验收，见[记录](validation-assets/2026-11-20/notebook-bulk-large.json)。

真实账号另在两种模拟尺寸从原生菜单保存 15 本笔记本的全部 30 项，其中包含一本导入书；每个尺寸各发起 30 次笔记读取。全新离线进程逐项核对缓存内容摘要，离线读取没有联网。请求限定为已核对笔记本的本人标记和想法，账号数据及授权请求均无写入；笔记和凭据只经内存管道及隔离内存文件系统处理，临时配置已清理。本次没有遇到真实限流、取消或授权过期，实体 Kindle 仍待验收，见[脱敏记录](validation-assets/2026-11-20/notebook-bulk-owner.json)。

只读探测：`python3 scripts/verify_notebook_catalog.py --saved-session`；不带参数时不会联网或读取本机凭据。探测报告只包含字段、数量和校验结果，不保存书籍名称、内容或凭据。
