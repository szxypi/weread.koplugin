# 我的笔记本

“工具 → 微信读书 → 我的笔记本”集中显示账号下有笔记的书籍。选择书籍后可以分别进入已有的云端划线、想法和书签页面；也可在首页设置里添加“我的笔记本”快捷入口。笔记正文的显示、搜索、原文定位及编辑仍由原有单书页面处理。

列表支持按书名、作者或书籍编号搜索；搜索忽略首尾空白，并复用书架的大小写及 Unicode 匹配规则。可切换原有顺序或按笔记总数从多到少排列，总数为划线、想法／点评和书签数量之和；数量缺失的书排在数量已知的书之后，同数保留原顺序。搜索和排序仅作用于已保存的列表，不联网、不改写云端或缓存；退出列表后恢复默认视图。

“本机想法草稿”可跨书查看并继续编辑；选择后自动进入该书的划线或想法列表，核对草稿版本及原引用后恢复。选区草稿还会核对本机原文；所需引用或文件不可用时保留草稿。草稿仍需用户主动提交，联网时沿用原有云端预检与回读。

想法中可识别的图片和手写图片可从详情中的“查看想法图片”打开，使用 KOReader 原生图片查看器。首次打开需要联网，成功后保存在当前账号的本机缓存中，可离线重开；批量保存笔记不会预先下载图片。缓存最多保存 128 张、总计 32 MiB，单张最大 3 MiB；超过限制的图片不会显示。已缓存的旧想法需联网刷新后才会识别附件。部分附件格式或图片地址尚未核实，遇到无法识别的附件会提示；为避免丢失图片，目前不能编辑带附件的想法。删除时会提示附件也将删除，并核对全部可处理的附件字段是否变化；旧缓存没有附件校验信息或附件数据过于复杂时暂不提供删除，刷新后仍无法核对则继续保留原想法。

“搜索所有已保存笔记”可跨书检索当前账号在本机保存的划线和想法，包括不在已保存笔记本列表中的快照；可按笔记内容、原文或已保存的章节名匹配，并直接打开对应笔记。长内容的结果预览从命中位置附近开始，优先显示匹配内容，右侧显示笔记类型和书名；原文不受修改。搜索不联网，尚未缓存的笔记不会出现在结果中；结果会显示已检查数量、笔记本列表中尚未保存的快照数量和读取失败数量。结果每批最多显示 200 条，可选择“更多结果”或“上一批结果”继续浏览。切换批次会重新扫描本机缓存；如果前面已展示的匹配项或顺序发生变化，插件会提示重新搜索，避免忽略或重复结果。标记和想法快照各最多保存 5,000 本、各受 32 MiB 数据总量限制；切换账号、关闭页面或取消时会停止当前搜索。

“保存所有笔记供离线使用”按笔记本列表原顺序读取每本书的云端标记（包含划线和书签）及想法，逐项保存后可离线搜索。一次处理当前列表中可识别的书，笔记本列表最多支持 5,000 本；不支持的书会在结束时计入跳过数量，进度以每本书两项计算。保存可随时取消，已完成的项目保留。读取失败、登录续期失败或本机空间配额不足时停止，已保存的笔记不会为本次批量操作被淘汰；联网后可再试。明确的授权过期可按现有方式续期一次，仅继续未完成项目。保存标记后，当前阅读器中同一本书的标记图层也会更新。此功能只读取云端笔记，不提交标记、想法或阅读进度。

中断后可选择“只保存尚未缓存的笔记”：插件先在后台检查当前账号已保存的两类快照，再只读取缺失的项。已缓存表示本机有可读取的快照，并不保证云端没有更新；需要更新已有内容时仍可选择“保存所有笔记供离线使用”。缓存无法核验时停止并保留原数据；检查后若其他任务先保存了同一项，也不会覆盖它。完成提示分别显示新保存、已有和跳过数量，检查及后续读取均可取消。

列表只保存书籍标识、标题、作者、数量、排序和读取时间，按账号保存在本机数据库。第一次需要联网和墨水屏授权；成功保存后可离线打开。再次联网时可手动刷新；授权过期时可使用现有续期流程。读取失败、数量不完整或保存失败时保留上一次缓存。列表中不支持云端笔记的书籍会显示提示。

## 验证与限制

想法图片在 KOReader 的 600×800 和 1264×1680 模拟环境中验证了原生查看、跨进程离线重开、账号隔离与缓存损坏处理；另用真实公开书评图片验证匿名下载、实际图片解码和离线重开。真实账号抽查的 7 条想法没有图片，手写图片的字段来自公开实现和合成数据，真实个人附件及 Kindle Oasis 2 实机仍待验收。测试未修改云端数据，真实图片及其地址只用于内存中的临时配置，测试后已清理。

附件删除保护经合成测试覆盖未知嵌套字段变化、旧快照、过大或无法确定的数据、删除前并发变化及确认后的独立回读；只有校验摘要保存在想法快照中，不保存额外的未知附件字段。两种模拟尺寸的想法界面验证了可核对附件的删除入口和无法核对时的提示；没有执行真实附件删除。

真实账号只读探测中，服务端对 `count=2` 和 `count=100` 返回了相同的 15 本书，返回总数与列表长度一致。以第一本书的排序值传入 `lastSort` 后，墨水屏接口仍返回完整列表，不能据此假定它与 Skill 接口的游标分页行为相同。暂未证明其他账号的分页行为：如果服务端报告还有更多记录，或总数与返回数量不一致，插件会拒绝覆盖原缓存，而不会显示不完整结果作为完整列表。

模型和界面测试覆盖了空列表、格式错误、重复书籍、数量不完整、网络错误、取消、缓存写入失败和账号切换；模拟 KOReader 的 600×800 与 1080×1440 两种尺寸中，45 本合成书籍经完整插件加载、真实菜单、三个笔记入口及 SQLite 验证，另以真实账号的 15 本书验证原生 HTTPS 读取结果、逐页展示、三个单书入口、账号隔离和全新进程离线重开。单书入口在离线状态下核对导航，并未在本次测试中重新读取单书笔记内容；单书内容另有独立验证。测试只读，未修改笔记或书架，临时配置及缓存位于内存文件系统并已清理。尚未在 Kindle Oasis 2 实机上验证本入口。

搜索与排序另在 600×800、1264×1680 两种模拟尺寸通过 45 本合成书及真实账号 15 本书的原生界面和离线重开；包含搜索结果、清空、按数量排序及恢复原序，操作期间没有额外网络请求。测试覆盖筛选与排序组合、缺失数量、相同数量、输入过长、关闭后的旧回调以及后台刷新期间输入。真实样本未覆盖所有语言、异常数据及实体设备。

跨书笔记搜索在上述两种尺寸以合成数据和真实账号的划线、想法各一份快照验证：均能搜索并打开目标笔记，全新进程离线重开后再次通过；搜索期间没有额外网络请求。真实内容仅用于内存文件系统中的临时配置，验证后已清理；测试只读取账号数据，未修改云端笔记。尚未在 Kindle Oasis 2 实机上验证该功能。

分批浏览另以 205 条合成笔记在两种尺寸完成第一批、后一批、返回上一批和新进程离线重开；搜索过程没有额外联网。组件测试覆盖 200 条整、多批、已显示匹配项变化和取消。首次原生验收因脚本按英文查找中文按钮而失败，修正后两尺寸复验通过；见[记录](validation-assets/2026-11-20/notebook-search-pages.json)。实体 Kindle 和真实超过 200 条匹配的账号仍待验收。
