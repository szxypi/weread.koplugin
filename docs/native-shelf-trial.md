# 原生书架成员实际往返

已完成本人账号的一次生产原生「加入书架 → 独立回读 → 移出书架 → 独立回读」。
从未在架的普通数字书号进入真实原生详情、书架状态和确认窗口，由生产后台任务派发一次加入、一次移除，
书架为 140 → 141 → 140 本。宿主只有 GET，没有数据 POST 或授权维护；测试书与独立待核对意图已清理。
本批按照用户的后续继续执行授权开展，不复用此前已经消费的两次 Python 试验记录。

## 核对与停止条件

独立 Python 先核对完整书架、搜索结果与所选书籍资料，确认目标不在架，并绑定同账号授权、原始成员摘要、
每本书的置顶／私密／读完字段，以及可见分组的编号、名称与成员投影。
一次性启动记录在读取凭据前创建；同一内存计划先完成一次零派发、零保留额度的真实界面预演，
再重新读取原状态。实际启动前在独立钥匙串条目一次保留最多两次派发，未知结果不允许重新启动旧试验。

原生流程继续使用生产持久发送记录、实时完整预检、单次 POST、明确回执及独立网络回读。
只有生产任务确认新状态、SQLite 书架快照已保存且无待核对记录时，才向宿主报告该步。
宿主另做完整 GET，独立确认只有指定目标的在架状态改变，原有字段和可见分组投影保持一致，才放行下一步。
原生传输限制器只允许所选书号的单本加入／移除各一次，且移除必须等加入和宿主核对通过。
未知回执、未生效、其他字段变化、宿主失联、中断或回执不匹配均停止；不重发、不继续下一次修改。

新增 `--resolve` 只读恢复要求两次独立当前读取都证明目标已不在架、原成员和保护投影一致，才结束待核对意图；
不会据此推断过去的派发次数，也不会把中断试验改写为成功。目标仍在架或无法证明恢复时继续保留意图，不自动移除。
使用共用检查的原生想法、划线、样式及书签试验也会被新的待核对书架意图阻止，排除自身时仍检查其他作用域。

## 实际结果与验证范围

官方 KOReader v2026.07.1 Linux ARM64，600×800／167 DPI 的真实流程通过原生详情、完整预览、确认、后台工作进程和 SQLite。
先单独完成一次真实零写入预演；正式一次性启动中又对同一计划预演后执行。
正式预演原生读取为三个书架 GET、一个资料 GET，实际阶段为八个书架 GET、一个资料 GET、两个数据 POST；
宿主在每步另行独立读取，最终再次核对恢复。原生缓存、隔离配置中的原有本机进度／待上传记录与文件字节保持一致。
服务器排序、操作时间、历史、未返回字段和不可用分组引用不属于完整恢复保证；本批没有读取或修改真实云端阅读位置。

两尺寸封闭合成场景共 16 组通过：正常、禁止写入预演、回执不明、加入未生效、移除未生效、原私密标记变化、
分组变化和宿主中断。异常结果确认停止，待核对记录拒绝重启，隔离配置删除、原生进程和子进程回收通过。
原有非交互执行器的零写入／两步模式在两种尺寸另做四组回归通过。
真实界面只在 600×800 验证，1264×1680／300 DPI 使用合成数据，不把它描述为两种尺寸的真实账号验收。

本批完整检查为 91 份 Python／1,102 项零跳过、222 组 Lua、621 个静态文件零警告／错误、623 个 Lua 语法、
280 个 Python 编译、四时区、命名空间及 TLS。250 个生产文件的候选包与原生实际安装逐字节一致，生产插件代码未因本批验证改变。
书名和完整书架只经过捕获管道／内存及隔离 tmpfs，真实截图为零。独立钥匙串试验条目只保留归属、目标编号和有界摘要，
已在核对恢复后清除；Web 与墨水屏开发登录按要求继续保留在钥匙串。
固定记录见[本批证据](validation-assets/2026-11-12/native-shelf-trial.json)。
