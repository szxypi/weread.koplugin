# 原生后台同步服务与真实流程

原生位置服务已通过真实账号的限定前移／恢复流程：两个实际 `POST /book/read` 都由安装候选中的 Lua 后台任务发送，
取得明确成功回执，分别经 Lua 与独立 Python 回读核对；最终完整原位置、摘要、三项时长计数和可见书架一致。
该轮是后台服务与传输流程验收，界面使用通用验证面板；后续已完成下述实际书籍阅读器的只读来源准备，菜单与自动同步入口仍未接通。
TXT 生产上传保持关闭。

后续已验证服务端完整保留 TXT 原文摘要，并新增在线原文／目录核对和候选准备，
见[原文摘要与同步准备](raw-txt-native-summary.md)。实际阅读器的原生发送入口仍待衔接。

## 阅读器来源准备：原文片段

后续接入新增了独立的只读准备步骤。`source_coordinates.lua` 的 `literal_excerpt` 仅接受 TXT 原文坐标，
保留 BOM、CRLF、空白、字面标签／实体和组合字符；按 Unicode 标量限制长度，起止位置仍按原文 UTF-16 单位计算。
表情中间的半个代理对、文件末尾的空片段和 XHTML 坐标会被拒绝。
该方法复用已有稀疏检查点，不为整章另建逐字位置表。

`source_position_worker.prepare_native_excerpt` 通过独立归档句柄重新核对文件身份、元数据、原文哈希和渲染成员，
只将最多 30 个标量的片段及位置元数据放入内存管道。结果继续标记 `upload_verified=false`，
不生成百分比、不转换本机版本为原生 API 版本、不产生云端 DTO，也不启用既有 XHTML 发送入口。

新增 59 项 Lua 来源／边界检查和 9 项 Python 检查。
真实书籍的 [21 组 Python／KOReader Lua 原文比对](validation-assets/2026-11-12/txt-literal-excerpt.json)通过，
前后目录和云端位置一致，账号修改及授权 POST 均为零。正文只通过内存管道，未创建书籍文件或配置。
真实样本的 30 标量原文片段与云端已存摘要不相同；这项结果只证明原文切片正确，
不能据此认定官方摘要规则已验证。该次切片比对未覆盖实际阅读器页面；后续的阅读器来源准备见下一节，摘要生成与同步入口仍待接入。

## 实际阅读器的异步来源准备

`SourcePosition.prepare_native_excerpt` 现已接入阅读器拥有的异步服务。父进程固定账号、文档实例、文件身份、视口和原文元数据，
独立子进程读取归档；返回前再核对原生位置、文件、版本和原文哈希。
结果中的片段只保留在内存，通过有效期最多 30 秒的空表回执确认归属；修改返回值、伪造回执、时钟回退、换页、
同页文字位置变化、换账号、资源不足、休眠和关书均不能接受旧结果。再次准备或取消也会清除旧回执。
正文不会进入 `current()`、阅读检查点或配置。该回执只证明本机来源准备，不能作为上传授权。

[实际书籍验收记录](validation-assets/2026-11-12/native-reader-excerpt.json)覆盖官方 KOReader 的 600×800 与
1264×1680／300 DPI 两种尺寸。插件书架选书、单章下载、真正 ReaderUI 打开和离线新进程重开均通过；
每个尺寸在正常页面、翻页后和精确跳转保留位置分别取得片段，两次进程共六条由宿主 Python 按原始 TXT 独立核对。
翻页和关书时，预先确认存活的片段子进程被取消并回收，迟到回调未执行；新进程无 HTTP 请求。
原生文档只在父进程访问，原阅读位置恢复，普通进度单位和未验证状态保持。
275 个安装文件与候选和源码逐字节一致，临时内存配置已删除，无正文截图，账号修改和授权 POST 均为零，前后云端位置一致。

最初四次 600×800 验收未通过：验证器的纯数字书架范围漏掉了 CB 类型书籍的只读显示请求。
固定字段诊断和失败结果保留；补充实际书架中观察到的 CB 标识后完整复验通过，未放行修改或续期。
新增 128 项 Lua 服务断言及 9 项 Python 回执／边界检查。
本轮不证明 TXT 云端摘要规则、原生上传、手动／定时／关书同步或实体 Kindle 已完成；这些后续工作仍然保留。

## 父进程与工作进程

`native_position_service.lua` 在父进程检查文档／来源回调、当前授权和任务时限，后台只运行原生协议、网络与 SQLite。
父进程的文档检查函数不会传给子进程调用。`native_position_guard.lua` 提供匿名共享取消位，
取消时先失效该位，再终止工作进程；子进程也检查直接父进程身份，父进程丢失后不再获得发送上下文。
该共享页不保存账号、正文或凭据。服务清理定时回调、共享页和工作进程，不在 UI 循环执行网络请求。

发送准备会冻结完整计划并绑定账号。异步结果只有与同一操作、计划、修订号和数据库核对完成状态一致时，才返回可接受的回执。
伪造或迟到的成功结果不能清除待确认状态。取消只能释放仍未领取的准备记录；领取、成功回执或已核对记录继续保留。
重新创建服务后，有成功回执的操作只能只读核对；没有回执的未知修改不重发。

已核对完成的旧操作与“当前云端仍在旧位置”是不同结论。若用户随后继续阅读或别的设备移动进度，
服务可以按账号接受旧完成回执并结束记录，不重新上传旧点，也不把旧操作结果当作当前进度。
未发送的准备状态可原子取消，两个过程竞争时不能同时清除准备状态并获得发送权。

## 限定真实验收

本次使用独立的钥匙串协议与两个槽位，不复用此前 Python 试验或原生同位置试验。
原始完整位置、摘要与目标保存在钥匙串，Lua 配置和数据库只放临时内存文件系统。
发送前由外部 Python 核对完整请求及签名、当前授权、原文／目录、两端位置、计数与书架，再原子领取槽位。
明确成功回执会立即通过内存管道交给外部持久保存，之后才进行进一步核对，避免回读异常时丢失已收到回执的事实。
每步 Lua 核对完成后仍须等待外部重新读取来源和进度；原生 SQLite 回执也通过后才开始下一步。
