# 从同步按钮应用 TXT 云端进度

开发分支已在实际阅读器中验证完整流程：从插件书架打开 TXT 章节，在本机保留一个不同的原文位置，
点击同步并选择“使用微信读书进度”，后台核对云端与 Reader 位置及原文，再以 KOReader 原生引擎定位。
成功后保存同步比较结果，清除旧本机待上传意图；原文来源回执仍为本机未验证状态，不变成上传授权。

## 离线重开修复

完整验证发现：云端目标及本机检查点已经保存，但重开同一 EPUB 时，插件会重新取当前页起点，
丢失仍在该页内的精确原文位置。只检查“目标字仍在屏幕上”不能发现这个问题。

现在只有当前已保留的原文目标才会附带 `source_view`：原文位置指纹、账号范围，以及原生页码、
滚动位置、XPointer、排版标识、页数、文档高度和视口高度。记录不含正文、Cookie 或令牌，不能用于云端写入。
重新打开同一文件时，账号、来源、文件身份与全部视口字段一致才恢复精确原文锚点；
仍通过独立归档工作进程核对原文和渲染内容，再由父进程定位。

翻页、滚动、排版或屏幕变化，未知视口字段，以及旧版本没有该记录的检查点，都不能覆盖 KOReader 当前的位置。
不同文件之间继续使用原来的来源交接流程。恢复本机锚点不会伪造云端核对结果，
不会因此自动上传进度或申请授权，也不会清除真实待确认记录。

## 验收

[固定字段记录](validation-assets/2026-11-12/raw-cloud-choice.json)覆盖官方 KOReader 的 600×800／167 DPI 和
1264×1680／300 DPI，两种尺寸各包含真实账号在线流程及全新离线进程。

在线通过正常同步对话框选择云端，核对后台工作进程、原文反向定位、同步状态、检查点、旧意图清除及成功提示。
离线重开在验证器做任何诊断跳转前，先核对已保存的原文位置、实际显示范围，以及插件此时真正识别的原文位置；
随后离线本机跳转仍保持未核对状态。每个尺寸的两个位置及两个检查点由宿主按独立原文重新核对。

宿主在 UI 验收前后独立读取 Web 与原生完整位置、摘要、三项时长计数、版本和书架，并重新读取原文和目录。
所有结果保持一致。阅读器中拒绝全部原生网络请求，Web 只放行规定的读取；宿主原生接口也只支持读取。
本轮真实数据及授权修改均为零，既有已消费试验和钥匙串凭据保持。

37 项视口约束断言、97 项来源交接断言及 631 项同步断言覆盖来源、账号、排版、移动和兼容边界；
新增 13 项 Python 边界检查。原有手动／定时／未知回执与离线重开、关书后原生同步，以及 XHTML 云端定位回归通过。
所有后台进程回收，临时内存配置删除，没有正文截图；读取结果与凭据只经内存管道，公开记录只有固定字段。

上述是软件运行环境验收，不能替代实体 KO2、断电或多设备验收。真实定时写入、更多格式和未开始阅读的边界仍待处理；
集中性能优化在整体功能验收后进行。
