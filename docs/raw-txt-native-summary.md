# TXT 原文摘要与同步准备

原生零时长接口已验证可保存直接取自 TXT 原文的 30 个 Unicode 标量，包括 CRLF 换行和段首全角空格。
新的 Python 限定流程完成一次前移／恢复，两个请求均取得 `succ=1`，两端回读完全匹配，
最终又进行了两次独立原文／目录／原生元数据及 Web／原生位置核对，原完整摘要恢复，三项时长计数保持。
这为插件提供了可核对的原文摘要方案，不依赖猜测官方 App 的空白归一化规则。

## 摘要策略和边界

原文坐标按 UTF-16 单位计算，片段长度按 Unicode 标量计算。取原位置开始的最多 30 个标量，
不解析字面标签或实体，不替换 BOM、CRLF、全角空格或组合字符，不从表情的代理对中间开始。
界面若需要折叠换行，应在展示时处理，不能把展示文本当作新的来源坐标或改写上传片段。

`native_source_candidate.lua` 从阅读器已经核对的原文片段生成独立候选：目录 UID 必须唯一且提供明确章节索引，
百分比沿用当前阅读器已有的整数显示百分比，不根据原文字节数重新估算。
本机文件版本、文件身份和原文哈希继续绑定来源；原生 API 的版本必须另行读取，本次真实值是合法的 `0`。
不能将本机归档版本替代 API 版本，或因 Web 目录未提供版本而编造正整数。
候选仍标记 `upload_verified=false`，不会修改本机检查点单位或启用 XHTML 发送器。

## 发送前的只读来源核对

`SourcePosition.prepare_current_native_preview` 先通过独立归档任务准备当前页面的原文片段，
再在后台使用 `source_currentness.run_txt` 重新核对账号、目录、指定章节阅读会话、TXT 回退标记及原始正文。
账号、目录均前后读取；TXT 的 `e_0` 标记必须属于同书／同章，失败时不能继续请求 `t_0`／`t_1`。
源字节长度、SHA-256、章节 UID／索引和前后目录版本观察必须一致。
结果带独立的 `raw_txt_utf16` 标记，XHTML 核对不能接受该回执。

父进程同时核对原页面、文件、账号、当前目录和显示百分比。回执为空表且仅存在内存中，
有效期不会超过首次原文准备开始后的 30 秒；换页、同页位置变化、换账号、取消、关书或授权变化会使其失效。
只有新的真实 HTTP 401 能进入一次 Web 来源授权恢复，其他错误和第二次 401 均停止；
此步骤没有账号修改，不能被解释为原生写入或写后重试授权。

  本次已 `retired`、两槽均消费，不能重跑。完整原位置和目标只在钥匙串保存，旧试验状态保持原结论。
- 两个实际原生账号 POST，无 Web 修改、历史时长记录或授权 POST。目标含 CRLF 的原文摘要完整保留，
  原完整摘要恢复，三项计数和可见书架一致；最终两次独立核对通过。
- 官方 KOReader 中的真实书籍在 600×800 和 1264×1680／300 DPI 均通过来源准备、一次在线 TXT 重新核对、
  翻页／精确跳转／后台取消及新进程离线重开；每尺寸六条片段由 Python 独立核对，新进程 HTTP 为零。
  276 个安装文件与候选和源码一致，原生文档仅父进程访问，临时配置删除，无正文截图，云端位置保持。
- 新增 10 项 Python 原文策略／两槽状态／跨试验屏障测试；33 项候选、187 项 TXT 来源传输和 114 项在线回执断言通过。
