# CB_ 编号书籍的书架进度

书架原先只为数字编号读取进度，当前账号中的五本 `CB_` 编号书籍因此保持未知。
现已支持这类书籍的 Web 只读进度，并沿用首页／书架的后台读取、SQLite 缓存及离线显示。
编号须为 `CB_` 加 1–64 个 ASCII 字母或数字；不接受路径、查询、控制字符或其他命名空间。
编号前缀本身不证明书籍来源或所有权，本项不据此宣称个人书籍上传已经实现。

## 通道和范围

`read_access.display_book_id` 仅用于书架显示；原有数字编号校验保留给账号、章节及其他调用。
`Client:get_progress_snapshot` 单独维持原校验，书架支持不会批准 CB_ 同步位置或其他云端修改。
新交互先由 `verify_cb_progress.py` 实际核对，再接入 Lua。

有 Web 授权时，CB_ 直接使用既有 `/web/book/getProgress` GET，不尝试未经验证的网关路径。
同一批的数字编号仍遵守原通道优先级和一次网关失败后的回退。
没有 Web 授权时不调度 CB_ 的新读取，数字编号继续读取；已有同账号缓存仍可显示，没有缓存则保留未知。
HTTP 401 继续走原有受保护的只读恢复流程，回调必须匹配账号和批次，已保存的有效前缀不重查。
不写入阅读器待同步位置、章节、时长或书架状态。

## 协议与真实界面

Python 工具默认离线，显式保存会话模式先核对原生和 Web 书架的完整 CB_ 编号集合及账号，
只读取其中最多八本，每个地址一次；不跟随重定向，响应上限 64 KiB，失败停止后续读取。
Cookie 只发送到固定 Web GET，原生授权不进入这个通道；经过账号核对的 Cookie 轮换延续既有钥匙串保存流程。
报告只含固定状态、数量和布尔值，原始书名、编号、百分比和凭据只留在内存／捕获的管道。

五本真实样本全部返回 HTTP 200 和有效进度，Python 首次验证在 Lua 修改之前完成。
随后 Python、Lua 模型与实际插件 HTTPS 的五份结果一致。两次协议验证共 21 个 GET，零数据及授权 POST。

打包插件在 600×800／167 DPI 和 1264×1680／300 DPI 各完成一次全部书架联网绘制与全新离线进程重开。
仍为 139 条（137 本普通书、2 个公众号容器），进度从此前 132 条扩为全部 137 本普通书。
全部页正向及离线反向的顺序、展示字段、139 个封面条目字节和 137 条进度一致，合计 115 次实际重绘。
实际账号界面未保存截图，临时配置仍使用 tmpfs，结束后清理。

合成服务的两尺寸真实原生界面另核对：CB_ 的 Web 与普通书的网关混合读取、SQLite 显示、
离线列表、无 Web 时跳过新 CB_ 读取并继续普通书、未知进度不伪造、阅读写入数量不变。
