首页、书城、搜索框、相似书籍列表继续使用 KOReader Lua 控件，正文使用原生 EPUB 引擎。
本次扩展数据通道，不加载网页界面、不执行网页 JavaScript。集中性能优化仍安排在全部功能验收后。

调用仅使用墨水屏授权头，隔离 Web Cookie 和 Skill 密钥；HTTPS 使用插件的 CA／SAN 校验。
仅投影有界的书籍展示字段、分页游标和推荐会话，不把原生 `version` 当成 EPUB `bookVersion`。

## 插件行为

- 搜索、推荐、相似书籍自动优先当前账号的墨水屏授权；无授权时使用已配置的 Skill 密钥。
  两者都缺少时，搜索可使用公开通道，推荐和相似书籍打开授权入口。原有“书架读取方式”仍只影响书架，不作为书城的全局开关。
- 首批读取遇到原生 HTTP 401／403／50x、传输错误或超时时，有 Skill 密钥可回退一次；搜索没有密钥，或密钥通道也遇到 401／403／5xx 或连接失败时，可以回退到公开通道。原生 401 优先尝试下述一次续期。
  HTTP 429、API 拒绝和无效响应不触发回退。后续页和上一批绑定原通道及授权修订号，不能拼接不同来源。
  刷新列表会从首批重新读取，清除旧游标和推荐会话。授权变化后需刷新或重开列表。
- 「为你推荐」的首批明确为空且有 Skill 密钥时，后台补查一次。Skill 返回书籍后，分页和缓存沿用 Skill。补查失败或同样为空时保留原生空列表。
- 网络读取、解析及投影使用独立后台进程和最多 512 KiB 的内存管道；原始 HTTP 响应最多 4 MiB。
  退出页面、取消等待时终止后台请求；关闭种子书详情也立即停止相似书籍请求。
  账号／登录代次／授权变化时丢弃旧结果，旧回调不能关闭新请求的等待窗。
  失败保留当前列表；尚无当前列表时可打开对应的已保存批次。浏览结果按账号写入独立 SQLite，不写入全局设置。
- 分类书单同样在后台读取；分类层级目录也已迁入独立后台进程，并保存公开 SQLite 缓存供未登录离线重开，
  详见[公开分类目录说明](public-category-catalog.md)。
- 原生授权书城读取的 HTTP 401 可复用既有持久化续期流程最多恢复一次，保留原生分页的游标／推荐会话；
  续期后的再次 401 不循环，已有原生分页不会回退其他来源。取消／休眠保留不明回执的待确认标记，
  后续读取不会重放续期。规则见[续期说明](eink-renewal-prototype.md#插件行为)；书城真实失效／限频待验收。

## 保存浏览批次与离线重开

首次进入书城且没有当前或已保存列表时，联网自动展示公开的「飙升·出版」榜单。它不需要登录，
也不冒充个性化推荐；「为你推荐」仍使用原有授权和独立入口。离线时不会自动发起请求，空列表刷新会
尝试读取榜单。已有列表优先恢复；切换页面、账号、打开搜索或开始其他请求会阻止旧的自动加载。
官方 KOReader Linux ARM64 运行环境在 600×800 与 Kindle Oasis 2 尺寸均通过模拟及真实公开榜单的两批读取，
新进程离线重开并核对两批内容、零网络请求；真实验证未登录、没有截图，实体设备仍待验收。
见[验收记录](validation-assets/2026-11-19/public-store-entry.json)。

搜索、为你推荐、相似书籍及分类书单现在保存到当前账号数据库的 `discovery_cache` 表。
书城重开时恢复最后浏览的查询与批次，标题开头标记“已缓存”，长书名不会挤掉状态；离线搜索相同关键词、
打开相同种子书的相似书籍，或者点击已缓存的前／后批次，只读本地数据，不要求有效的墨水屏授权。
没有对应缓存时保留当前列表并提示联网刷新，不把别的查询或账号的数据当成结果。
从详情打开离线相似书籍会关闭详情窗口，避免列表被旧窗口遮住。

从书城结果的详情打开「相似书籍」后，按返回键或点左上角箭头，可直接回到原书城结果，恢复原批次、页码和焦点。返回沿用已加载的列表，离线时也可使用。继续查看相似书籍时，当前会话最多保留四级返回路径；切换账号或主动打开其他搜索、榜单或推荐列表会清除路径。返回后正常关闭，仍按原有方式保存当前浏览位置。

从首页或书架进入「相似书籍」也使用同一返回键。首页保留页码和书籍焦点，书架恢复原分组、搜索和滚动位置。书架在返回时读取当前本机数据；期间有新书插入时，按原可见书号恢复位置。原先打开的书城查询在同一会话内可以继续浏览。

从「已下载书籍」的详情进入「相似书籍」，返回时会恢复原来的下载类型筛选、搜索、页码和焦点。返回沿用已加载的下载列表，点刷新可重新扫描本机文件。两种 KOReader 模拟尺寸已验证在线翻到下一批后返回，以及断网打开已缓存的相似书籍后返回。实体 Kindle 待验收。

切换到其他标签或正常关闭书城后，返回时会恢复当时的批次、页码和书籍焦点。正常关闭后重新启动 KOReader 也可离线恢复；访客仅保存公开分类和榜单位置。刷新、删除或淘汰对应缓存后，使用有效缓存的默认位置。翻页和重绘期间无需写入浏览位置。

保存其他查询或追加同一书单的批次时，保留已保存的浏览批次、页码和焦点。追加后，仍停留在原批次的页面也能保存新焦点。刷新替换或淘汰该书单时，清除原位置。两种 KOReader 模拟尺寸均通过实际 SQLite 写入后的全新进程离线恢复，覆盖登录、访客及登录后引用访客公开书单三种情况。

登录后离线浏览访客缓存的公开榜单或分类时，批次、页码和焦点同样按当前账号保存。重新打开书城时，插件核对仍然存在的原公开书单批次后恢复。此位置记录只引用已保存的公开书单，访客的浏览记录独立。

两种 KOReader 模拟尺寸各读入真实榜单两批，再以合成账号离线浏览，从另一全新断网进程直接恢复到第 2 页及同一本书的焦点，随后继续翻批。实际 SQLite 的合成回归也覆盖了另一个账号、访客原位置和公开书单替换后恢复至账号缓存。实体 Kindle Oasis 2 仍待验收。

缓存只含查询的展示信息、书籍卡片字段和已浏览批次，不保存 Cookie、访问／刷新凭据、
授权修订号或推荐会话 ID。缓存页只能在已保存的链内往返，不根据远端的 `hasMore` 猜测未保存的下一批。
即使网络已恢复，缓存批次的前后切换仍只用本地数据；点击刷新从首批重新取得当前通道／授权／会话，
不会把新授权拼到旧推荐会话上。新首批替换该查询的旧链，旧任务不能继续向已替换的链写入。
刷新当前列表时，断网或请求失败会保留当前批次、页码和焦点；刷新成功才切回新结果的首批。取消、页面或账号变化后，迟到结果不能保存。

离线翻批或联网翻批失败后，只使用当前书单同一轮保存的批次。另一进程刷新并替换书单时，保留当前页和书籍焦点，可重新打开查询查看更新的结果。同一书单后续保存的批次仍可翻阅。

每账号最多 12 个查询，每查询最多 12 批，每份 JSON 最多 2 MiB，总载荷最多 16 MiB。
按最近保存顺序清理较旧的查询；单查询超限或保存失败时继续显示本次在线结果并提示无法离线保存。
所有写入、查询链替换和配额清理在同一 SQLite 事务完成；失败回滚，原有缓存保留。
保存内容经过有界字段投影，损坏缓存不进入网络参数；这些不是服务端原子快照或任意外部进程并发的保证。
封面图片继续走已有封面缓存，正文不进入本表。

## 已保存的搜索

首页或书城的搜索框提供「已保存的搜索」入口。列表从当前账号已有的书城缓存读取，按最近保存顺序展示；选择一条会直接打开已保存的首批结果，离线也可使用。要获取新结果可在结果页刷新。该入口只展示已有结果缓存；搜索结果随缓存额度清理后，对应条目也不再显示。尚未保存过搜索时会提示联网搜索。

同词的普通与公开搜索可同时保留，公开条目用「公开搜索」标明来源。打开或长按删除只针对该条目的来源，另一个来源的已保存结果可以继续查看。

搜索框另有「最近搜索」：保留最近 20 条已提交的搜索词，普通和公开搜索分别记录，即使搜索失败或没有可保存结果也可再次选择。选择时沿用原搜索方式；离线时只有相应结果已缓存才能打开。长按可移除单条，列表末尾可确认清空；这只清除搜索词，不删除「已保存的搜索」结果。登录状态下按账号保存在设备本机，不上传或跨设备同步；访客记录只保留在当前进程内，登录切换后清除。保存失败不会阻止本次搜索。

两种尺寸的打包插件在原生搜索框和菜单中验证了提交、公开／普通搜索区分、离线结果、账号隔离、长按删除、清空及全新进程重开；数据和搜索词均为合成值。旧版「已保存的搜索」与页面生命周期也一并回归。首次原生测试发现清空确认后菜单失效，已修复并在两尺寸复验；实体设备及真实网络情况仍待验收。见[普通尺寸结果](validation-assets/2026-11-22/recent-search-600.json)、[KO2 尺寸结果](validation-assets/2026-11-22/recent-search-ko2.json)和[普通尺寸菜单截图](validation-assets/2026-11-22/recent-search-list-600.png)。

长按已保存的搜索可以确认移除该条及其本机离线结果，不修改微信读书云端数据，也不影响其他搜索。删除在后台进行，并核对列表展示时的缓存代次；如果确认期间该搜索已被重新刷新，保留新结果并提示重新查看。两种屏幕尺寸的原生列表验证了取消、移除、保留其他搜索及全新离线进程重开；实际 SQLite 另验证账号隔离、刷新冲突和提交失败回滚，见[脱敏记录](validation-assets/2026-11-20/saved-search-removal.json)。实体 KO2 尚待验收。
