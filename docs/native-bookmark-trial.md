# 原生云端位置书签实际两步

已完成本人账号的一次原生书签往返：从插件书架进入原生阅读，核对当前视口的原文点，
通过生产菜单保存一条新书签；宿主独立完整回读后，从本人书签列表定位回原文，再确认删除并独立回读。
恰好两次生产数据派发，宿主没有数据 POST，没有写入重试，最后没有测试书签或待确认意图。
两种尺寸合成场景、协议来源和禁止发送准备见[执行器说明](native-bookmark-trial-readiness.md)。

## 同一计划的禁止发送与实际执行

一次性启动记录在读取凭据前创建，记录最多两次数据修改、零授权 POST；记录已消费，不能重跑。
同一内存计划先完成一次禁止发送预演，核对生产确认窗口、当前视口／原文归档、点坐标和完整预览，
零派发、零额度保留后，再重新核对原状态、更新并读回同账号 Web 凭据快照，才启动实际执行。
实际执行开始前独立原生书签钥匙串意图一次保留两次额度，未知结果或中断会阻止旧测试重启。
根进程的独立 SQLite 限制器核对完整请求、生产发送记录与新增编号，每步派发前原子领取。

| 步骤 | 生产原生路径 | 允许目标与核对 |
| --- | --- | --- |
| 新建 | `/book/addBookmark` | type=0、style=0、单点原文范围；不发送颜色或推测的章节序号；只接受唯一新增且完全匹配的书签 |
| 定位 | 原生本人书签列表 | 按核对后的归档与可逆锚点回到保存的原文点，不调用位置上传 |
| 删除 | `/book/removeBookmark` | 只删除宿主已独立确认、完整指纹未变的新增编号；原有编号不能作为目标 |

每步都保护完整本人标记、想法、章节描述、书架标记和精确位置。
最终宿主确认原投影恢复、Web 位置一致，原生确认缓存不含测试编号、本机笔记与原文位置恢复、阅读模式恢复。
服务端排序、操作历史和未返回字段不属于完整恢复保证。
本批公开回执不含原集合数量，因此不据此宣称非空真实集合的专项写入验收。

## 实际结果与范围

同一计划预演为 12 次原生 GET、零原生数据 POST，实际阶段为 14 次原生 GET、两次原生数据 POST。
宿主在每步完成自己的独立完整回读，才允许原生界面继续；两次生产派发没有合成回执。
本次启动的授权 POST 为零。此前真实预检观察到一次 HTTP 401 后，已单独续期一次并核对同账号 140 本书架与钥匙串回读，
详见准备记录；未因书架刷新阶段的旧快照问题再次续期。
书签功能本轮累计真实数据派发为 Python 两次、原生两次，均只操作各自的新测试记录。

真实运行使用官方 KOReader v2026.07.1 Linux ARM64，600×800／167 DPI；实际使用滚动视口核对章首可见正文点，
最后恢复原阅读模式与位置。正常页面模式及 1264×1680／300 DPI 使用合成数据核对，不据此宣称实体 KO2 通过。
预演和实际执行分别回收工作进程、清理私有 tmpfs 配置；249 个生产文件的实际安装内容与候选包逐字节一致。
真实正文、编号、坐标和凭据未写入公开记录，没有真实截图。Web 与墨水屏登录按用户要求继续保留在钥匙串。

执行器修复了预检 Cookie 更新后仍传入旧副本的问题；交接前保存、读回、账号与并发替换检查已覆盖书签、划线和样式验证入口。
完整本地检查为 90 份 Python／1,084 项零跳过、221 组 Lua、618 个静态文件零警告／错误、620 个 Lua 语法、275 个 Python 编译、
四时区、命名空间和 TLS，另有 22 组书签原生合成场景与四组旧执行器回归。
准备与实际两份证据分别保留，见[本次固定记录](validation-assets/2026-11-11/native-bookmark-trial.json)。
