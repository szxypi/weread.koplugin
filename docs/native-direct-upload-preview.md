# 原生章节位置同步与验证

在原生章节的「微信读书·快捷菜单」选择「同步本页到云端」，插件会核对账号、文件、原生及网页来源、章节目录、两端云端位置、摘要、阅读计数和书架。确认后再次检查全部来源与基线，再使用零阅读时长的原生请求上传；仅收到明确成功回执且独立回读完整目标和计数一致，才显示同步成功。翻页、文件或账号变化会取消当前流程。

原生和网页两端都未返回摘要时，预检会将其作为明确的缺失状态，不能当成空字符串或先前摘要。如果上传后仍未返回完整目标摘要，结果保持待核对，不声称成功。已有云端位置与原文一致时不发送；云端尚无章节时只在三个阅读时长计数均为零时允许准备。全书百分比保留云端原值，并非从单章推算，可能暂时与实际位置不一致。

发送前由账号隔离的 SQLite 记录绑定来源、位置和基线，领取发送权后不重发。回执丢失、回读异常或中途取消时保留记录；再次选择同步可只读检查云端状态，经明确选择后归档，不自动发送或撤销先前请求。同步过程中必要的原始摘要与待上传摘要会暂存于账号本机的同步记录，记录完成或归档后不再保留在活动记录中。

原生章节离线翻页后会在联网、休眠或关书时尝试保存账号隔离的本机位置提醒；保存失败会提示，本机页码仍由 KOReader 保留。已保存章节列表会标出经过文件核对的「离线进度待核对」章节；开启「打开时拉取进度」后重新打开该章节，如果当前页与记录不同，可选择恢复离线位置；停在记录所在页时，可比较云端位置、同步当前页或稍后处理。同步仍走上述来源检查、再次确认及回读，不因联网自动发送；账号、页面、文件、网络或设置变化会使旧选择失效。选择稍后或结果不明确会保留记录；确认当前页与云端相同或同步并回读成功后，才移除对应提醒。缓存清理会保护提醒所引用的章节。

选择云端位置后，离线提醒仍会保留，方便再次查看本机位置。若不再需要，可在提醒中选择「移除离线提醒」并再次确认；该操作只移除提醒，不移动当前页面或修改云端位置。账号、页面变化或提醒已被更新时，旧确认不会删除新记录。

原生章节快捷菜单另提供「离线位置」手动入口，不依赖网络或自动拉取设置。断网时可以查看、恢复或确认移除已核对的提醒；当前离线翻页尚无提醒时，也可从这里先保存本页。若本章已有旧提醒且当前离线页面尚未保存，会询问是否用本页替换旧提醒；取消后保留旧提醒和当前页，在该冲突解决前自动检查点不会覆盖旧提醒。关书时若仍未处理会提示，KOReader 仍保存本机页码。再次打开后，如果当前页与旧提醒不同，可在「离线位置」选择「改为保存当前页」并确认替换；取消则保留旧提醒。确认替换时再次核对账号、页面和原记录，其他操作已更新或移除记录时不会覆盖。恢复位置前会再次读取记录，记录变化或不可核对时不跳转；连接网络后可选择比较或同步云端。

真实账号的一本书另在两种模拟尺寸通过完整打包插件和独立进程验证：离线保存、冲突取消后关书重开并确认保存当前页、取消移除、移动页面、恢复离线位置、确认移除及再次重开均通过；关闭自动拉取后，也从快捷菜单在禁网进程中查看、恢复并移除提醒，关书后没有重新生成。测试使用临时配置和禁网阅读进程，独立回读的书架与网页阅读位置保持；比较阶段没有账号数据写入、授权请求或凭据文件，临时数据已清理。该验证不代表自然断网、实体 Kindle 或其他书籍均已验收，见[脱敏记录](validation-assets/2026-11-23/native-direct-pending-owner.json)。

两种模拟尺寸的完整安装插件验证了离线翻页、联网提醒，以及两种选择经缓存身份核对后进入各自的同步入口；测试在实际传输入口前拦截，没有网络写入。另用独立进程验证离线翻页关书、重开、不同页面恢复原位置、稍后保留和模拟确认后再重开；SQLite 测试覆盖账号、文件身份、锁竞争和旧记录不可删除新位置，缓存清理在扫描后新增提醒时会停止。实际确认流程另由组件测试覆盖。记录仅在上述检查点写入，并非每次翻页均已落盘；检查点前断电、更多真实书籍、真实断网环境和 Kindle 真机仍待验收。

原生章节也支持「定时同步进度」，默认关闭。打开设置后，先在当前阅读会话中手动同步本页；同步成功或确认本页已经与云端一致后，翻页才会启动定时器。到期时插件再次核对账号、文件、来源和完整云端基线，两次预检一致才发送零阅读时长的位置；持续翻页不会不断推迟截止时间。云端状态变化、发送结果不明确时暂停并提示，待核对的请求不会自动重发。关书、切章、休眠或断网后需再次手动同步以建立新基线；定时器不会唤醒网络。两种尺寸的完整 KOReader 模拟已覆盖手动建立基线后的定时上传、云端冲突、回执丢失、检查中翻页和离线停止。真实账号在 KO2 模拟尺寸的隔离阅读器中完成自然一分钟到期、位置上传和原位置恢复，并经独立两端回读；测试宿主从只读预检建立基线并主动通知翻页，实际手动建基线和完整插件事件链由模拟覆盖，见[定时往返记录](validation-assets/2026-11-23/native-direct-interval-roundtrip.json)。实体设备仍待验收。

「关闭时上传进度」也适用于原生章节，默认关闭，且同样要求当前会话先手动同步或核对。关书前固定当前页面的有限文字上下文，关书后在后台两次核对云端基线、来源和文件，再通过受保护的原生通道发送；后台不会使用已关闭的阅读器或唤醒网络。新的阅读器打开、断网、休眠、账号变化或关闭设置会取消旧任务；若请求结果不明确，保留待核对记录且不自动重发。本机位置仍由 KOReader 保存。两尺寸完整插件模拟覆盖成功、云端变化、回执丢失、断网和立即重开；真实账号一本书在 KO2 模拟尺寸的隔离阅读器完成关书上传及原位置恢复，独立核对两端及书架，测试宿主从只读预检建立基线并调用关书流程，见[记录](validation-assets/2026-11-23/native-direct-close-roundtrip.json)。实体设备仍待验收。离线待上传和尚未显示的云端批注自动叠加仍待接入。

两种尺寸的完整 KOReader 原生模拟验证成功、取消、云端变化、回执丢失，以及缺少摘要的上传准备和写后只读核对；模拟失败情况下未重发。真实账号只读预检分别覆盖摘要存在和缺失的书籍，原文与独立位置核对通过。两种尺寸的隔离原生阅读器还分别对两类书籍走到实际发送边界，核对发送载荷并在出网前阻断；待核对记录正确保留，云端和书架未变，临时环境已清除。

真实服务器先由独立 Python 原生协议完成一次 XHTML 位置变更与原位恢复。随后同一本书在 600×800 的隔离 KOReader 原生阅读器中，使用正式同步界面、后台服务及 SQLite 完成第二次变更与恢复：宿主在每次发送前独立核对来源、可见页面位置、签名请求和云端状态，明确回执及两端回读均成功后才继续；两次原生数据写入后原位置和摘要恢复，阅读计数及可见书架未变。全新只读检查再次确认原状态和已结束的测试记录。两次测试均没有网页进度写入或授权请求，不能证明最近阅读时间或服务端全部历史恢复。

在合成往返中发现 KOReader JSON 解析器会把转义的表情符号拆成无效的代理项，导致回执后无法确认摘要。现只对 JSON 字符串内有效的代理对进行转换，保留转义反斜杠及无效输入，普通响应使用快速检查；实际 KOReader 解析器及两尺寸原生往返回归通过。真实账号完整插件宿主、缺少摘要时的真实写入、更多书籍及实体 Kindle 仍待验收。见[只读预检记录](validation-assets/2026-11-23/native-direct-upload-preview.json)、[真实协议记录](validation-assets/2026-11-23/native-direct-upload-roundtrip.json)及[原生界面记录](validation-assets/2026-11-23/native-direct-ui-roundtrip.json)。
