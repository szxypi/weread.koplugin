# 原文位置就绪后再核对云端

原生阅读器唤醒或重新取得位置时，原文坐标采集和云端进度读取都在后台完成。
此前云端读取先返回时，本机坐标可能仍在准备，比较会进入“进度不同”的选择流程；
即使随后本机坐标与云端完全一致，该次选择也不会自动重新比较。

现在，进度读取遇到本机原文位置仍在等待、准备或资源延后状态时，先等待正常采集器就绪，
再重新读取云端，随后按当前页面比较。同一请求最多等待 35 秒，不把旧云端结果保存着等本机坐标。
已经有本机坐标时直接读取；不支持的来源保留原有选择及格式限制。
这适用于共用读取服务的打开、手动、定时及唤醒入口，不授予新的上传权限。

等待只持有本次进度读取的计时器，继续观察已有采集器，不另开正文读取或联网任务。
新的页面就绪后使用该页面；真正的位置差异仍须选择，不能把字数或百分比接近当成原文坐标一致。
换账号、关书、明确原文导航及取消会撤销本次等待；休眠和采集停止不会弹出旧提示或继续请求。
超时、来源不匹配或采集失败时结束等待，保留本机待同步记录；手动操作显示可理解的暂不可用提示。
旧就绪回调和计时器不能取消或唤醒替换它的新请求。

## 综合测试中的状态隔离

此前综合冒烟的五个公众号场景模拟休眠后没有配对唤醒：下载、版本刷新、离线清理、
中断修复及目录读取。其后的同步沿用了暂停状态，因此被正常的上传检查拦住。
这些场景现已在取消断言之后执行正常唤醒，并确认旧确认框不能因唤醒恢复操作。

补齐测试配对后，原文坐标上传、确认后的本机记录保存及独立 Web 回读通过。
随后暴露的唤醒时序差异由上述读取等待修复，而非手动给服务设置“已验证”。
综合测试现在等待真实异步完成，核对原文章节、偏移及归档身份，再核对读取服务的百分比。

## 验证范围

42 项组件检查覆盖：旧行为的提前冲突对照、就绪后读取、已有坐标直读、不支持的来源，
换页后真实差异、取消／账号／文档／明确导航、暂停／停止／不可用、提前计时器、
超时与时钟回退、其他书籍坐标，以及替换请求后的旧回调。
这些检查只使用合成数据。

官方 KOReader v2026.07.1 Linux ARM64／Xvfb 在 600×800／167 DPI 与 1264×1680／300 DPI
完成整个综合冒烟，包含授权、书架、书城、资料、统计、划线、公众号、导出、同步与整书下载。
唤醒场景刻意让实际原文采集子进程延迟 0.6 秒，确认等待期间没有云端进度读取或旧上传重发；
再次休眠回收实际子进程，再唤醒建立新请求。旧等待回调和计时器不能干扰该新请求，
原文就绪后两个通道各读取一次并验证位置相同。

同一候选另通过正常选书、下载、离线重开、双向重连、正常／周期／定时／关书同步，
授权保存恢复和云端成员操作的两尺寸合成回归。
所有账号写入与授权维护均只发往本地模拟服务，没有读取钥匙串或真实账号。
固定字段与代码哈希见[就绪等待与综合验证证据](validation-assets/2026-11-10/source-comparison-readiness.json)。

这仍是分辨率模拟，实体 KO2、真实账号在新组合中的写后回读、多设备并发和其他格式仍待验收。
