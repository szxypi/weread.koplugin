# CB_ 编号书籍的原生详情

当前书架中的五本 `CB_` 编号书籍已支持后台资料读取、原生详情绘制、按账号缓存及离线重开。
编号使用既有显示校验：`CB_` 后仅允许 1–64 个 ASCII 字母或数字。前缀不代表已经确认书籍来源，
本项也不构成个人书籍上传、CB_ 正文阅读或同步写入的验收。

## 数据通道

有墨水屏授权时优先固定 `/book/info` GET；允许回退时使用 Web Reader GET 中的 JSON 初始状态。
CB_ 不尝试尚未验证的 Skill 网关路径，数字编号书籍维持原通道策略。
Web 数据在后台解析，不加载网页界面或执行网页 JavaScript。
只合并既有资料白名单，保留请求期间更新的本机进度、章节、版本和待同步记录。
取消、账号或授权修订变化后的旧回调不能提交资料。

新交互先由默认离线的 `scripts/verify_cb_metadata.py` 验证，再接入 Lua。
显式复用保存会话时，先核对同账号的原生／Web 书架 CB_ 完整编号集合，最多八本，
每个地址及通道只读一次。遇到失败停止该通道的剩余读取，报告仅包含固定状态、数量和字段名。
原始编号、书名、位置和凭据只留在内存或捕获的管道。

五本真实样本的原生和 Web 资料均通过；随后两条通道各五份 Python、Lua 模型及实际 HTTPS 投影一致。
原生均提供字数，Web 样本未提供字数；没有根据其他字段推导该值。
这些真实样本未返回简介，简介排版由另列的合成用例验证。
协议阶段合计 49 个 GET，以及一本书目录的一个只读查询 POST；没有账号数据或授权 POST。
目录返回 57 章，仅验证了 Python 查询及结构，未接入 CB_ 的 Lua 目录／正文流程。

## 文件缓存与界面验收

同生产代码的候选在官方 KOReader v2026.07.1 Linux ARM64／Xvfb 中，分别以
600×800／167 DPI、1264×1680／300 DPI 运行。
每种尺寸均由全新配置联网显示五本详情，核对实际控件文字、SQLite 和 per-book 文件，再由全新离线进程重开。
四个进程共核对 20 次详情，连同全书架及首页共 131 次实际重绘。
139 条书架记录、137 本普通书进度、139 个封面条目与独立参考一致，全部书架页及离线反向翻页通过。
离线零请求；真实页面没有保存截图，也没有人工目视验收。
临时配置位于 tmpfs，凭据不写入配置文件，结束后删除。

首次原生书架读取返回 HTTP 401，界面验证随即停止，没有启动后续请求。
随后既有受保护工具仅续期一次，核对同账号、139 条书架及钥匙串回读后，重新开始上述独立界面流程。
这是独立的授权维护和读取验证，不代表已通过真实界面内的完整失效恢复组合。
包含这次拒绝、续期和界面读取，本轮实际合计 651 个 GET、一个只读目录查询 POST 和一个授权 POST，
账号数据写入为零；没有使用待回复的读完标记或 Lua 成员写入许可。

两尺寸合成服务另核对实际后台工作进程、等待时 UI 心跳、SQLite、原生资料、
原生 503 后 Web 回退且跳过网关、请求期间本机状态保护及取消后进程回收；没有新增阅读进度请求或写入。

## 后续范围

账号、章节及同步等原数字编号门槛保留。CB_ 的目录／正文、原文坐标、阅读链接导入、
批注及云端写入仍需各自验证；本项不据资料读取结果放开这些调用。
真实文件缓存 UI 使用原生优先通道；真实 Web 资料通道已完成模型／HTTPS 核对，
Web 回退 UI 本轮使用合成服务验证。
更多编号类型、真实完整续期组合、实体 KO2 和完整开发清单仍未完成，集中性能优化尚未开始。
开发凭据继续按要求保留。
