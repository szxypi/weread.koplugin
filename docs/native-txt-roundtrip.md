# 原生 TXT 一字前移与恢复

本轮实际执行两次原生位置请求，分别前进一个原始 UTF-16 单位和恢复。
两次均取得明确 `succ=1`；后续独立读取分别看到了精确目标和原始位置、完整 30 标量摘要，三项时长计数和可见书架一致。
但两次请求后的即时回读都未通过，自动流程分别停止。此后通过独立只读核对才确认状态，
因此本轮自动往返仍记为未验证，已消耗意图为 `closed_restore_unverified`，不能重跑。
生产 Lua 未修改，TXT 上传仍关闭。

## 摘要与恢复数据

前置[同位置协议](native-txt-position.md)已验证原生端点、签名和完整原摘要。
本次先只读比较六种常见换行／空白处理方式，均不能重建原摘要；继续核对发现一类差异：
原文的 CRLF 与全角缩进，在已存云端摘要中对应不同的空白序列。
不能把原始 30 字截取或任一通用空白规则当成正确摘要。

`native_txt_summary.py` 仅为本轮限定试验准备相邻目标：保留观测摘要中的全部内部空白，移走首标量，再从原文末端补一个紧接的非空白标量。
首字必须与原文唯一位置对应且只占一个 UTF-16 单位，目标摘要也必须能在规范化原文中唯一定位。
新增边界若含未知空白、组合字符、控制字符、原文末尾或歧义就拒绝，不推断新的段落格式。
百分比和章节序号保留原值；该方法不用于任意位置的生产摘要生成。

独立钥匙串意图保存完整原位置、完整目标、摘要、三项计数及版本，以便进程退出后仍能恢复。
账号、原文、来源目录、原生授权和可见书架均绑定指纹；来源目录只投影身份／格式／版本及章节，
不把社交或阅读时长元数据当成正文版本。没有正版本号时仍按当前原文快照验证，不宣称正版本匹配。
每次发送前重新读取当前原文、目录、Reader、原生版本与两端位置；保存领取并回读后才执行该槽位。
全部恢复数据仅在钥匙串，不写入普通文件；完成后的消费记录保留。

## 实际经过与限制

[去敏证据](validation-assets/2026-11-12/native-txt-roundtrip.json)保留失败和收尾，未把它们改写为完整自动流程通过：

1. 零写入预演通过；随后只发第一条前移请求，明确成功回执后的即时读取未通过即停止，未自动恢复或重发。
2. 独立只读进程重新取得原文和目录，两次核对两端精确目标、完整摘要、原始计数和可见书架一致。标识符统一比较字符串／数字形式，不将 JSON 类型差异当成章节变化。
3. 仅使用尚未领取的恢复槽位，再次完成前置检查后发出唯一恢复请求，得到明确成功回执；即时读取仍未通过即停止。
4. 独立只读进程两次重新取得原文、目录和两端进度，全部核对到保存的原始状态，零写入结束本次核对。意图保留两次已消耗且自动流程未验证的记录。

合计两次账号数据 POST、零授权续期、零 Web 写入、零历史时长上报。
没有保存首次即时回读的原始正文或完整字段，不能还原当时的具体差异或延迟时长；
观察到的是即时检查失败、稍后独立精确核对通过，不能断言具体服务端缓存或复制机制。
以上只核对可见位置、摘要、三项时长计数与书架，不证明全部服务端历史、最近阅读时间或全部统计未变化。
原文有 CRLF，本轮不证明 BOM、非 BMP、跨章、多设备或实体 KO2 的云端写入行为。

## 回读与中断处理的改进

实际尝试后，工具补充持久保存明确成功回执的阶段，回执已保存但位置尚不可见时保留该阶段，
独立新进程可只读核对完成。未知回执仍不能升级为已确认状态；旧记录没有补造成功回执或改换结论。

在明确成功回执后最多读取四次，间隔一秒；两个端点各自只能显示完整原状态或完整目标状态，
允许两端暂时各显示一种已知状态。任意其他位置、摘要与偏移的部分组合、时长／书架变化、授权或来源异常都立即停止。
这只重读，不重发 POST；未知回执只观察一次，不进入等待或自动恢复。读次数和两次修改上限均有独立边界。
保存的明确恢复回执可以在后续两次精确原状态读取后结束；没有保存回执的旧试验仍只能按未验证状态收尾。

新增 35 项离线检查覆盖完整摘要边界、恢复数据跨实例回读、阶段与回执替换、槽位耗尽、来源／授权变化、
未知／丢失回执、只读恢复核对、两端可见性差异和有限读取。共享实验互斥测试改用统一资源栈，
避免多个保护项叠加触及 Linux Python 的静态嵌套限制；原测试断言保留。
改进后的等待／回执阶段已通过离线测试，未重发已消耗的真实试验来伪造通过证据。
