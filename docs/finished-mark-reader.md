# 阅读器中的读完标记与进度同步

正在阅读时，可从微信读书菜单的「书籍详情 → 书架状态」修改读完标记。
读完标记的后台任务不会移动原生正文位置，也不会发送阅读进度；手动或定时同步是独立操作。
如果独立同步改变了云端位置，读完标记会保留待核对记录，再明确选择保留当前云端状态，不能把新位置改回旧值。

## 修复旧详情缓存覆盖阅读状态

并发验收复现了一个实际问题：进度上传完成、待上传记录已清除后，再打开书籍详情会从旧 SQLite 详情中
补回 `pending_upload_position`、账号和原因。这会使已完成的上传重新显示为待同步。

现在详情缓存写入时排除阅读状态，读取旧详情时同样过滤，且不删除或改写旧数据库记录。
详情界面只把缓存及入口快照中的元数据合并到最新本机书籍记录；阅读位置、待上传记录、发送日志和会话字段
统一按每本书的阅读状态字段表保护。书名、作者和下载路径仍可合并，已有本机待上传位置继续保留。

单元检查覆盖全部 25 个阅读状态字段、已清除记录和仍有待上传记录，以及陈旧入口快照。
另在 KOReader 的实际 SQLite 中执行 13 项新缓存过滤、旧行兼容和不修改调用方的检查。

## 验收范围

KOReader v2026.07.1 Linux ARM64 原生运行环境，实际 PluginLoader、ReaderUI、CRE、DocSettings、SQLite、
后台工作进程及本机 HTTP，分别以 600×800／167 DPI 和 1264×1680／300 DPI 执行：

- 从插件首页／书架／书城选书，下载章节，在正在打开的原生阅读器内进入读完标记入口。
- 标记、恢复、HTTP 200 空回执后的独立读取；取消与关闭后的过期确认均不发送修改。
- 预检位置变化阻止修改；发送后位置变化保留待核对记录，只读接受不发送修改。
- 在标记响应尚未返回时，分别完成一次独立手动同步和定时同步。随后核对新的上传位置、完整阅读状态、
  待上传及发送记录，不复活旧待上传记录，不覆盖新的同步结果。
- 每种尺寸五次合成标记修改；正文 SHA-256、当前原生位置和实际保存的原生附注保持一致。
  后续关书同步及全新进程离线重开通过，离线重开零 HTTP 请求。

原先文件管理器中的读完标记用例两尺寸重新通过，包括中断后新进程只读核对；每份配置共八次合成修改。
首页／书架／书城／统计／授权，以及阅读、来源／授权恢复、成员管理与读完标记的组合回归也以两尺寸通过。
这些结果均仅使用合成账号。本批真实微信读书 GET、数据 POST 和授权 POST 都为零。

第一次检查把 JSON 字段顺序变化误判为状态改变，已改为完整字段和值比较；之后两次检查明确复现上述旧缓存问题，
均保留为失败，不计入最终通过记录。修复后两尺寸及组合流程均以全新配置重跑。
本地完整检查为 75 份 Python／918 项零跳过、207 组 Lua、572 个静态文件零警告／错误、
574 个 Lua 语法、219 个 Python 编译、命名空间、四时区及 TLS 通过。
