# 历史统计零桶的独立核对

[原单次试验](readtime-cross-day.md#实际单次发送与停止后的只读核对)已消费一个请求，收到明确回执，
但原始严格比较未通过。旧计划、回执和请求额度保持，不重发，也不将原试验倒改成通过。
本阶段把随后找到的两个零桶差异实现为独立规则，用新工具只读验收。

## 比较规则

`readtime_statistics.py` 和 `weread.lib.readtime_statistics` 使用同一规则：
月份集合、总时长、日数和全部已出现日桶的值须符合明确目标；只允许原来已有且值为数字零的日桶消失。
每个消失的零桶都计入审计数量。新增零桶、非零日桶消失、日桶值变化、额外字段、错误月份、
不规范日期键、布尔值和非有限数均不接受。目标本身仍是原日期增加两秒、发送当天不增加；
日数的零或一增量与原发送协议保持一致，不用于掩盖额外秒数。

这是时长语义核对，不把桶的存在性变化隐去，也不修改前一次试验保存的判断规则。
该纯模块不提供网络、授权、队列领取或回执推进能力。

## 有界重建与实际只读验证

旧计划只保存了完整时长投影（月份、日桶、总时长和日数）的摘要，原进程结束后未保留明文统计基线。
新工具不会声称直接取回了那份明文，也不采用一个“看起来相近”的当前统计作为基线。
它仅在内存中逆向扣除原日期及月总数的两秒、枚举零或一的日数变化和最多两个缺失零桶，
每个候选必须精确匹配旧计划密封的完整 SHA-256。必须只有一个重建结果，并再次经过上述正向比较。
无法重建、结果不唯一、任何非零变化或读回不稳定均停止。后续新上传仍应直接保存完整私密基线，
不能依赖这种有界重建处理所有未知结果。

`verify_cross_day_audit.py` 默认离线；以下调用只读，不发时长、位置或授权请求：

```bash
python3 scripts/verify_cross_day_audit.py --saved-session
```

实际运行还通过私有捕获管道将两轮月度投影交给 KOReader 的 Lua 模块比较，没有写入普通文件或展示真实内容。
两轮均精确匹配原统计摘要：逐书阅读时长与原日期日桶增加两秒，发送当天增量为零，
两个原有零桶被删除，日数不变。Python／Lua 结果一致；原始来源、原生／Web 位置、目录、
两端版本、原标记／想法／书架状态和原采集保持。

新增 8 项统计规则测试、11 项只读审计测试及 16 个 Lua 检查覆盖变化、时间、跨月、
零桶存在性、摘要不匹配、无回执范围、存储损坏、配置保存失败、私有管道及不可重用。
完整 Python 为 135 个模块／1715 项，零跳过；259 组 Lua、741 份 Lua 语法及 739 份静态检查通过，零警告。

## 原试验的本机封存

新工具另有 `--close-unverified`，只对明确已确认回执的同一条记录，在重新完成两轮只读核对后封存。
封存保留原计划、尝试编号、唯一已消费次数，以及可以反向精确验证原确认记录的摘要；
新审计明确写入“原试验未通过、原回执保留、禁止重放”。状态为 `closed_unverified`，不变为 `verified`。
所有后续领取和推进均拒绝，其他开发试验则不再被一个已结束的试验永久占用。
该本机封存机制已经测试，实际封存另行记录，不能把准备文档当作执行证据。

本阶段只验收原有实际两秒窗口的归属和零桶规则；Lua 历史发送器、实体设备账本补传及 UI 仍待接通。
原采集没有替换、回拨或重新发出。生产包增加一个纯比较模块，原生页面流程未改变；
没有重复执行未变页面的真实账号写入。固定记录见[零桶核对证据](validation-assets/2026-11-17/readtime-zero-buckets.json)。
