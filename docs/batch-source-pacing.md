# 批量正文读取的请求间隔

批量下载在后台任务中读取正文时，Reader 和章节分片响应后等待一秒，再继续下一次读取。
间隔位于可取消的子进程内，界面仍可刷新或取消下载；单章阅读不增加等待。
此改动处理实际整书下载中断，不属于后续的整机性能或耗电专项。

## 已有失败与对照

同一排序首本 CB_ 书籍的独立 Python 预检曾完整读通 57 章，原始来源共 1,153,077 字节。
旧生产候选两次原生下载分别在第 56／46 章收到缺少书籍身份的阅读页，随后位置回读返回 -10102。
这些失败仍保留在[原交接记录](cb-file-handoff.md)，没有跳过章节或更换书籍。

限定诊断只给原生 Reader／正文请求增加一秒间隔，既有账号、传输范围和来源校验保留。
诊断下载完成 57 章并进入 725 页原生整书，三张已打包图片能由原生组件解码，云端位置独立回读未变。
后续页首位置核对未通过，因而整例仍为 UNVERIFIED；诊断结果不能替代正常生产流程验收。
不能仅凭这一对照确定 -10102 对所有接口的含义或其服务端原因。

## 后台实现

`weread/lib/download_read_client.lua` 提供任务私有的客户端代理，保留原响应与原设置，
只对严格 HTTPS Reader GET 和既有正文／样式分片 POST 增加等待，不增加、改写或重发请求。
原界面客户端、进度查询、账号写入、授权续期、目录和外部图片请求不受该代理的等待影响。
`Downloader:_runInterruptible` 仅在后台批量任务中构造代理，初始化、正文及需要后台处理的资源步骤使用同一规则。
取消仍沿用原生 Trapper 的终止和回收流程，已完成章节保留，已有完整 EPUB 不被半成品覆盖。

单章任务保留原客户端。缺少后台进程能力时，既有前台兼容分支不插入阻塞等待；
不能据 Linux 原生验收推断该兼容分支、其他平台或实体 KO2 已通过。
代理不改变读取失败后的既有有限重试、严格同书核对或授权恢复策略，更不授权任何新的账号数据写入。

## 位置核对工具

独立 DOM 核对需要文字 XPointer，而原生页首可落在图片或结构节点。
验收工具现只在同一当前视口内解析可见文字，保留边界前的可见字符，不跨章节借用前一字符，
纯图片页或下页才有正文时拒绝。随后仍以完整 DOM／原文模型独立核对实际偏移，未删除坐标相等断言。
九项工具检查覆盖结构节点、相邻章节、纯图片页、已有文字点及滚动视口。

跳转后也不把逻辑书签假定为文字点。改为独立采集实际应用且仍位于当前页的文字锚点，
再次要求原文偏移相等；跨文件交接使用同样的独立检查。首次正常候选因此未通过的记录保留，
并非删除断言后将旧失败改为成功。

## 正常候选的真实验收

同一生产候选在官方 KOReader v2026.07.1 Linux ARM64／Xvfb 中完成两轮正常流程，均未启用诊断延迟。
每轮重新选择当次完整 CB_ 书架排序的首本，独立核对全部 57 章来源、目录／版本及云端原位置；
正常续读章节保留，不为测试更换章节。书籍编号在该轮内绑定到清单与原生进程，公开记录不保留跨轮编号封印。

- 600×800／167 DPI 为 725 页，1264×1680／300 DPI 为 780 页。
- 逐章原始摘要、2,113 段原文、两个正文图片引用、三张打包图片（含封面）、spine 顺序和 ZIP CRC 均通过。
- 实际来源回执、可见正文、翻页、后台原文采集、位置窗口和双向原生跳转通过。
- 整书→单章→整书均使用正常插件入口，原始正文与偏移相同，各包身份不同，不授予上传权限。
- 两轮均通过关书和全新离线进程；上述交接在离线也成立，零 HTTP，整书字节及页码／原生位置保持。
- 独立回读云端位置未变；配置和正文仅在 tmpfs／捕获管道中使用，临时配置清理，真实界面没有截图或人工目视验收。

包含本轮限定诊断、首次正常候选的位置核对失败及最终两轮验收，共 585 个 GET、
1,623 个只读目录／内容查询 POST，零账号数据及授权 POST。旧两次下载失败的计数另保留在原交接记录，不重复相加。
现有授权继续保存在本机钥匙串至整体目标完成，没有复用任何旧数据写入许可。

## 合成取消与回归

随后在实际后台读取间隔内，确认界面至少两次响应，通过当前可见下载窗口的按钮取消，
核对工作进程退出、防休眠保护释放、当前阅读器未被切换、旧完整 EPUB 摘要及本机／待同步位置保留。
这是实际 Trapper 子进程和真实一秒等待，不在生产代码中为模拟环境绕过间隔。
