# 原生读完标记新策略实际验证

新单次策略已完成本人账号的真实原生「标记读完 → 独立回读 → 新预览与确认 → 恢复未读完 → 独立回读」。
恰好两次生产原生数据修改，原有完整书架标记、可见分组投影和精确阅读位置核对一致；待核对意图已清理。
执行基于用户的继续执行授权，未重跑此前已经消费的严格回执试验，也没有把其历史未知结果改写为成功。

## 生产策略与独立核对

每次仍是独立的生产预览与确认，产品不会自动标记后恢复。
预览绑定同账号、书籍、完整书架标记、原生章 UID／序号／偏移／精确百分比；确认后先 FULL 提交 SQLite 意图，
再原子领取并派发一次请求。HTTP 200、`status=1` 或未知对象不作为成功回执的猜测依据。
写后另做书架与位置 GET，只有完整预期投影出现、其他字段和精确位置一致，并保存本机快照后，才结束生产待核对记录。

这次执行器在独立钥匙串条目一次保留最多两个名额，且启动记录排他创建，已消费记录不能重跑。
同一内存计划先完成零数据修改、零保留额度的真实预演，再重新读原状态，才启动实际执行。
第一步生产任务和 SQLite 缓存均核对后，宿主另做完整书架与精确位置读取，并核对可见分组；通过后才放行新的恢复预览。
第二步也必须分别完成生产核对和宿主核对，最后再次独立确认原状态，才清除专用意图。
宿主没有数据 POST；原生传输只允许所选书号的标记、恢复各一次，且恢复须等待第一步宿主确认。

位置、其他书架标记、成员或可见分组变化，未生效、宿主失联、执行器回执不匹配或中断均停止，未知修改不重发。
回执本身丢失时，生产单次策略仍可通过完整新读取确认当前状态；本批模拟分别覆盖 HTTP 503 与空返回体，均不重发。
新增只读恢复要求连续两次书架／位置读取证明原标记、可见分组和精确位置都已恢复，不发送修改，
也不会据此把中断试验判为成功。新意图独立于既有 Python 试验、原生成员、划线、样式和书签意图；共用检查会保留跨试验阻止。

## 实际范围

官方 KOReader v2026.07.1 Linux ARM64，600×800／167 DPI 的真实原生详情、状态菜单、两次确认、后台工作进程和 SQLite 均通过。
正式同计划预演为五次原生 GET、零数据 POST；实际阶段为十五次原生 GET、两次数据 POST，宿主共十七次独立 GET（含计划准备与预演）。
当前书架为 140 本，测试全程成员数不变。隔离配置中原有本机进度、待上传记录及文件字节保持一致。
目标原本就在书架中，最后仍在书架中且恢复未读完；未发送书籍、划线或想法的新建／删除请求。

初次只读准备成功，之后预演准备读取观察到一次真实 HTTP 401；当时零数据修改、零额度保留、未启动原生界面。
只进行一次已有的受保护续期，核对同账号 140 本书架和钥匙串保存回读，未返回刷新令牌时保留原值。
续期后的零写入真实预演通过，才启动新的两步执行；实际两步授权 POST 为零，前置维护授权 POST 为一。

读完日期、操作历史、排序及服务端未返回字段不属于完整恢复保证。
原有严格回执策略的历史失败继续保留；本次证明的是新单次策略的状态与精确位置核对，并不替代多设备并发或整机断电验收。
实际界面只验收 600×800，KO2 分辨率使用合成数据，不能描述为实体 KO2 通过。
