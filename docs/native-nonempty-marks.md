# 已有笔记书籍的原生划线实际验证

已在本人账号中完成原生「新建测试划线 → 改为蓝色 → 改为波浪线 → 删除」四步往返。
测试书原有 52 条划线、3 条本人想法，选中章节原有 3 条划线；全体书架为 140 本。
每步均独立核对全部原记录、书架标记和原生精确位置，最后核对 Web 精确位置与完整章节索引；结果一致。
测试划线和专用待处理意图均已清除。本批没有改变生产插件功能、入口或版本。

## 真实原生范围

使用官方 KOReader v2026.07.1 Linux ARM64、600×800／167 DPI，插件直接渲染原文与原生控件。
新选区避开原有划线、位置书签和本人想法，引用与原文坐标在保存前独立核对。
同一内存计划先拦截第一条生产请求：零数据提交、零额度保留，仍完整核对原有集合与位置。
重新读取原状态和交接 Web 会话后，才执行四步实际流程：

1. 正文选区的「保存划线」创建荧光笔／默认色记录。
2. 从本人划线列表找到新记录，通过「修改划线颜色」改为蓝色，保留荧光笔线型及其他字段。
3. 再次找到该新记录，通过「修改划线样式」改为波浪线，保留蓝色及其他字段。
4. 仅删除这条新记录，核对所有原记录、章节索引和阅读位置恢复。

实际阶段恰好四次原生数据 POST、26 次原生标记流程 GET；零提交预演为 12 次 GET。
宿主在准备、预演与执行期间另做 57 次原生 GET，包含完整状态与元数据读取；选书前置为 12 次 GET，分别受既有 80 次限额约束。
宿主没有数据 POST；本轮授权 POST 为零，没有续期或重新扫码。
生产后台任务、SQLite 缓存、正文图层、事件循环响应及恢复原文位置均通过。
灰度正文与颜色字段分别核对，不把蓝色字段描述为墨水屏彩色显示。

## 中断与原记录保护

新流程使用独立钥匙串作用域和独立协议，旧样式试验不能授权本轮操作。
一次保留最多四个名额，启动记录排他创建；已消费或未知步骤不能重跑。
每次提交前，生产 FULL SQLite 意图与测试门控都持久记录准确请求摘要、步骤及目标。
下一步只有在生产核对与宿主独立完整回读均通过后才放行；原有记录从不作为修改目标。
改色只能改变颜色，改线型只能改变线型；引用、范围、时间或其他字段改变都停止。
最后要求完整原状态一致，才结束专用意图。排序、历史和服务端未返回字段没有完整恢复保证。
