# 本机书籍状态保存失败与提交前中断

修复了 `BookStore` 把关闭文件失败当作保存成功的问题。缓冲写入可能先返回成功，
真正的写入错误直到 `close` 才出现；旧逻辑仍会改名发布截断的临时文件，丢失上一份有效记录。
现在写入与关闭都成功后才替换旧文件，失败返回原错误并清理本次临时文件。
这一公共路径覆盖书籍资料、阅读状态、文章目录和下载清理后的资料保存。

发送记录也使用该路径。关闭失败时，`SourceDispatch.begin` 不返回可发送的回执，
原检查点和待同步位置保留；即使模拟关闭失败时文件字节碰巧完整，也不能据此批准发送。
本项不修改接口、阅读坐标或云端同步策略。

## 实际内核写入错误

Linux ARM64 的实际 KOReader LuaJIT／JSON 下，监督器把独立子进程的文件上限设为 256 字节，
忽略 `SIGXFSZ`，用 1 KiB 左右的真实 JSON 触发 `EFBIG`（错误码 27）。
六个入口均观察到 `write` 成功、`close` 失败：阅读状态补丁、发送记录、资料保存、阅读状态保存、文章目录保存和下载资料清理。

基线 `b1da897` 的六项均用截断文件替换了原文件；一般保存返回成功，发送记录随后因回读失败未取得回执。
修复后的六项均返回失败、原目标文件逐字节不变、临时文件清除，共十二次最终对照。
这验证的是文件大小上限导致的延迟错误，不把它描述为实际磁盘耗尽或所有设备故障的验收。

离线 `book_store_spec.lua` 增加关闭失败、完整字节但关闭不确认、真实发送门槛及新实例回读检查。
64 位 Linux CI 还在本进程短暂降低文件上限触发内核错误，随后恢复原上限和信号处理；其他平台保留关闭失败的模拟检查。
64 位 Linux 共 35 项断言，macOS 共 32 项断言。

## 发送记录提交前的完整进程中断

新增 `before-state-commit`：生产发送记录已经写完并关闭临时文件，尚未改名替换旧检查点。
测试只在实际改名边界停住，由外部监督器终止整个阅读器会话及后台进程，不伪造发送回执或待确认记录。

600×800／167 DPI 与 KO2 分辨率 1264×1680／300 DPI 各覆盖手动同步、关书同步和周期时长上报，共六组。
每组事先保存有效本机检查点及原生阅读记录；中断后由独立 Python 检查旧文件和未提交临时文件。
旧文件保留本机位置、没有新发送记录，临时文件含本次完整记录；模拟服务没有接收本次发送。

随后两个全新原生进程依次完成只读联网比较与离线持久状态复核：

- 不把 `.tmp` 视为已提交记录，恢复原页与精确原文位置，保留本机待同步意图。
- 云端与本机不同，须明确选择；比较前后均不自行上传，周期报告也受未核对状态约束。
- 第一次重开零数据 POST，最终离线重开零 HTTP，阅读器及后台进程全部回收。

原有三个已提交中断点另各回归一个发送分支，共三组，确认旧待核对记录、已接收报告的独立读取确认和禁止重发仍有效。
此前完整十八组的历史范围见[进程中断说明](progress-process-loss.md)。
