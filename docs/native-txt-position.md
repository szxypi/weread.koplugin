# 原生 TXT 同位置、零时长协议

真实账号的一次原生 `POST /book/read` 已得到明确 `succ=1`，并通过独立回读。
该结果只证明服务端接受本轮同位置请求；相邻位置写入、恢复、全部 TXT 字符边界和生产上传仍未验收。
生产 Lua 没有修改，TXT 上传仍关闭。

## 来源与前置检查

协议字段参考固定版本的[墨水屏接口目录](https://github.com/teng-lin/weread-omni/blob/88bd2e095d7d7ee423eaadf8f40653e72c5be6d4/docs/endpoints.md)
及 [Moon 原生请求构造](https://github.com/AnkioTomas/moon/blob/43b2181da6eb5285b62114da85e1413d2f8464e4/book.koplugin/source/wechat/app.lua)。
复用项目已归属的签名实现，另用 Moon 原文件在官方 KOReader Lua 环境中计算合成数据签名向量，独立核对零时长请求。
许可证和来源保留在[协议归属文件](../integrations/licenses/readtime-sources.txt)。

新的只读检查首先遇到实际 HTTP 401，没有执行数据写入。随后只续期一次，钥匙串保存后回读验证同账号和 140 本书架；
新响应未返回 refresh token，保留原值。没有制造失效，也不在写入异常后续期重发。

重新取得当前 TXT 原文，核对目录、Reader、Web 独立进度及原生进度。两端的书、章节、索引、偏移、百分比和完整 30 标量摘要一致，
原文唯一摘要起点与原始 UTF-16 偏移匹配。本轮原文包含 CRLF，未包含 BOM 或非 BMP 字符，不能据此宣称后两者的云端坐标已验证。

最初要求正版本号的检查未通过，后续明确查明原生版本为 0、Web 目录没有版本字段。
新检查仅允许“正版本且两端一致”或本轮“原生 0 且 Web 缺失”两类情况；后者明确记录 `book_version_matched=false`，
仅依据实时原文快照，不将缺失版本推定为正版本，也不改写旧检查结果。
原生接口未提供 `chapterProgress`，请求中不猜测或补造该字段。

## 单次请求与实际结果

`native_txt_read_model.py` 单独构造零时长的位置请求，保留完整原摘要、实际版本和原始百分比。
`hours=[]`，所有阅读／听书时长为 0；不使用纯时长的重发标志，也不读取或上报历史时长记录。
账号、原文快照、完整基线、双端授权、书架／时长计数和精确请求体的指纹绑定到独立钥匙串意图。
发送前再次核对原状态和授权，原子保存领取并回读后才发送；时间过旧、请求被改动、重复调用或待确认实验均禁止派发。
未知回执、断网或状态变化立即停止，不自动重发。

[去敏记录](validation-assets/2026-11-12/native-txt-position.json)包含失效证据、单次续期、只读预检、零派发计划和实际请求：

- 一次账号数据 POST，响应 HTTP 200 且明确 `succ=1`；没有 Web 写入，也没有历史时长上报。
- 独立原生与 Web 回读确认原位置、完整摘要一致；原生三项时长计数及可见书架状态一致。
- 意图已转为 `retired`，保留一次已消耗记录，不能再运行同一试验。

三项计数和可见状态一致不能证明全部服务端统计、更新时间或历史都未变化。
此前两条 Web 未确认记录继续保留原状态，没有重发或解释为成功。
开发凭证留在钥匙串直到整体目标完成；真实身份、书名、坐标、正文、摘要、签名和任意回执正文均不写入普通文件或公开记录。

新增 18 项离线测试覆盖独立签名向量、完整摘要、版本条件及冲突字段、精确回读、单次领取顺序、失联、未知回执、
状态变化、共享实验互斥、旧协议隔离和默认不联网。下一阶段另建限定相邻位置／恢复试验，通过后才实现 Lua 发送路径。

```sh
python3 scripts/verify_native_txt_position.py --saved-session
python3 scripts/verify_native_txt_same_point.py --saved-session
# 本轮 v1 已消耗，不得再 --apply；--resolve 仅用于仍待核对的同一意图。
```

后续[一字前移与恢复](native-txt-roundtrip.md)已实际看到精确目标和恢复原状态，两次明确成功回执均保留；
即时回读未通过，独立稍后核对一致，自动往返仍按未验证收尾，生产发送未启用。
