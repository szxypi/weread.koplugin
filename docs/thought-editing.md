# 原生想法编辑

从「我的云端划线」打开一条已保存的文字划线，可「写私密想法」。从「我的云端想法」打开本人记录，可编辑或删除。
编辑器使用 KOReader 的多行输入框和键盘，提交前显示完整文字；新建固定私密，编辑保留原来的公开／私密属性。
删除需要单独确认，不会操作其他想法。当前入口只支持普通数字书号和已验证的服务端划线引用，不在阅读器中任意选区建笔记。

两种列表都有「本机想法草稿」及「核对上次想法修改」。草稿可离线保存、查看、删除或恢复到原引用；恢复要求云端引用版本仍一致。
其他书籍的草稿可以查看和删除，需要回到对应书籍和列表才能继续编辑。
每账号最多 16 条、正文合计最多 2 MiB，满额不自动清理旧草稿。提交前必须先成功保存草稿，文字不附加实验编号。
草稿及操作状态在账号自己的 SQLite 文件中，既有云端想法缓存仍使用独立的有界表；不把文本或集合写进 `settings/weread.lua`。

## 一次提交与独立回读

独立 Python 先验证真实私密新建、编辑、删除协议，见[限定实验](private-thought-experiment.md)。
本实现另外核对三份任意用户文字的 Python／Lua 计划；Lua 生产预检通过捕获的真实数据重放固定 GET 后生成相同计划，没有发送账号数据修改。

1. 后台完整重读本人想法；新建还读取本人划线与书籍版本。所选旧想法或划线变化时停止，保留本机草稿。
2. 用户确认后，后台再次重读并核对整个想法集合、目标引用和请求摘要。预览有效期为 120 秒，切书、换账号、授权变动或关闭使旧操作失效。
3. SQLite `BEGIN IMMEDIATE` 串行领取操作，连接使用 `synchronous=FULL`。先落盘 `prepared`，真正派发前原子领取为 `pending`，只调用一次固定 POST。没有自动续期、重定向或写入重试。
4. 最多三次完整 GET 核对预期结果。创建要求唯一新记录、文字与私密引用一致，且移除该记录后恰好等于原集合；相同文字的原有记录不能冒充新建。
   编辑／删除要求整个集合与唯一预期修改完全一致。HTTP 200 或成功回执本身不代表核对通过，回执丢失也可以由独立读回确认。
5. 父进程先保存已核对的想法缓存，再完成操作状态并仅清理匹配版本的草稿。存储失败、不明确回读或中断保留待核对状态。

未派发的 `prepared` 可原子取消；即使旧子进程随后运行，也不能再领取已取消的操作。
已领取的 `pending` 在关闭、杀死工作进程及下次打开后保留，后续只读核对，不重放请求。
如果结果仍不一致，用户可以继续核对，或经过两次明确选择接受当前云端状态；这只解除本机等待并保留草稿，不能撤销已发请求，也不能排除服务端延迟生效。
因此界面会提示先检查想法，再决定是否另建一份。

## 验证范围

- 生产请求构造与独立 Python 的真实三份只读计划一致；本批账号数据 POST 为零。
- Lua 模型／传输、单次派发、预览归属、草稿和持久状态测试，以及实际 KOReader SQLite 的双进程竞争、同步等级、回滚、配额和账号隔离通过。
- 600×800 与 KO2 尺寸 1264×1680、300 DPI 的实际 PluginLoader／FileManager／多行输入／确认／删除流程通过。
  覆盖离线保存、其他设备改动、回执丢失、预期状态未出现、显式接受、取消未提交操作、提交后杀死工作进程和全新进程只读核对。
  所有输入、数据库和请求均为合成数据；安装包逐字节核对，临时配置删除，截图已目视检查。
- 已另回归两尺寸划线、本人想法、原文跳转、首页／书架／书城／统计／授权及正常阅读／同步／恢复组合。

这些不代表实际账号的 Lua 原生写后回读已验收；此前三次 Python 实验许可已使用，不能复用。
公开想法的编辑／删除、更多书号和复杂引用、整机断电及实体 KO2 尚未实测。当前电脑未检测到 Kindle USB 或 KOReader 挂载。
附件、想法引用跳转及阅读器任意选区创建仍在后续清单，集中性能优化尚未开始。
