# 原生 TXT 同步核心模块

原生请求构造、单次任务与 SQLite 回执记录已迁入 Lua；尚未接入 TXT 的生产菜单、位置准备或自动同步入口。
本轮通过真实账号的两份完整请求比对，但未执行 Lua 账号修改，也未宣称完整原生界面流程通过。
此前[Python 一字前移与恢复](native-txt-roundtrip.md)的未验证消费记录保持原样，不重跑或升级旧记录。

## 协议与位置检查

`weread/lib/native_position_protocol.lua` 复用已有归属的原生签名变换，按 Python 原型构造零时长 `POST /book/read`。
保留完整摘要、实际版本、原始百分比和明确章节字段；不带历史时长、纯时长重发标志或推断的章内百分比。
签名与来源见[协议归属](../integrations/licenses/readtime-sources.txt)，独立参考向量与[同位置验证](native-txt-position.md)一致。

摘要严格检查 UTF-8、标量数、字节数和控制字符，不截短原始状态；章节编号转数值前限制在精确整数范围。
位置响应继续使用已有严格投影，并复用同一节点选择器读取三项时长计数，拒绝缺字段、歧义、冲突编号和外国书籍。
空小时列表必须经过实际客户端编码器确认为 JSON `[]`，不能把空对象当作空数组发送。

`native_position_contract.lua` 绑定书籍、完整前后位置摘要、三项计数、实际版本、原文哈希、可见书架哈希、文件身份及 `raw_txt_utf16` 类型。
这些绑定只能防止计划被替换；调用方仍须独立证明当前文档、原文哈希、位置与来源身份一致。
原生版本为 0 时不制造正版本号，也不据相同版本推定正文未变。

## 单次修改与持久回执

`native_position_store.lua` 在当前账号的库数据库中保存一个有界意图，所有写入使用 SQLite `synchronous=FULL` 和立即事务。
准备、已领取、明确成功回执、独立核对完成分别保存；领取成功并提交后才可能发送。
各阶段核对账号、操作身份、不可变计划及准确修订号，不能跨账号或用旧回执推进状态。
没有明确成功回执不能跳到核对完成，已领取记录不能作为未发送清除，也不允许重放。

`native_position_task.lua` 在真实发送前重新核对原生书籍版本、完整原位置、时长和书架，验证当前授权及调用方的来源上下文。
只有显式提供上下文检查且仍有效才允许派发；请求不使用或保存 Web Cookie。
成功回执先持久保存，再最多四次只读核对，间隔一秒；只允许完整原状态或完整目标状态。
未知位置、摘要与坐标的部分组合、时长或书架变化、取消和授权变化都停止，不重发 POST。
未确认回执最多观察一次，不进入等待或自动恢复；已经发送的 HTTP 401 不续期重发。

已有成功回执的意图可以由新进程只读核对两次并完成；同账号重新登录允许只读收尾，旧登录会话的发送仍禁止。
只有核对完成或确实尚未领取的准备记录可清除。上层完成、取消和异常路径仍须正确使用这些状态；
后台工作进程不得调用继承的原生文档句柄，后续服务层需由父进程负责文档事件取消。

## 验证结果及范围

[固定字段记录](validation-assets/2026-11-12/native-position-core.json)包括真实只读字段比对和合成候选运行：

- 真实账号重新读取原文、目录、Web／原生位置和版本，将原位置及限定相邻位置分别送入官方 KOReader Lua 环境。
  Python 独立构造期望请求，与 Lua 输出逐字段比较完整请求、摘要、签名、数值和 `hours=[]`；还将真实原生响应送入 Lua 核对严格位置和三项计数投影。
  两份均一致，零账号数据或授权 POST。
- 新增两组 Lua 规格，分别 46 和 334 项断言，覆盖完整请求、非法 UTF-8、完整摘要、严格响应、明确回执、未知回执、有限等待、取消、授权变化及只读恢复。
- 真实 SQLite 验证 26 项：两个 fork 进程竞争时仅一个可领取；提交失败回滚，重新打开及独立进程保留完整摘要和成功回执；旧修订号、跨账号和损坏记录均拒绝。
- 候选安装的 273 个生产文件与 ZIP 逐字节相同；五处模块函数确认来自实际候选目录，再执行上述协议／任务规格和 SQLite 检查。
  合成配置与数据库放在临时内存文件系统，完成后已删除。另有十二项 Python 比对边界检查，拒绝布尔数值、空对象、截短摘要、未知字段、错误子进程输出和超限私密输入。

候选检查只证明安装内容和核心协议／任务／数据库行为，不等同于原生阅读器界面或真实 Lua 网络修改的端到端验收。
