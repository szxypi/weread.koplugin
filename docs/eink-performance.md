# 墨水屏性能

## 首页状态更新

首页时钟、电量或阅读概览变化时，若首页位于最上层且布局稳定，只重绘对应的状态行；有弹窗覆盖、镜像布局、旋转待处理或几何信息不可靠时继续按窗口顺序重绘。阅读概览控件重新创建导致位置失效时改为请求整屏刷新，避免原位置未刷新。

两种 KOReader 模拟尺寸下，10 次合成状态变化触发的首页整页绘制由 10 次降至零，状态行各重绘 10 次，屏幕刷新请求范围保持为状态行；普通及镜像布局共 76 对画面与原实现逐像素一致。普通布局的变化像素均在请求刷新区域内，弹窗、旋转待处理和控件重建均已测试。此结果不等于实体 Kindle 的刷新次数、速度、残影或电量；镜像布局保留原有整页绘制，详见[记录](validation-assets/2026-11-24/eink-home-status-refresh.json)。可用 `python3 scripts/benchmark_home_status_refresh.py --koreader /path/to/koreader` 复验，加 `--rtl` 检查镜像布局（Linux、Pillow、`/dev/shm` 及基准提交需可用）。

首页每分钟生成阅读概览时，用一次只读数据库查询获取统计和目标，并跳过只供完整月历使用的日期格式化；仍每次读取最新数据，不延迟目标或账号变化。在内存文件系统上的 100 次合成概览计算中，只读数据库打开从 200 次降至 100 次；短连续阅读样本的三轮 CPU 时间中位数从 13.5 ms 降至 9.0 ms，长连续阅读样本从 56.8 ms 降至 51.1 ms。四个时区的日界线、目标变化、数据损坏和账号隔离已检查；两尺寸原生首页及真实账号统计与离线重开通过。这些是批量模拟数据，不代表实体 Kindle 的速度或续航，见[记录](validation-assets/2026-11-24/eink-home-summary.json)。可用 `python3 scripts/benchmark_home_summary.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

连续阅读天数按月复用日期边界，跨月时才换算前一月；缺少月份、当天未阅读及连续天数上限的处理保持不变。724 天合成记录计算 100 次的三轮 CPU 时间中位数从 24.6 ms 降至 2.1 ms；单次计算从 726 次月份定位变为一次定位和 24 次跨月换算。闰年、跨年、缺失月份和最长记录已与旧算法在四个系统时区对照；模拟统计加载的请求数量不变。真实账号统计页面及离线重开也与独立结果核对，数据范围与限制见[记录](validation-assets/2026-11-24/eink-profile-streak.json)。这些是批量合成计算，不代表 Kindle 整体响应或续航；可用 `python3 scripts/benchmark_profile_streak.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

## 后台结果传输

后台任务返回数据时，每次界面调度最多读取四块；有数据时缩短下一次检查间隔，空闲时仍采用原来的低频检查。子进程处理短写时直接使用已有数据，避免反复复制尚未写出的内容。结果大小限制、进度顺序和取消行为保持不变。

在 KOReader Linux ARM64 模拟环境中，传输 1 MiB 合成数据的三次独立测试中位耗时从 3.44 秒降至 0.54 秒；带进度的传输从 3.64 秒降至 0.54 秒。8 MiB 结果、数据完整性、短写、中断重试和传输中取消均已验证。测试期间界面事件循环继续运行；这些数据只反映合成进程间传输，不能代表整本书加载或实体 Kindle 的速度、续航和残影。真实账号的章节读取与笔记搜索在两种模拟尺寸通过，书架、笔记和阅读位置保持不变。详见[验证记录](validation-assets/2026-11-24/eink-memory-worker.json)。可用 `python3 scripts/benchmark_memory_worker.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

## 批量任务进度刷新

后台笔记同步、图片批量保存及书架进度更新将进度条和标题合并更新；密集变化按已有刷新间隔合并，任务间歇时会安排一次延时刷新，完成时立即显示。关闭后取消待处理刷新，迟到回调不会重新绘制已关闭的窗口。章节下载及不支持后台处理的笔记同步仍立即显示状态标题。

在两种 KOReader 模拟尺寸下，100 次快速合成更新分两批送入时，主动重绘调用由 102 次降至 3 次。标题和进度条像素一致；旧版多次叠绘使圆角有少量抗锯齿像素变深，两尺寸中途画面分别有 24 和 68 个圆角像素不同。此数字不等于实体设备的实际刷新次数或耗电，真实任务间隔也会改变合并效果。记录和复验方式见[测试结果](validation-assets/2026-11-24/eink-progress-refresh.json)；可运行 `python3 scripts/benchmark_eink_progress.py --koreader /path/to/koreader`（Linux、Pillow、`/dev/shm` 和基准提交需可用）。

进度标题和进度条变化时，刷新请求进一步收窄到已绘制的弹窗；几何信息缺失、弹窗尺寸变化或越界、屏幕旋转时回退为整屏。在带说明和取消按钮的合成窗口中，600×800 的请求区域从 600×800 降至 544×146，1264×1680 从 1264×1680 降至 1147×316。两尺寸共 14 对画面逐像素一致，五次内容变化均落在请求区域内，旋转回退和取消也已检查。设备驱动仍可能对区域对齐、放大或合并，不能据此推断真机耗电和残影；详见[测试记录](validation-assets/2026-11-24/eink-progress-region.json)。可用 `python3 scripts/benchmark_eink_progress_region.py --koreader /path/to/koreader` 复验。

原生墨水屏章节包的 ZIP 内容校验优先使用经过已知结果检查的设备压缩库；解密时使用有界字节缓冲区，减少单字节字符串创建。压缩库不可用或不兼容、缓冲区无法分配时分别回退到原有实现，密码头、解压长度与内容 CRC 校验均保留。4098 组二进制内容与原校验一致，加密正文被篡改和目录校验值损坏均被拒绝。

以包含约 2 MiB 合成图片的未压缩章节包在 KOReader Linux ARM64 模拟环境中比较，连续读取三次、三轮的 CPU 时间中位数：加密包从 279 毫秒降至 115 毫秒，未加密包从 14 毫秒降至 2 毫秒。此为章节包处理的合成测试，不代表下载、排版或实体 Kindle 总耗时；详见[验证记录](validation-assets/2026-11-24/eink-native-archive.json)。可用 `python3 scripts/benchmark_native_archive.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm`、`zip` 和基准提交均需可用）。

真实账号的一本书在两种模拟尺寸下完成四个可读章节的内容核对与离线重开；另外 11 章未请求，书架和网页阅读位置保持不变，未修改账号数据。实体设备仍待验证。

无网络图片的章节在检查账号及来源未变后复用首次资源整理结果，避免再次遍历同一正文和本地图片；有网络图片时仍在下载后重新整理。对约 470 KB 合成中文章节连续处理三次，KOReader Linux ARM64 模拟环境三轮 CPU 时间中位数：纯文字从 81 毫秒降至 40 毫秒，本地图片从 81 毫秒降至 41 毫秒；网络图片模拟路径的处理与请求次数不变。会话取消、来源变化、缺图占位和网络图片重新整理均已核对；真实账号四章在两种模拟尺寸完成原文核对及离线重开，书架与网页位置不变。这不是实体 Kindle 或完整章节打开耗时，详见[验证记录](validation-assets/2026-11-24/eink-native-prepare.json)。可用 `python3 scripts/benchmark_native_prepare.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

验证已保存章节的正文与图片时，按块比较文件内容，避免为完整文件再构造一份副本；仍检查大小、内容、CRC 和重复条目。设备缺少原生比较接口时回退到有界的 Lua 比较。使用一个 8 MiB 合成压缩条目的模拟测试，三次独立进程的峰值常驻内存中位数从 28,164 KiB 降至 19,932 KiB。真实账号四章在两种模拟尺寸完成原文核对和离线重开，书架与网页位置不变。内存数字包含运行时及待比较数据，不能代表整书或 Kindle 的内存占用；详见[验证记录](validation-assets/2026-11-24/eink-archive-verify.json)。可通过 `python3 scripts/benchmark_archive_verify.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

## 阅读位置与搜索结果

普通翻页不再为没有运行中的授权恢复任务额外读取恢复标记；本地阅读位置仍逐次采集，恢复中的任务仍在位置变化时立即取消。100 次合成页面更新的恢复标记读取从 100 次降至零，100 次本地位置采集均保留；两种 KOReader 模拟尺寸的实际翻页、离线保存与重连通过。该计数只针对恢复标记，不代表翻页时所有位置读取或真机耗时。

划线和原文位置核对使用的章节索引，按原文范围一次截取连续文字，不再为每个字符维护临时表项；标签、注释、实体和字符位置的处理保持不变。10,000 组带中英文、表情、标签及不完整输入的索引与旧实现一致，并核对 40,000 个引用范围。

KOReader Linux ARM64 模拟测试中，约 960 KB 合成长段落的三次 CPU 时间中位数从 35.6 ms 降至 7.6 ms；暂停垃圾回收时的 Lua 分配增量从约 6,486 KiB 降至 2,389 KiB。另一份 10,000 段合成正文的中位时间从 15.7 ms 降至 8.7 ms。这些只测索引，内存增量包括临时分配和结果，并非进程峰值或 Kindle 实测。真实账号一章的 14 条划线与 53 条想法在 KO2 模拟尺寸完成在线核对和离线重开，阅读位置保持不变；见[记录](validation-assets/2026-11-24/eink-annotation-source.json)。可用 `python3 scripts/benchmark_annotation_source.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

长段落多次提取引用时按需保存稀疏字符位置与实体边界，单次查询不建立完整索引；正文变化时重建，章节释放后缓存随之释放。缓存数量有上限，超出时仍按原有方式核对。约 600 KB 合成长段落、分布在不同位置的 200 次引用提取，三次模拟 CPU 时间中位数从 282 ms 降至 3.6 ms；含少量实体的正文从 285 ms 降至 3.7 ms。24,000 组含实体和不完整 UTF-8 的引用与旧实现一致；测试仅测量合成数据上的批量引用，不代表真实书籍或实体 Kindle 的总耗时，详见[记录](validation-assets/2026-11-24/eink-annotation-quote.json)。可用 `python3 scripts/benchmark_annotation_quote.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

同时保留的完整引用索引进一步限制为 32 份，超过时轮换淘汰，后续再次使用可重新建立；弱引用不会让已关闭的章节继续留在内存。对同时保留 96 个实体密集合成片段的压力测试，三次垃圾回收后 Lua 内存增量中位数从约 6.0 MiB 降至 2.0 MiB；这里不含源文本建立时的内存，也不代表进程峰值或真实设备用量。淘汰、重建、释放与引用一致性已验证；真实账号一章的划线和想法在线与离线核对通过，阅读位置未变。详见[记录](validation-assets/2026-11-24/eink-annotation-cache-budget.json)，可用 `python3 scripts/benchmark_annotation_cache.py --koreader /path/to/koreader` 复验。

章节位置映射增加稀疏索引，定位时仅检查可能包含目标位置的区间；相邻区间和相互重叠的位置仍会共同核对，避免将有歧义的位置误认为唯一。5,578 组 XHTML、连续文档、TXT、重叠位置、多字符实体、长空白及边界输入与原实现对照一致。

对约 473 KB、500 段的合成中文章节，在 KOReader Linux ARM64 模拟环境中连续定位 20 次，三轮 CPU 时间中位数从 658 毫秒降至 55 毫秒，检查的字符位置从 3,215,680 降至 40,800；索引建立时间中位数前后均约 54 毫秒。索引会增加一定内存；这些数字不代表完整搜索耗时或实体 Kindle 表现。真实账号两章在 KO2 模拟尺寸通过离线跨章搜索与位置核对，书架及网页位置不变。详见[验证记录](validation-assets/2026-11-24/eink-anchor-index.json)；可通过 `python3 scripts/benchmark_eink_anchor.py --koreader /path/to/koreader` 复验（Linux、`/dev/shm` 及基准提交需可用）。

## 阅读来源摘要

阅读来源、缓存身份和同步核对共用的 SHA-256 计算优先使用 KOReader 自带实现；启动使用前会检查空内容、二进制内容及分块边界的已知结果。组件缺失、校验失败或运行中返回错误时自动退回原有实现，摘要格式和输入转换保持一致。

使用打包插件的 KOReader Linux ARM64 模拟运行三次：每轮对 1 KiB 合成内容计算 1,000 次，CPU 时间中位数从 126 ms 降至 3 ms；对 1 MiB 内容计算 8 次，从 935 ms 降至 20 ms。63 组包括二进制、边界及不同长度的摘要同时与原实现和 Python 独立结果一致。此为单项计算时间，不代表翻页或实体 Kindle 的整体速度；详见[记录](validation-assets/2026-11-24/eink-sha256.json)。

普通书和导入书在两种模拟尺寸完成阅读、来源、进度和笔记合成回归。真实账号在 KO2 模拟尺寸的隔离阅读器另完成选书、来源核对、翻页、位置回转及新进程离线重开，云端位置未变；没有账号数据写入、授权维护或真实截图。

复现：`python3 scripts/benchmark_eink_sha256.py --koreader /path/to/koreader`（Linux，使用 `/dev/shm` 临时安装，无账号或网络请求）。

章节分片校验、协议兼容及封面缓存文件名使用的 MD5 也采用同样的已知结果检查和回退机制。三次模拟测试的 CPU 时间中位数：1 KiB 内容计算 1,000 次从 47 ms 降至 2 ms，1 MiB 内容计算 8 次从 345 ms 降至 11 ms；63 组内容与原实现及 Python 独立结果一致，旧封面文件名仍可定位。普通 EPUB 与 TXT 的两尺寸下载和离线续读，以及真实账号一章的原生阅读、位置核对和离线重开通过；真实书架封面及其全新进程离线缓存也在 KO2 模拟尺寸通过。未测量实体 Kindle 或整体下载耗时，见[记录](validation-assets/2026-11-24/eink-md5.json)。

章节分片仍先校验原有摘要，再还原字符交换并解码；现在只记录需要交换的少量位置，并分批生成输出，避免为每个输入字符保留表项和构造六倍长度的位字符串。对 5,013 组合成输入、5,080 组重复及重叠交换、异常字符和分片校验与旧实现逐字节对照通过。

## 阅读时的个人笔记

个人划线、书签和想法加载时的联网检查由后台进程执行；已验证的章节来源存在于本地时，不再为每批笔记检查网络。离线阅读时，连续翻页不会反复执行可能阻塞的联网检查。如果没有收到网络连接事件，阅读界面在下次页面更新时最多每 30 秒启动一次后台检查；恢复联网后会重新读取个人笔记。连接事件仍会立即触发重新读取。

授权文件的读取也移到后台；确认离线时不读取。在线分两次获取划线和想法时，第二次在后台重新核对授权版本，版本不一致或第一次无授权时使用本地快照。两尺寸合成原生阅读测试覆盖在线与离线、授权变化以及后台进程隔离；真实账号另在 KO2 模拟尺寸分别核对一章的两条想法和两条划线，并在新进程离线重开，云端笔记与阅读位置未改变。验证前授权过期，经独立复核后续期一次并保存在本机；没有账号数据写入。未测量 Kindle 真机耗时或电量。

合成测试覆盖连续 100 次离线页面更新、后台重新检查、无连接事件的网络恢复，以及已有笔记的离线显示。KOReader 模拟运行覆盖两种屏幕尺寸、在线与离线重开及损坏缓存的拒绝；这些结果不能代表 Kindle 真机的翻页耗时、电量或网络表现。

云书签角标保留最近四个页面的可见书签结果，来回翻页时可复用；页面或排版信息不足、查询失败、笔记变化及排版失效时会清空缓存。两种 KOReader 模拟尺寸使用 512 个合成书签，首次进入和翻到另一页分别执行 512 次原生位置检查，返回最近页面执行零次，显示结果与首次一致。单元测试覆盖缓存淘汰、异常恢复和布局失效；这不是 Kindle 真机的整体速度测量。
