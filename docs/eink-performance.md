# 墨水屏性能

## 书架封面和进度的网络检查

首页、书架和书城的可见封面及书架进度属于可选的后台读取：缓存已满足时跳过网络检查；需要更新时只检查设备连接状态，不在界面线程同步探测外网域名。设备无法提供连接状态时，允许后台任务尝试，失败仍由原有超时和错误处理结束。明确断网时不下载封面，但已有原图仍可生成缩略图。手动联网操作的检查方式保持原样。

打包插件在 600×800 和 1264×1680 的 KOReader 模拟器中，通过禁止同步外网探测的书架打开、后台封面下载和进度刷新；单元测试覆盖缓存命中、断网、本地图像转换及连接状态不可用。完整 Lua 测试通过。上述测试没有测量真实网络延迟或实体 Kindle 的响应、残影和耗电；实体设备仍待验收。

真实账号的书架快照另在两种模拟尺寸完成离线搜索、分组选择和重开；书架回读未变，没有账号数据写入。验证前原生授权过期，已续期一次并核对同账号；这项只读验证没有测试真实网络下的封面加载。

当前页绘制与立即启动的封面任务共用磁盘检查结果。缺图时只检查一次设备连接状态，任务排队或休眠后恢复时则重新检查。首页的纯文字列表跳过封面文件检查。用九本合成书测试冷缓存打开、后台加载和重绘，缩略图路径检查从 36 次降至 27 次，设备连接检查从 2 次降至 1 次。实体 Kindle 的响应时间待测。

首页和书架后台取得相同的云端进度时，仍更新 SQLite 中的缓存时间和来源，保留当前界面。连续书架同时更新可见区域里的缓存时间，滚动后仍在屏幕上的书不会立即重复请求。明确的 0%、旧缓存中未经确认的 0% 和不足 1% 分别处理。两种 KOReader 模拟尺寸均通过本地 HTTP 验证，进度未变时后台完成不重建页面，进度变化仍在弹窗关闭后显示。

## 书城搜索与榜单

书城搜索、分页、榜单目录和搜索建议只检查设备网络连接状态，由后台任务执行实际请求。已有列表会保留至请求完成。查询失败时可回到与查询及批次匹配的离线结果，缺少对应缓存时继续显示当前列表。服务端明确限流时保留当前列表并提示稍后再试。

600×800 和 1264×1680 的 KOReader 模拟器均通过禁止同步外网探测的榜单加载、翻页及断网重开测试。模拟服务延迟返回 HTTP 503 时，已保存的榜单批次可恢复。真实账号在两种尺寸通过搜索、相似书籍、推荐和已保存搜索的在线或离线验证。此次采样的个性化推荐为空。实体 Kindle 的响应耗时待测。

重新打开已保存的书城结果时，完整快照校验一次，随后直接用已核对的批次生成界面数据。使用 KOReader Linux ARM64 运行环境和内存文件系统，合成 12 批公开搜索结果、每批 20 本。读取第 10 批时，书目公开资料处理次数从 500 次降至 240 次。与 `133492c4` 交替运行，9 组各 100 次读取的 CPU 时间中位数从 340.1 ms 降至 232.4 ms。测量包括 SQLite 读取和数据准备，实体 Kindle 的界面响应仍待测。

## 书籍详情与下载状态

标准 EPUB 下载和后台预取完成后，只更新当前书的下载路径和文档对应关系。已有的阅读进度文件和书架索引无需回写。使用 KOReader Linux ARM64、内存文件系统和 140 本合成书，与 `0bd0b242` 交替测量五轮。每次记录一个已准备好的预取结果，完整书籍记录读取和保存各从 140 次降至零，仅写入一次该书的下载元数据；本机处理耗时中位数从约 110 ms 降至 0.07 ms。测量覆盖保存环节，联网下载和 Kindle 真机耗时待测。

同账号已核对的书籍资料可以直接从本机记录打开，即使数据库中的详情副本暂缺。资料更新只检查设备连接状态，实际请求由后台执行。详情的下载状态在一次绘制中复用同一路径的文件检查。已确认有整书缓存时跳过章节计数。

两种 KOReader 模拟尺寸验证了本机资料恢复、后台资料更新和授权恢复。真实账号的一本书在两种尺寸通过了在线详情与新进程离线重开。文件检查次数由合成样本核对，实体 Kindle 的耗时待测。

## 分页书架和下载筛选

从本机打开首页或书架时，书目和分组共用一次只读数据库连接。并发保存新书架时，本次打开仍读取同一批书目和分组，下次打开再读取新批次。旧缓存缺少分组记录时仍可显示书目。合成并发测试通过，实体 Kindle 的打开耗时待测。

首次打开缓存书架或首页时，书目、云端分组、已选分组、本机分组和本机置顶使用同一次只读事务。首次显示书架沿用这次读取的置顶，随后的翻页与重绘仍可读取其他会话保存的新置顶。KOReader Linux ARM64 在内存文件系统中与 `2beabc6a` 交替测量七轮。每轮读取 35 次，书目和这三项本机设置的数据库连接由 140 次降至 35 次。140 本合成书的累计 CPU 时间中位数从 18.0 ms 降至 13.7 ms，1,500 本合成书从 174.7 ms 降至 171.0 ms。并发写入、旧缓存、账号隔离及两种模拟尺寸的离线重开均已核对。测量覆盖书架数据读取，实体 Kindle 的整页打开耗时待测。

分页书架按当前页检查下载徽标，列表只为当前页计算最近阅读日期，封面不计算日期。搜索先筛选匹配书目，再检查下载条件和排序。启用「已下载／未下载」筛选时，会检查符合搜索条件的所有书目，供完整结果翻页。

KOReader Linux ARM64 在内存文件系统上用 1,500 本合成书与 `77b05af6` 交替测试五轮。打开封面书架并翻一页的界面数据准备 CPU 时间中位数从 1,322.1 ms 降至 43.1 ms，下载状态检查从 1,500 次降至 12 次。打开按书名排序的分页列表从 1,316.4 ms 降至 24.6 ms。带下载筛选、匹配 15 本书的连续列表搜索从 1,309.2 ms 降至 19.5 ms。前后可见书目和下载徽标一致。两种模拟尺寸的原生书架另检查了分组、下载筛选、翻页和文件移除后的徽标更新。这些耗时仅覆盖界面数据准备，实体 Kindle 待测。

分页书架现在按书号加载本地记录，同一次更新中的下载标记、阅读日期和进度共用读取结果。需要全局阅读时间或进度的排序仍会读取相关书目。首页可见卡片和点击续读也按需读取，首页生成最近阅读列表时仍会查找书架外的本地记录。

同样以 1,500 本合成书与 `d18bd924` 交替测试五轮，打开封面书架并翻一页的本地记录读取从 3,000 次降至 12 次，界面数据准备的 CPU 时间中位数从 44.4 ms 降至 11.7 ms。按书名打开分页列表从 1,500 次降至 6 次（27.7 ms 降至 7.9 ms），带下载筛选且匹配 15 本书的搜索从 1,500 次降至 15 次（21.9 ms 降至 6.0 ms）。可见顺序和下载标记一致，两种模拟尺寸另核对了翻页、进度排序和旧缓存兼容。这些数据来自桌面模拟器，实体 Kindle 的响应时间待测。

书架搜索与进度排序或筛选组合时，先匹配书名、作者或书号，再读取命中书目的本地记录和 SQLite 进度。当前页复用这次读取的进度快照，后台刷新仍检查快照是否过期。

KOReader Linux ARM64 使用 1,500 本合成书和 SQLite，与 `a3218e17` 交替测试五轮。关键词匹配 15 本时，两种组合的本地记录读取均从 1,500 次降至 15 次，SQLite 进度查询从 1,506 条降至 15 条。界面数据准备 CPU 时间中位数，按进度排序从 37.5 ms 降至 7.5 ms，按在读进度筛选从 35.6 ms 降至 7.3 ms。前后书目、顺序和进度一致。不带关键词的全书架进度排序仍读取 1,500 份本地记录，CPU 时间未见可靠变化。两种模拟尺寸另验证了分组、空结果和本机待同步进度，实体 Kindle 响应时间待测。

按进度整理全书架时先读取账号的本机阅读记录。已有记录且没有待同步位置的书，直接使用已保存的云端进度。有待同步位置或需要兼容旧记录时继续核对书籍资料，已下载筛选及阅读时间排序仍共用所需的完整记录。KOReader Linux ARM64 在内存文件系统中用 1,500 本合成书、30 条含待同步位置的记录及 SQLite，与 `63c2e585` 交替测量七轮。准备进度的书籍资料打开次数从 1,500 次降至 30 次，文章缓存打开尝试由 1,500 次降至零，CPU 时间中位数从 53.9 ms 降至 12.3 ms。每本书的进度值、精度和来源一致。两种模拟尺寸核对进度排序、下载筛选组合、进度更新后的筛选结果和离线重开，实体 Kindle 的响应时间仍待测量。

SQLite 按批读取进度缓存，每批最多 256 个书号。跨批次读取共用一次只读事务，刷新过程中的写入下次读取时才可见。KOReader Linux ARM64 在内存文件系统中用 1,500 本合成书与 `b883cdee` 交替测量七轮，单次读取的查询由 1,500 次降至 6 次。每轮连续读取 30 次，有 300 本缓存进度时累计 CPU 时间中位数从 56.4 ms 降至 47.7 ms，有 1,200 本缓存进度时从 157.4 ms 降至 153.3 ms。6 本书的合成查询每次变化约 0.005 ms。前后结果一致，测试也覆盖并发写入、重复书号、损坏缓存、导入书和精确大书号。两种模拟尺寸已核对排序、筛选、后台进度刷新及离线重开，实体 Kindle 的耗时待测量。

按作者或书名排序时，首尾空白通过查表识别。多词搜索拆分时也用同一张表，保留 Unicode 空白规则和原始文字字节。KOReader Linux ARM64 与 `8719b41c` 交替测量九轮，每轮用 1,500 本合成书连续按作者排序 60 次，CPU 时间中位数从 164.3 ms 降至 141.4 ms。另对 1,500 条混合中英文查询重复拆分 60 次，CPU 时间中位数从 398.6 ms 降至 22.3 ms。排序结果和拆分后的词逐项一致。两种模拟尺寸通过分组搜索、排序及离线重开，实体 Kindle 的界面响应耗时待测。

书架搜索按书目原文复用 Unicode 规范化结果。刷新书架或切换账号时清空，最多保存 4,096 个值和 256 KiB 的原文及转换结果，另有 Lua 表开销。KOReader Linux ARM64 用 1,500 本合成书与 `b77cc7db` 交替测量九轮。每轮执行 24 个中英文混合查询，规范化调用由 138,695 次降至 3,029 次，匹配环节累计 CPU 时间中位数由 149.6 ms 降至 17.7 ms。单次查询从空缓存开始的中位数由 6.19 ms 降至 3.61 ms。每次的匹配书目和顺序均一致，两种模拟尺寸核对分组搜索、书名更新及离线重开。实体 Kindle 的整页响应耗时待测。

书架同时选择多个分组时，翻页和复用已有书目的重绘只检查分组状态，沿用已经去重、排序的书目。更换分组或刷新书架时重新整理书目。KOReader Linux ARM64 用 1,500 本书、12 个各含 750 本书的重叠分组与 `a3a7b4d6` 交替测量七轮。每轮 120 次复用时用于合并分组的书籍身份检查从 126 万次降至零，该环节的 CPU 时间中位数从 132.9 ms 降至 0.26 ms。两种模拟尺寸核对翻页顺序、分组缺失提示及离线重开，实体 Kindle 的整页耗时仍待测量。

## 批量保存墨水屏章节的容量检查

下载前仍按本书目录中的实际条目计算剩余容量，损坏副本和遗留文件也计入 2,000 项上限。仅枚举文件名时，在开始、每 32 个条目和返回计数前核对授权。会话失效会丢弃本轮计数，下载和保存前继续核对账号与来源。

KOReader Linux ARM64 模拟环境使用内存文件系统和合成授权，与 `c7e27441` 比较同一目录的 20 次扫描。三轮 CPU 时间中位数在 1,000 个条目时由 834 ms 降为 30 ms，授权核对从 20,060 次降至 660 次。2,000 个条目时由 1,670 ms 降为 58 ms，授权核对从 40,060 次降至 1,280 次。测试单独测量容量扫描，实体 Kindle 的下载耗时和续航尚待测量。

批次在已有章节目录上取得同书文件锁后，扫描一次容量，之后每新建一个副本扣减一项。复用已有副本或重建同一个空目录沿用该目录的计数。已有章节只读打开仍可进行，同书保存和清理在此期间互斥。批次成功、失败或取消时释放文件锁，文件系统无法加锁时逐章重新扫描。新书首次保存创建目录后，后续章节可复用容量检查。

与 `523862b5` 比较，在 KOReader Linux ARM64 的合成目录中对 1,980 个条目连续做 20 次容量检查，五轮交替测量的 CPU 中位数由 30.5 ms 降至 1.9 ms，目录扫描由 20 次降至一次。合成回归核对新建／复用、副本上限、跨书拒绝、并发锁及进程取消后重新获取文件锁。测量覆盖容量检查，实体 Kindle 的下载总耗时待测。

范围下载只加载所选可读章节的缓存候选。单章范围按目标文件名筛选，多章范围在一次扫描中按章号筛选，再为入选记录核对摘要、读取目录和校验 EPUB。KOReader Linux ARM64 模拟在 2,000 个缓存目录项（其中 1,800 项含有效索引）中查找两章，与 `dc5fdbcf` 交替测量五轮。目录记录读取由 1,800 次降到两次，查找 CPU 时间中位数由 71.2 ms 降到 26.6 ms。初始章节记录读取仍需扫描缓存；真机及下载总耗时待测。

真实账号在两种模拟尺寸各从 15 章的目录选择两章，验证下载、重复下载跳过已有副本及断网重开。独立核对正文与所选范围，书架及云端位置回读一致。合成回归覆盖错误摘要、容量限制、取消和限流。

## 已保存墨水屏章节列表

打开「已下载书籍」时，先检查该书是否有墨水屏缓存目录。只有目录存在时才从磁盘重新核对账号与授权，再读取下载标记或修复。KOReader Linux ARM64 在内存文件系统中对 1,500 本没有墨水屏缓存的合成书与 `d2b0cf8e` 交替测量五轮，授权重新读取由 1,500 次降至零，缓存状态检查的 CPU 时间中位数由 1,480 ms 降至 17 ms，结果一致。测量仅覆盖墨水屏缓存状态检查，实体 Kindle 的整页打开耗时待测。

生成「已下载书籍」列表时只收集展示所需的书目、下载路径及归属信息。已有明确归属的书籍跳过阅读记录，旧书仍可用本机阅读记录确认归属。列表无需读取公众号文章缓存，点开书籍后仍按所选操作读取完整资料。KOReader Linux ARM64 在内存文件系统中使用 1,500 本合成书，其中 100 本含 64 KiB 的文章缓存。与 `b04de12b` 交替测量五轮，文章文件的打开尝试从 1,500 次降至零，阅读记录的打开尝试从 1,500 次降至 150 次，列表准备的 CPU 时间中位数由 137.1 ms 降至 56.6 ms。前后 653 条结果的顺序和内容一致，实体 Kindle 的整页打开耗时待测。

## 后台结果传输

查看想法或书评图片时，先在后台检查账号范围内的图片缓存；已有图片不再检查网络，缺失图片的联网检查也在后台执行。联网检查结束后会再次核对账号及页面范围，断网、缓存损坏和请求失败仍按原流程提示。
