# 原生授权恢复的阅读器验收

本轮补充了[发送前授权恢复](native-source-recovery.md)的定时同步、取消及真实账号验收。
生产安装包仍为同一份 284 文件候选；本轮改动集中在独立验证工具及记录，没有扩大位置发送权限。

## 定时与中断

实际 KOReader 在 600×800／167 DPI 与 1264×1680／300 DPI 各完成五项新增场景：
定时器在来源预检和发送预检两处遇到 401，以及续期工作进程运行时断网、切换账号和休眠。
定时任务只续期一次、重新核对来源后完成模拟同步；三个中断场景保留本机意图和待确认授权，
取消、回收工作进程，不发出迟到的位置修改。切换账号后不能再读出原账号凭据。

这十项均为合成数据。原有正常手动、定时、关书及异常结果的验证记录仍保留。

## 真实自然过期

验证从插件书架下载并打开实际 TXT 章节，使用正常同步按钮及“保留 KOReader 进度”选择。
验证器不制造过期，也不拿以前的 401 作为续期依据。

本次原生来源预检实际返回 401；宿主立即使用同一授权、同一读取地址独立复核，又得到 401。
随后核对本次完整刷新请求、时间、随机数、签名和原设备，先写入不可重复使用的本机标记与钥匙串待确认记录，
才允许 Lua 原生服务发出一次授权申请。新授权经插件书架核对后，通过内存管道交给宿主，
再次独立读取位置、计数、版本和书架，核对同一账号后保存到钥匙串并回读。

原生插件随后第二次核对原文，并使用新授权读取完整原生状态。宿主核对重新准备的完整计划及零时长请求，
包括原始 UTF-16 坐标、30 字原文片段、实际阅读器整数百分比、原生版本、签名和空小时数组。
**该位置请求在调用网络传输前被拦截，真实阅读进度修改为零。** 这不作为一次成功的位置上传，
也不伪造成功回执；插件只在临时内存配置中保留未确认记录和本机意图，然后删除整个配置。

最终宿主独立回读确认原完整位置、摘要、三项时长计数、版本和可见书架保持一致。
以前真实关书试验的已消费记录没有被重用或改变。本次恰好一次真实授权申请，新凭据继续保存在钥匙串。

随后以 KO2 尺寸执行禁止续期的真实对照：新授权有效，正常准备后停止，不申请授权、不尝试位置修改，
不创建新的续期领取标记；独立前后读取仍一致。该对照也不能把“没有过期”写成“续期成功”。

## 隐私与验证边界

Web 授权使用匿名内存文件；原生授权使用临时内存文件系统中的唯一受核对主文件。
审计例外只接受该文件的精确路径，以及预期账号、设备、完整凭据、修订号和无待确认状态；
其他配置、备份、日志和缓存文件仍检查全部旧、新凭据字面值。所有后台进程回收，内存配置删除，禁止正文截图。
宿主输出采用封闭字段，写出前再检查账号、书籍标识、片段及旧、新授权字面值；普通文件中不保存这些数据。

[固定字段验收记录](validation-assets/2026-11-12/native-source-recovery-acceptance.json)区分合成服务、
真实自然过期和禁止续期的对照。新增独立边界测试覆盖新过期证据、钥匙串领取顺序、未知回执、
错误账号、保存后丢失后续结果、完整请求比较、只观察模式和已消费标记的启动拒绝。

这项验收证明实际阅读器的发送前自动续期和重新准备流程；没有新增真实位置写入，
不代替真实定时写入、更多异常、实体 KO2、多设备或断电验收。集中性能优化仍在整体功能验收后进行。
