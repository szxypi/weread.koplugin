# 跨章节正文搜索

微信读书 Web Reader 的只读搜索接口可返回跨章节候选。新增的 `book_search` 模块检查目录、页序、游标、账号和返回结构，限制响应大小并去除重复结果。网络读取应放在后台工作进程；每页读取前核对 Web 账号，并绑定同一登录会话。网络诊断不会输出查询词或正文。当前仅支持数字书号，结果范围默认标记为未核对，不能直接用作阅读器位置。

本次真实账号只读测试先从一章原文选择查询词，再读取四页、五章的搜索候选；Python 与 Lua 独立比较了 113 个去重结果，原生 Lua HTTPS 的首批结果与独立读取一致。分页仍有后续，不能声称获取了全书全部匹配。请求的每页数量是 5，服务端一次返回多达 51 条，因此不能把请求数量当成返回数量上限。目录和原阅读位置在前后读取中保持一致，未发送账号数据或授权修改请求。

该章 64 个候选中，一处结束范围包含正文标记，简单的文字边界比较不一致。现有原文核对与位置转换逻辑对 64 个候选均成功验证，包括这一处；新适配器只在原文、章节、书籍和引用吻合时产生本地定位候选，不授予云端上传资格。观察仅覆盖一本书的一章原文和有限页数，不能推断所有图书、跨标记、表情或其他格式均有相同坐标语义。[脱敏验证记录](validation-assets/2026-11-18/cloud-book-search-preflight.json)不包含查询词、书籍标识或正文。

阅读器快捷菜单的「搜索整本书」已接入原生输入框与结果列表，搜索和后续分页在后台执行。点击结果时先核对书籍、章节、原文和引用，再交给 KOReader 定位；目标章节未缓存时先询问是否下载。取消搜索或下载确认、切书、关书及账号变化会停止相应操作，旧响应不能继续打开阅读位置。当前入口需要联网及已验证的 Web 登录，暂限数字书号；正文或坐标不能独立核对时会提示失败，不猜测位置。最多读取 128 页，达到上限会提示结果可能不完整。现有快捷菜单的[本机搜索](reader-local-search.md)保持独立。

两种屏幕尺寸的实际 KOReader 进程使用合成书籍及模拟服务验证了输入、两页结果、取消后台任务、已缓存章节定位，以及缺少目录和章节时的下载确认、取消与下载后定位；确认前取消没有发起下载请求。旧的本机搜索和划线缺章定位流程也已回归。另以真实账号从目录首章发起只读搜索，原生 Lua 首批结果与 Python 独立读取一致，目录和原位置保持，见[补充记录](validation-assets/2026-11-18/cloud-book-search-first-chapter.json)。

真实账号还在 600×800 和 1264×1680 隔离的 KOReader 进程中，从原生快捷菜单搜索并点击一本书当前章节中的一个匹配结果；结果范围与原文独立核对后，阅读器定位到对应页面。验证使用内存中的授权和临时章节，限制网络请求为只读，完成后再次读取确认云端进度、目录和章节原文不变；没有截图或修改账号数据。[脱敏验证记录](validation-assets/2026-11-18/cloud-book-search-owner-ui.json)按上述屏幕顺序记录两次结果。这只覆盖一本书的一个结果和已缓存章节；更多书籍格式、真实缺章下载和实体 KO2 仍待验收。合成界面：[600×800](validation-assets/2026-11-18/cloud-book-search-ui-600.png) · [KO2 尺寸](validation-assets/2026-11-18/cloud-book-search-ui-ko2.png)。
