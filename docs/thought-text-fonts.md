# 原生想法文字的表情回退

想法输入框、保存前的确认、草稿正文、本人想法正文和选区引用窗口现在使用插件自带的 `NotoEmoji-Regular.ttf` 补齐表情。
原有中文、拉丁文字的主字体、字号和回退顺序保留；表情字体放在链末尾，避免后续字体把组合字符重新替换成缺字框。
没有修改 KOReader 全局字体列表、字体获取函数或阅读字体设置，也没有更改引用文字、范围和上传内容。

原生 `TextViewer` 没有独立字体参数，插件只在自己的窗口中重建文字框的整形结果和滚动状态；
字号和等宽字体切换后继续应用同一局部回退。输入框通过原生 `input_face` 传入字体，沿用原有键盘和光标处理。
回退最多使用 xtext 的 16 个字体槽；已有满额链保留原字体，不挤掉用户配置的字体。
字体缺失时保留原生显示，不因此阻止编辑或草稿恢复。

## 验证

实际 KOReader v2026.07.1 Linux ARM64 的 600×800／167 DPI 和 1264×1680／300 DPI 均通过：

- 先用未修改的默认字体复现 😀 的缺字，再检查修复后的 FreeType 字形编号、表情字体路径、非空位图和行内边界。
- 😀、🙂及肤色、爱心、职业／家庭连接序列、键帽和国旗混合样本没有缺字字形；这不等于覆盖所有 Unicode 表情。
- 中文、英文、数字、标点、换行和重音字母的字形、位置、宽度、行数及高度与原生默认字体逐项相同。
- 字号改至 30、切换等宽字体、全新进程重开仍保留表情回退；未重复缩放字号或添加窗口按钮。
- 实际输入、引用与正文确认、草稿查看、本人想法查看、恢复输入和新进程离线恢复均核对表情字形。
- 原生选区的创建／编辑／删除、取消、来源变化、401、未知回执和持久待核对状态继续通过；引用范围、原有本机附注及精确阅读位置保持。
- 回归来源上传、授权恢复、书架成员、读完标记和关书同步。全部修改请求只发往合成模拟服务，本批真实账号请求为零。

原有想法编辑器两份候选及阅读流程两份候选的 236 个生产文件，与当前源码和安装内容逐字节一致。
原有编辑器的临时配置清理通过。完整检查为 76 份 Python／929 项零跳过、211 组 Lua、583 个静态文件零警告／错误、
585 个 Lua 语法、222 个 Python 编译、四时区、命名空间和 TLS；摘要、执行记录及图片校验见[固定证据](validation-assets/2026-11-11/thought-text-fonts.json)。

首个字形断言误把 xtext 的内部字符索引访问当成 UTF-8 字符串，未匹配到目标表情而停止；
改用原始合成文字的 Unicode 字符数组按同一索引核对后，两尺寸全部断言及流程重跑通过。该失败没有计为成功。

可复现入口为 `scripts/test_thought_editor_runtime.py`，以及
`scripts/test_discovery_runtime.py --reading-flow --source-upload --source-recovery --progress-recovery --recovery-save-retry --shelf-membership-write --finish-change --selection-thought`；
均需按参数提供 KOReader、显示尺寸与新的独立运行目录。
