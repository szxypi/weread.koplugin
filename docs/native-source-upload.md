# TXT 原生位置发送通道

当前开发分支将手动／定时位置同步接到独立原生发送通道。TXT 原文位置只用于零时长的位置同步，
后台阅读时长上报不会借用这条通道。尚未完成实际阅读器中的新写入验收或发布。

## 发送与回执

`native_source_upload.lua` 保留父进程的页面、文档、账号和原文检查，再后台核对原生版本、完整云端位置、
时长计数和可见书架。云端位置必须与用户刚确认的位置一致；发生变化便停止，要求重新比较。
缺少章节索引、未开始阅读的零章节、未知坐标单位均不能绕过检查。
原生版本另行读取，合法的 `0` 不得替换成本机文件版本。

准备好的计划仅存在内存中，绑定原有的短期来源回执。实际发送使用已有 SQLite 原生回执，
不会进入 Web 发送器或 Web 的来源发送记录。发送后先保存本机结果，再接受原生完成回执；
保存失败会留下可核对的完成记录。未知回执不重发，已领取和已确认待核对的记录不会被新任务覆盖。
只读确认云端已等于目标时，不伪造一次 POST 成功回执。

翻页、关书、账号变化、超时和取消会使旧计划失效。释放旧计划不能取消随后新建的来源准备任务。
后续仍需补齐关书后的独立来源交接、待确认回执的用户恢复入口，以及发送前原生授权恢复的完整衔接。
本轮原生过期返回停止；验证工具仅依据新观察到的 HTTP 401 续期一次，无写后自动续期或重发。

## 验收

[固定字段记录](validation-assets/2026-11-12/native-source-upload.json)区分本轮零修改检查与以前的接口写入验证。
原生准备器、计划取消、未知回执、本机保存失败和异步同步桥接均有单元检查。
完整回归包含 247 组 Lua 测试；Python 验证覆盖原生读取额度、结果组合、默认无凭据、
跳过尚未开始阅读的样本，以及不隐藏其他读取错误。

实际 KOReader 以打包插件从书架打开有完整云端位置的 TXT 书籍，完成在线原文核对和原生元数据／进度／书架三个 GET，
准备实际发送计划后终止，不调用派发函数。翻页、精确跳转、后台取消和新进程离线重开继续核对；
每尺寸六个原文片段由 Python 独立复核。临时配置置于内存文件系统并删除，不截图正文、不将凭据或摘要写入普通文件。
KO2 尺寸仿真不能替代实体 KO2 验收；实际阅读器的写入和恢复需要新的独立试验记录，不复用已消费试验。

## 定时器与实际阅读器的模拟发送

继续验收发现定时器的资格判断仍只接受 XHTML，导致 TXT 虽有异步原生发送计划，却不会启动定时任务。
现已改为接受两种明确的来源坐标；未知单位仍拒绝。69 项定时器断言包含 TXT 异步派发和原本地坐标保留。

[模拟发送记录](validation-assets/2026-11-12/native-reader-position.json)覆盖打包插件、真实 ReaderUI、实际后台子进程和 SQLite，
以独立本机服务接收请求；每个尺寸手动和定时各发送一次零时长原生位置，第三次模拟缺失成功回执。
独立 Python 模型按原始 TXT 重新核对坐标、完整 30 字片段、签名、合法原生版本 `0` 和所有零时长字段，
与本机归档版本分别处理。两个尺寸均核对发送前已持久领取、Web 派发记录没有参与、原本机检查点单位保持且不保存摘要。

关闭定时同步会取消尚未完成的原文准备并回收子进程；重新开启后正常处理剩余本机意图。
第三次请求已在模拟云端生效，但没有明确成功回执，因此停止自动同步并保留原生待核对记录与本机意图。
推进定时器和全新离线进程均不重发，重开仍能读取待核对记录；离线 HTTP 为零，三项时长计数保持，临时配置已删除。
这些发送全部为合成数据，真实账号没有修改或续期。不能据此宣称真实账号下的阅读器写入／恢复或实体设备已经验收。
