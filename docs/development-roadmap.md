## 验证层次

1. 单元与组件：数据整理、分页、取消、失败恢复、账号隔离、同步状态机。
2. 合成 HTTP：真实传输、错误响应、延迟、断线、空数据；不访问真实账号。
3. 真实 KOReader：打包后的插件、原生控件、字体、SQLite、EPUB 引擎、截图与交互。
4. 在线服务：真实授权、数据读取、写入后的回读确认、权限与限频行为。
5. 真机：实际屏幕、按键／触摸、休眠唤醒、网络恢复、性能和残影。

## 当前可用环境

- macOS 主机：LuaJIT、Luacheck、Python 和 GitHub CLI。
- OrbStack 容器 `weread-validation`：Ubuntu 24.04 ARM64。
- 官方 KOReader Linux ARM64 v2026.07.1，使用 Xvfb 提供虚拟显示器。
- 运行数据与截图保存在工作区外层 `.validation/`，不使用日常账号或设置。
- 已有原生控件几何测试另固定 KOReader 提交 `1e2fa5f1239028ab4b37acae833cdc86a71e5258`。
- 用户已确认真机为 Kindle Oasis 2（KO2）；KOReader 版本和在线账号测试条件待补充。
  重点覆盖实体翻页键、触摸、休眠唤醒和断网恢复。不得在聊天或仓库中收集凭据。
- 本机 E-Ink 授权验证工具已准备；`scripts/verify_eink_login.py` 默认只验证出票和二维码，
  `--interactive` 在本机显示二维码并等待本人扫码，随后只登录和读取书架，不保存凭据或修改书架。
  详见 [E-Ink 授权原型](eink-authorization-prototype.md)。

真实绘制测试（在具有 SDL 依赖的 Linux 环境执行）：

```sh
xvfb-run -a python3 scripts/test_discovery_runtime.py \
  --koreader /path/to/runtime \
  --run-dir /path/to/new-test-directory
```

每次使用新目录。脚本会生成候选包、SHA-256、隔离配置、运行日志和截图。
测试使用真实插件初始化及本地数据库，账号和书籍为合成数据。
它验证绘制、回调与页面清理，不代表所有触摸手势或在线请求已验收。
